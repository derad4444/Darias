# UI/UX仕様

> **最終更新**: 2026-09-16

## 🗺️ 画面遷移フロー

```
MainShellScreen（5タブ）
├─ ホームタブ
│  └─ チャットで悩みを話す
│     └─ 自分会議の提案バナーを表示
│        └─ [開く] → 自分会議タブへ切り替え
│
└─ 自分会議タブ（meetingTabIndex）
   ├─ 未解放（signalCount < 30） → ロック画面（進捗を表示）
   ├─ 悩みテキスト入力
   ├─ 生成中（ローディング）
   └─ 会議室 → 会話表示 → 統合レポート
      └─ [完了] → 結論をチャットへ引き継ぎ、ホームタブへ戻る
```

自分会議はタブの中身なので、単独ルート（`/meeting`）は持たない。

✅ **Flutter実装**: `flutter/lib/presentation/screens/meeting/meeting_screen.dart`

---

## 📱 画面詳細設計

### 1. 入口

- 下部タブバーの4番目「自分会議」から開く（`main_shell_screen.dart` の `meetingTabIndex`）
- チャットの返信で悩みが検出された場合、ホーム下部に提案バナーを表示
  - **表示条件**: 送信メッセージが悩み系キーワードを含む（`chat_datasource.dart` の
    `_concernKeywords` を `String.contains` で判定）かつ `signalCount >= 30`
    （`home_screen.dart` の `_showMeetingBanner`）
  - [開く] を押すと自分会議タブへ切り替わる
- **解放条件**: `signalCount >= 30`（性格タイプが確定するライン）。未解放のあいだ、自分会議タブは
  トピック入力の代わりに進捗を示すロック画面を表示する

---

### 2. 画面の状態

`MeetingScreen` は3つの状態を出し分ける（`build()` の分岐）。状態はすべて `State` のフィールドで持ち、
専用ルートや Phase enum は持たない。

| 状態 | 表示条件 | ビルダー |
|-----|---------|---------|
| ローディング | `_isLoading == true` | `_buildLoading()` |
| 会議室 | `_meetingResponse != null` | `_buildMeetingRoom()` |
| ロック画面 | `signalCount < 30` | `_buildLocked()` |
| トピック入力 | 上記いずれにも当てはまらない | `_buildTopicInput()` |

判定は上から順に評価されるため、生成中はローディングが、レスポンス取得後は会議室が最優先で表示される。

AppBar は常に「自分会議」のタイトルと、右上のヘルプアイコン（`_showCharacterExplanation()` で
6人の紹介シートを開く）を出す。初回に自分会議タブを開いたときは `HintService` の記録を見て、
このシートを自動で1度だけ表示する。

---

### 3. ロック画面（`_buildLocked`）

- 🔒 アイコン + 「もう少しでひらきます」
- 「チャットをもう少し続けて性格タイプを確定させる必要があります」という案内
- `現在の進捗: {signalCount} / 30` と `LinearProgressIndicator`

---

### 4. トピック入力（`_buildTopicInput`）

- 無料ユーザーには使用回数バナー（`_buildUsageBanner`）を最上部に表示
  - 未利用: 「無料プランでは1回のみ利用可能」（青）
  - 1回利用済み: 「利用制限に達しました」（オレンジ）
  - どちらにも「プレミアムで無制限に」ボタン → `/premium?source=meeting_banner`
- 👥 アイコン + 「6人の自分があなたの悩みを多角的に議論します」
- 悩み入力の `TextField`
  - `minLines: 4` / `maxLines: 6` / **`maxLength: 500`**
  - ヒント「例: 転職すべきか迷っている...」
  - カウンター欄に「Shift+Enterで開始 / Enterで改行」と `{現在}/500文字`
  - Shift+Enter で会議を開始（`FocusNode.onKeyEvent`）、Enter は改行
- 「会議を開始」ボタン（入力が空の場合は disabled）
- 無料ユーザーにはバナー広告（`AdConfig.meetingScreenBannerAdUnitId`）
- Web かつ非プレミアムの場合は開始時にダイアログを出して `/premium?source=meeting_web_limit` へ誘導する

カテゴリはユーザーに選ばせない。クライアントは `concernCategory` を送らず、サーバー側が
gpt-4o-mini で自動判定する（`05_API仕様.md` 参照）。

---

### 5. ローディング（`_buildLoading`）

- `CircularProgressIndicator`
- 「6人の自分が集まっています...」／「会議を準備中です」

---

### 6. 会議室（`_buildMeetingRoom`）

```
┌─────────────────────────────────┐
│ ヘッダー                          │
│  👥 自分会議        [再利用バッジ] │
│  悩み（最大2行・省略あり）          │
│  統計テキスト                      │
├─────────────────────────────────┤
│                                 │
│  会話バブル（順次追加）             │
│  左側: original / ideal / wise   │
│  右側: opposite / shadow / child │
│                                 │
│  （全発言の表示後）                 │
│  ─────────────                   │
│  結論サマリー（黄）                 │
│  アドバイス（オレンジ）             │
│  [会議結果を共有]                  │
├─────────────────────────────────┤
│ [結論へ]              [完了]      │
└─────────────────────────────────┘
```

#### ヘッダー（`_buildHeader`）
- 「自分会議」タイトル
- `cacheHit == true` のときだけ緑の「再利用」バッジ（毎回新規生成のため通常は出ない）
- 入力した悩み（`maxLines: 2`）
- 統計テキスト（`MeetingStatsData.displayText`）
  - `similarCount > 0`: 「{n}人の似た性格の方のデータを参考にしています」
  - それ以外: 「あなた専用の分析を生成しました」

#### 会話表示（`_startAnimation`）
- レスポンスの `rounds` を平坦化した1本のリストを、先頭から1件ずつ `_displayedMessages` に追加
- 表示間隔 = `min(2500 + min(文字数, 150) × 17, 5000)` ミリ秒（2.5〜5秒）
- 1件追加するたびに `addPostFrameCallback` で最下部までスクロール
- 全件表示後に2秒待ってから結論を表示し、`_maybeAskReview()` を呼ぶ
- バブルは `characterId` で左右と色・アイコンを決める（`six_person_meeting_model.dart` の
  `position` / `characterColor`、`meeting_screen.dart` の `_characterIcon`）

#### 結論（`_buildConclusion`）
- 結論サマリー（黄色背景・⭐️アイコン・「会議の結論」）
- アドバイス（オレンジ背景・💡アイコン・番号付きリスト）
- 「会議結果を共有」ボタン（緑）
  - 画面外に置いた `MeetingShareCard` を `RepaintBoundary` でPNG化し、
    `share_plus` の `Share.shareXFiles` で画像＋テキストを共有する
    （`share_card_capture.dart` の `shareCardWithText`）
  - 画像化できない環境ではテキストのみにフォールバック
  - 共有テキストの組み立ては `meeting_share_card.dart` の `buildMeetingShareText`
  - 詳細仕様は [`SNS共有仕様書.md`](../functions/SNS共有仕様書.md) 参照

#### フッター（`_buildFooter`）
- 「結論へ」ボタン: 表示アニメーション中だけ出る。押すと残りの発言を一括表示して結論へ飛ぶ
- 「完了」ボタン: 常時表示。結論サマリーを `meetingFollowupConclusionProvider` に渡してから
  画面をトピック入力に戻し、ホームタブへ切り替える。ホーム側はその結論を
  `【自分会議の結論】…` としてチャットに送り、キャラクターのフォローアップ返答を表示する
  （`home_screen.dart` の `_triggerMeetingFollowup`）

---

### 7. アプリ評価の依頼

結論表示後（および「結論へ」でスキップした後）に `AppReviewService` の条件を満たせば、
3秒おいてストアレビュー依頼ダイアログを出す（`app_review_dialog.dart`）。
会議はきっかけの中で最も頻度が高いため、通算3回目以降に絞っている。
条件・文言・バックオフの詳細は [`アプリ評価仕様書.md`](../functions/アプリ評価仕様書.md) 参照。

---

### 8. 参加者の紹介シート（`_showCharacterExplanation`）

AppBar のヘルプアイコン、または自分会議タブの初回表示で開くボトムシート。
6人それぞれのカード（アイコン・色・説明・特徴4項目）と「会議のポイント」を表示する。
キャラクターの定義は `02_キャラクター設定.md` 参照。

---

### 9. 履歴からの閲覧

過去の会議は履歴画面の「会議」タブ（`unified_history_screen.dart`）から見る。

- 一覧: カテゴリ名・相談内容・相対日付。相談内容で絞り込み検索できる
- 詳細シート: `sharedMeetingId` から `shared_meetings` を読み込み、会話と結論を表示
- 詳細シートからも会議画面と同じカード・同じテキストで共有できる
- 「この会議を削除」で `meeting_history` のドキュメントを削除する（`shared_meetings` は残る）

## 🎨 デザインガイドライン

### カラー（`characterId` 別）

| キャラクター | 色 | 表示位置 |
|------------|---|---------|
| 今の自分 (original) | 青 | 左 |
| 理想の自分 (ideal) | 紫 | 左 |
| 未来の自分 (wise) | 茶 (#996633) | 左 |
| 真逆の自分 (opposite) | オレンジ | 右 |
| 本音の自分 (shadow) | 赤 | 右 |
| 子供の頃の自分 (child) | 緑 | 右 |

右側のバブルはキャラクター色の半透明、左側は白の半透明。

### アニメーション
- メッセージ表示間隔: 2.5〜5秒（`min(2500 + min(文字数, 150) × 17, 5000)` ミリ秒）
- 新しい発言が出るたびに最下部へオートスクロール
- 「結論へ」で残りを一括表示して結論へジャンプ
