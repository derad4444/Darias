# 自分会議（6人会議）機能 - 概要

> **最終更新**: 2026-09-16

## 📋 機能概要

「6人の自分に相談する」機能。ユーザーの性格（BIG5）を基に、6つの異なる視点から人生の悩みを議論して結論を出す。

### コアコンセプト
- ユーザーのBIG5性格診断データを活用して6人の「自分」を作る
- 6人が「会議」形式で議論し、最後に明確な結論と3つのアドバイスを出す
- 会議はリクエストごとに、その悩みに沿って毎回新規AI生成
- チャット風UIで発言を順次表示する

---

## ✅ 仕様

### 解放条件
- `signalCount >= 30`（性格タイプが確定するライン）
- 未解放のあいだ、自分会議タブは進捗を示すロック画面を表示する

### 課金モデル
- **無料ユーザー**: 生涯1回のみ（`meeting_history` の件数で判定）
- **プレミアム（月額980円）**: 無制限
- Web版は非プレミアムだと会議を開始できず、プレミアム画面へ誘導する

### AIモデル
- **会議生成**: `gpt-4o-2024-11-20`
  - `temperature: 0.8`
  - `response_format: { type: "json_object" }`
  - `max_tokens` の指定なし
- **カテゴリ判定**: `gpt-4o-mini`（`temperature: 0`）
  - クライアントは `concernCategory` を送らないため毎回実行される
- コスト: 約3.4円/会議（毎回新規生成のため常に発生）
- 生成方式: 100% AI生成（テンプレート不使用）

### データソース
- **統計**: `PersonalityStatsMetadata/summary` のみ
  - `total_completed_users` と `personality_counts[personalityKey]` から
    `similarCount` / `totalUsers` / `percentile` を決定論的に算出
  - `avgAge` は固定値30
- **BIG5・6人の性格**: `characters/{characterId}/details/current`
  - `confirmedBig5Scores` / `gender` / `personalityKey` / `sixPersonalities`

### 生成戦略
- **毎回新規生成**: リクエストのたびに、そのユーザーの悩み（concern）とカテゴリをプロンプトに含めてAIが会話を生成する
- **shared_meetings コレクション**には生成結果を保存するが、後続リクエストでの再利用（読み出し）は行わない（履歴・分析のための保存）
- 同じ性格タイプでも、悩みが違えば異なる会議になる

### 会話生成
- **プロンプト方式**: 脚本家アプローチ（`sixPersonMeetingTemplates.js`）
  - Phase制（3段階：本質探索 → 葛藤 → 統合）
  - 禁止表現リスト（教科書的表現を排除）
  - 推奨表現（問いかけ、感情、具体的経験）
  - BIG5パーソナライズ（数値ではなく `buildPersonalityTraits()` の日本語特性文を渡す）
  - ユーザーの悩みの具体的な言葉を会話・結論に反映
  - カテゴリ別の結論指示で「やる/やらない」を必ず断言させる

## 🎯 ユーザーフロー

### パターン1: 自分会議タブから直接
```
1. 下部タブバーの4番目「自分会議」を開く

2. 悩みを自由記述（最大500文字）
   カテゴリ選択UIはない（サーバー側が自動判定）

3. 「会議を開始」

4. 【システム内部】
   a. プレミアム判定・利用制限チェック
   b. details/current から personalityKey / BIG5 / 6人の性格を取得
   c. gpt-4o-mini でカテゴリ判定
   d. その悩みに沿ってAIが会議を新規生成（約3.4円）
   e. shared_meetings に保存、meeting_history に参照を保存

5. チャット形式で発言を順次表示（1件2.5〜5秒）

6. 結論（サマリー + アドバイス3件）を表示

7. [完了] → 結論をチャットに引き継ぎ、ホームでキャラクターが感想を返す
```

### パターン2: チャットからの提案
```
1. ホームのチャットで悩み系キーワードを含むメッセージを送る
   （「迷ってる」「どうしよう」など。判定は chat_datasource.dart のキーワード一致）

2. signalCount >= 30 ならホーム下部に提案バナーが出る

3. [開く] → 自分会議タブへ切り替わる（以降はパターン1と同じ）
```

## 💰 コスト試算

### 1会議あたり（毎回新規生成）
- gpt-4o-2024-11-20（会議生成）: 約3.35円
  - 入力: 約2,260 tokens × $2.50/1M ≈ 0.85円（プロンプト実測4,976文字から換算）
  - 出力: 約1,670 tokens × $10.00/1M ≈ 2.51円（出力JSON構造からの推定）
- gpt-4o-mini（カテゴリ判定）: 約0.003円
- Firestore読み書き: 約0.0013円
- Cloud Functions: 約0.011円
- **合計: 約3.4円/会議**

### 月間コスト（プレミアム50人 × 月5回 = 250会議）
```
250会議 × 3.4円 = 850円/月
```
コストは利用回数に比例して線形に増加する。詳細は `06_コスト試算.md` を参照。

### 年間収支（課金率5%・50人想定）
- 収益: 50人 × 980円 × 12ヶ月 = **588,000円/年**
- コスト: 850円 × 12ヶ月 = **10,200円/年**
- **利益率: 約98.3%**

## 🎨 UI/UXの特徴

### 1. キャラクター可視化
- AppBarのヘルプアイコン（と初回表示）で6人の紹介シートを開く
- BIG5数値は非表示（ユーザーフレンドリー）
- アイコンと色で視覚的に区別

### 2. 会話形式
- LINEのようなチャットUI
- **2.5〜5秒ごとにメッセージ表示**（メッセージ長に応じて動的調整）
  - `min(2500 + min(文字数, 150) × 17, 5000)` ミリ秒
- 左右配置（左＝慎重派 original/ideal/wise、右＝行動派 opposite/shadow/child）

### 3. インタラクション
- 「結論へ」で残りの発言を一括表示して結論へジャンプ
- 「会議結果を共有」で結論カードのPNG＋テキストを共有
- 結論表示後、条件を満たせばストアレビュー依頼ダイアログ
- 「完了」で結論をチャットへ引き継ぎ、ホームに戻る

詳細は `04_UI仕様.md` を参照。

## 📊 データフロー

```
ユーザーが悩みを入力
↓
details/current から personalityKey 取得（例: "O4_C4_E2_A4_N3_female"）
↓
concernCategory を gpt-4o-mini で判定（例: "career"）
↓
会議を新規生成
├─ PersonalityStatsMetadata/summary から統計データ算出
├─ 悩み（concern）+ カテゴリ + 6人の性格特性をプロンプトに含めて生成
│   （gpt-4o-2024-11-20）
├─ shared_meetings に保存
├─ meeting_history に参照を保存
└─ 表示（約3.4円）
```

## 🔒 プライバシー・倫理

### データの匿名化
- `shared_meetings` に保存するのは `personalityKey`（例: "O4_C4_E2_A4_N3_female"）と
  カテゴリ・生成された会話・統計。ユーザーIDと悩みの入力欄の原文は保存しない
  （ただしプロンプトが悩みの具体的な言葉を使うよう指示しているため、
  生成された会話本文には悩みの内容が反映される）
- 悩みの原文（`userConcern`）は本人のみ読める `meeting_history` に保存する
- Analytics には「自分会議を使った」という事実だけを送り、悩みの本文は送らない
  （`meeting_provider.dart` の `logFeatureUsed`）

### shared_meetings の管理
- Cloud Functions（Admin SDK）のみが書き込み可能
- 認証済みユーザーは読み取り可能（`firestore.rules`）
