# データ構造設計

> **最終更新**: 2026-09-16

## 📊 方針

```
✅ 新規コレクションは shared_meetings と meeting_history の2つだけ
✅ BIG5・統計は既存の users / characters / PersonalityStatsMetadata を使う
✅ 会議はリクエストごとに新規生成し、shared_meetings に保存（履歴・分析用）
```

---

## 1. `/shared_meetings/{sharedMeetingId}`

ルートレベルの共有コレクション。生成した会議をここに保存する。
後続リクエストでの検索・再利用（読み出し）は行わない。

書き込むのは Cloud Function `generateOrReuseMeeting` のみ
（`db.collection("shared_meetings").add(...)`）。

```javascript
{
  personalityKey: "O4_C4_E2_A4_N3_female",  // details/current の値をそのまま記録
  concernCategory: "career",                // 判定したカテゴリ（記録用）

  conversation: {                           // AIが返したJSONをそのまま格納
    rounds: [
      {
        roundNumber: 1,
        messages: [
          {
            characterId: "shadow",          // original|opposite|ideal|shadow|child|wise
            characterName: "本音の自分",
            text: "本当にそれでいいの？...",
            timestamp: "2024-01-01T00:00:00.000Z"  // AIが生成する文字列
          }
          // Phase 1 は5〜7発言
        ]
      }
      // 3ラウンド（Phase 1〜3）
    ],
    conclusion: {
      summary: "転職するかどうか迷っているあなたへ、この会議の答えは〜です",  // 200〜300文字
      recommendations: [
        "今週中に転職サイトに登録し、3社に応募する",
        "...",
        "..."
      ]  // 3項目
    }
  },

  statsData: {                              // calculateStatsFromAnalysis() の戻り値
    similarCount: 127,   // personality_counts[personalityKey]（完全一致の人数）
    totalUsers: 1523,    // total_completed_users
    avgAge: 30,          // 固定値
    percentile: 8,       // round(similarCount / totalUsers * 100)
    personalityKey: "O4_C4_E2_A4_N3_female"
  },

  usageCount: 1,                            // 生成時に 1 で固定
  ratings: {                                // 生成時に 0 で初期化
    avgRating: 0,
    totalRatings: 0,
    ratingSum: 0
  },

  createdAt: Date,
  lastUsedAt: Date
}
```

> `messages` のキーは `characterId` / `characterName` / `text` / `timestamp` の4つ。
> 感情絵文字や発言者の別名フィールドは持たない。

> `ratings` は初期化されるだけで、更新する経路は現状ない。
> `firestore.rules` は `shared_meetings` を `allow write: if false` にしているため、
> クライアントから評価を書き込むことはできない。

**Firestore Index**（`firestore.indexes.json` に定義済み）
```
shared_meetings: personalityKey ASC, concernCategory ASC, usageCount DESC
shared_meetings: personalityKey ASC, usageCount DESC
```
再利用のためのクエリを実行しないため、現状これらのインデックスは使われない。

## 2. `/users/{userId}/characters/{characterId}/meeting_history/{historyId}`

ユーザーごとの会議履歴。会話本体は持たず、`shared_meetings` への参照を保持する。

```javascript
{
  sharedMeetingId: "abc123",              // これで会話内容を取得する
  userConcern: "転職すべきか迷っている",     // ユーザーが入力した悩み（最大500文字）
  concernCategory: "career",
  userBIG5: {                             // 記録時点の confirmedBig5Scores
    openness: 4,
    conscientiousness: 4,
    extraversion: 2,
    agreeableness: 4,
    neuroticism: 3
  },
  cacheHit: false,                        // 毎回新規生成のため常に false
  createdAt: Date
}
```

このコレクションの件数が無料ユーザーの利用制限判定に使われる（件数 >= 1 で制限）。

Flutter 側のモデルは `meeting_history_model.dart` の `MeetingHistoryModel`。
`userBIG5` は読み込まず、`sharedMeetingId` / `userConcern` / `concernCategory` /
`cacheHit` / `createdAt` を使う。

## 3. 既存コレクションの利用

### A. `/users/{userId}/subscription/current` — プレミアム判定

`checkPremiumStatus()` が読む。

```javascript
{
  status: "active" | ...,   // "active" ならプレミアム
  plan: "premium" | ...,    // "premium" でもプレミアム扱い
  end_date: Timestamp | null  // null は無期限。設定があれば現在時刻と比較する
}
```
ドキュメントが存在しない場合は非プレミアム。

### B. `/users/{userId}` — 月間利用回数の記録

プレミアムユーザーの利用後にインクリメントされる（制限ではなく記録）。

```javascript
{
  usage_tracking: {
    meeting_count_this_month: 3,
    last_meeting_month: "2026-09"   // YYYY-MM。月が変わったら 0 から数え直す
  }
}
```

### C. `/users/{userId}/characters/{characterId}/details/current` — BIG5とキャラクター

`getCharacterData()` が読む。

```javascript
{
  confirmedBig5Scores: { openness: 4, conscientiousness: 4, extraversion: 2,
                         agreeableness: 4, neuroticism: 3 },
  gender: "female",
  personalityKey: "O4_C4_E2_A4_N3_female",
  sixPersonalities: [ ... ],   // 事前計算済みなら使う。無ければその場で生成
  analysis_level: 100          // backfillSixPersonalities の対象判定に使う
}
```
このドキュメントが存在しない場合、会議生成は `not-found` エラーになる。

### D. `/PersonalityStatsMetadata/summary` — 統計データ

`calculateStatsFromAnalysis()` が読む唯一の統計ソース。

```javascript
{
  total_completed_users: 1523,
  personality_counts: {
    "O4_C4_E2_A4_N3_female": 127,
    ...
  }
}
```
ドキュメントが無い場合は `similarCount: 0, totalUsers: 0, avgAge: 30, percentile: 50`
のフォールバック値を返す。

## 4. 会議生成時のデータフロー

```
1. 認証チェック（request.auth / uid 一致）
   ↓
2. subscription/current でプレミアム判定
   ↓
3. 無料ユーザーは meeting_history の件数を数え、1件以上なら resource-exhausted
   ↓
4. details/current から big5 / gender / personalityKey / sixPersonalities を取得
   ↓
5. concernCategory 未指定なら gpt-4o-mini で判定
   ↓
6. meeting_history を全件取得（閲覧済みIDの収集）
   ↓
7. PersonalityStatsMetadata/summary から statsData を算出
   ↓
8. 6人の性格（sixPersonalities があればそれ、無ければ generateSixPersonalities）
   ↓
9. gpt-4o-2024-11-20 で会話を生成（悩み・カテゴリ・6人の性格特性・統計を渡す）
   ↓
10. shared_meetings に add
   ↓
11. meeting_history に add
   ↓
12. プレミアムなら usage_tracking の月間カウントをインクリメント
   ↓
13. レスポンス返却（cacheHit: false）
```

> 実装は `shared/functions/src/functions/generateSixPersonMeeting.js` の
> `generateOrReuseMeeting`。`searchMeetingCache()` は定義されているが呼び出されず、
> `cacheResult` は常に `null` で生成パスを通る。

## 5. Flutter データモデル

| クラス | ファイル | 主なフィールド |
|-------|---------|--------------|
| `GenerateMeetingResponse` | `six_person_meeting_model.dart` | success, meetingId, conversation, statsData, cacheHit, usageCount, duration |
| `SixPersonMeetingModel` | 同上 | id, conversation, statsData, createdAt, personalityKey, concernCategory, usageCount, lastUsedAt |
| `MeetingConversation` | 同上 | rounds, conclusion |
| `ConversationRound` | 同上 | roundNumber, messages |
| `ConversationMessage` | 同上 | characterId, characterName, text, timestamp（+ position / characterColor のゲッター） |
| `MeetingConclusion` | 同上 | summary, recommendations |
| `MeetingStatsData` | 同上 | similarCount, totalUsers, avgAge, percentile, personalityKey（+ displayText） |
| `MeetingHistoryModel` | `meeting_history_model.dart` | id, sharedMeetingId, userConcern, concernCategory, cacheHit, createdAt |

Cloud Functions SDK は `Map<Object?, Object?>` を返すため、
`meeting_datasource.dart` の `_deepConvertMap()` で `Map<String, dynamic>` に再帰変換してから
モデルに渡している。

## 6. セキュリティルール

`firestore.rules` の該当箇所。

```javascript
// ユーザーのサブコレクション（meeting_history を含む）は本人のみ
match /users/{userId} {
  allow get: if request.auth != null;
  allow list: if false;
  allow write: if request.auth != null && request.auth.uid == userId;

  match /characters/{characterId}/details/{detailId} {
    allow get: if request.auth != null;
    allow list: if false;
  }

  match /{subcollection=**} {
    allow read, write: if request.auth != null && request.auth.uid == userId;
  }
}

// 共有会議: 認証済みユーザーは読み取り可能、書き込みは Cloud Functions のみ
match /shared_meetings/{meetingId} {
  allow read: if request.auth != null;
  allow write: if false;
}

// Big5性格解析データ
match /Big5Analysis/{personalityKey} {
  allow read: if request.auth != null;
  allow write: if false;
}
```

`PersonalityStatsMetadata` はルールに個別の許可が無く、
Cloud Functions（Admin SDK）からのみ読まれる。

## 7. データ量の見積もり

```
shared_meetings: 会議生成のたびに1件追加（再利用しないため件数は生成回数に比例）
meeting_history: ユーザー数 × 利用回数（参照のみなので軽量）
```
