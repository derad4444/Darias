## 🔍 5. データ生成ロジック（毎回新規生成）

会議はリクエストごとにその悩み（concern）へ沿って新規生成される。過去に生成した shared_meetings の検索・再利用は行わない。

### メイン処理フロー

```
1. キャラクターデータ取得（details/current）
   - personalityKey, confirmedBig5Scores, gender, sixPersonalities

2. カテゴリ判定
   - concernCategory 未指定なら gpt-4o-mini で判定

3. 統計データ算出
   - PersonalityStatsMetadata/summary から決定論的に計算
   - similarCount, totalUsers, avgAge, percentile

4. 会話生成（gpt-4o-2024-11-20）
   - 悩み（concern）+ カテゴリ + 6人の性格 + 統計をプロンプトに含める

5. shared_meetings に保存（add）
   - personalityKey, concernCategory, conversation, statsData
   - usageCount: 1, ratings: { avgRating: 0, totalRatings: 0, ratingSum: 0 }
   - createdAt, lastUsedAt

6. meeting_history に参照を保存（add）
   - sharedMeetingId, userConcern, concernCategory, userBIG5, cacheHit: false
```

> 実装は `shared/functions/src/functions/generateSixPersonMeeting.js` の
> `generateOrReuseMeeting`。shared_meetings の検索（`searchMeetingCache`）は
> 呼び出されず、`cacheResult` は常に null で生成パスを通る。

## 🔐 7. セキュリティルール

```javascript
// firestore.rules

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isAuthenticated() {
      return request.auth != null;
    }

    function isOwner(userId) {
      return isAuthenticated() && request.auth.uid == userId;
    }

    // 共有会議（全ユーザー読み取り可能）
    match /shared_meetings/{sharedMeetingId} {
      allow read: if isAuthenticated();
      allow write: if false;  // Cloud Functionsのみ
    }

    // 会議履歴（自分のキャラクターのみ）
    match /users/{userId}/characters/{characterId}/meeting_history/{historyId} {
      allow read, write: if isOwner(userId);
    }

    // 会議テンプレート（全ユーザー読み取り専用）
    match /meeting_templates/{templateId} {
      allow read: if isAuthenticated();
      allow write: if false;
    }

    // Big5Analysis（全ユーザー読み取り専用、統計用）
    match /Big5Analysis/{personalityKey} {
      allow read: if isAuthenticated();
      allow write: if false;
    }

    // PersonalityStatsMetadata（全ユーザー読み取り専用）
    match /PersonalityStatsMetadata/{docId} {
      allow read: if isAuthenticated();
      allow write: if false;
    }
  }
}
```

## 📈 8. データフロー

### 会議生成時のデータフロー（毎回新規生成）

```
1. ユーザーが悩みを入力
   ↓
2. Cloud Function呼び出し
   ↓
3. subscription/current から プレミアム状態確認
   ↓
4. characters/{characterId}/details/current から personalityKey 取得
   ↓
5. カテゴリ判定（concernCategory 未指定なら gpt-4o-mini）
   ↓
6. 会議を新規生成
   → PersonalityStatsMetadata から統計データ算出
   → 悩み（concern）+ カテゴリ + 6人の性格をプロンプトに含めて AI生成
   → shared_meetings に保存
   → meeting_history に参照保存
   → 完了（約1.63円、3-5秒）
   ↓
7. プレミアムユーザーは usage_tracking の月間カウントをインクリメント
```

## 📝 10. まとめ

### 新規追加するコレクション

1. **shared_meetings/{sharedMeetingId}** - 生成した会議の保存先（履歴・分析用、再利用はしない）
2. **users/{userId}/characters/{characterId}/meeting_history/{historyId}** - 個人履歴

### 既存コレクションの活用

1. **users/{userId}** - subscription.status でプレミアムチェック
2. **characters/{characterId}/details/current** - confirmedBig5Scores, personalityKey
3. **Big5Analysis/{personalityKey}** - 統計データのメインソース
4. **PersonalityStatsMetadata/summary** - サンプル数の取得

### Firestore Index

```javascript
// shared_meetings コレクション
// personalityKey ASC, concernCategory ASC, usageCount DESC（firestore.indexes.json に定義済み）
// 現状は再利用クエリを実行しないため、このインデックスは使用されない。
```

### データ量の見積もり

```
Big5Analysis: 既存89パターン
PersonalityStatsMetadata: 1,523ユーザー分

shared_meetings: 会議生成のたびに1件追加（再利用しないため件数は生成回数に比例）
meeting_history: ユーザー数 × 利用回数（参照のみなので軽量）

→ 統計データは実データから決定論的に算出
→ 会議は毎回その悩みに沿って新規生成
```
