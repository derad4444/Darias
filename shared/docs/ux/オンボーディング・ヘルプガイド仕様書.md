## 概要

新規ユーザーへの機能説明と、既存ユーザーへの操作ヒント表示を担う機能群。

| 機能 | 表示タイミング | 管理場所 |
|------|--------------|---------|
| オンボーディングスライド | 新規登録後・未視聴アカウントのログイン時 | Firestore `hasSeenOnboardingSlides` |
| 使い方ガイド画面 | 設定画面から任意で参照 | ハードコード |
| 相性診断 性格解析チェック | 相性診断画面（常時） | Firestoreリアルタイム |

## オンボーディングスライド

### 表示フロー

オンボーディングは**ホーム画面の上に重ねるダイアログ**として表示する。
そのため、どの経路でも一度ホーム（`/`）へ行き、ホーム表示後に `/onboarding` を **push** する。

```
新規登録
    ↓
register_screen.dart
    ├── needsOnboardingProvider = true（signUp() 呼び出し前にセット）
    └── signUp() 完了
            ↓
        GoRouter redirect（refreshListenable でトリガー）→ / (ホーム)

ログイン（splash経由）
    ↓
Firestore users/{uid}.hasSeenOnboardingSlides を確認
    ├── false または フィールドなし → needsOnboardingProvider = true → / (ホーム)
    └── true → / (ホーム)

            ↓
    MainShellScreen.initState の postFrameCallback
        └── needsOnboardingProvider == true
                ├── フラグを false に戻す
                └── context.push('/onboarding')  ← ホームを下に残したまま重ねる
```

> **実装注意1**: GoRouter の `redirect` はログイン完了を検知して即時発火するため、`context.go('/onboarding')` を `signUp()` 完了後に呼んでも redirect が先に `/` へ飛ばしてしまう。そのため `needsOnboardingProvider`（`StateProvider<bool>`）を事前にセットする方式を採用している。エラー時はフラグをリセット（`needsOnboardingProvider = false`）する。

> **実装注意2**: `/onboarding` は必ず `push` で開く。`go` で開くとホームがスタックから消え、背景に何も映らなくなる（暗幕だけの黒い画面になる）。フラグの消費（true → false）と push は `MainShellScreen` が担当する。

### スライド構成（6枚）

「AIがあなたを知っていく」という一本の物語として構成する。機能紹介の順ではなく、
**出会い → 話す → 変化が起きる → 使える → はじめる** の体験順に並べる。
読み飛ばされないよう1枚あたり3〜4行に抑える。

| # | タイトル | アイコン | 役割 |
|---|---------|---------|------|
| 1 | はじめまして。このAIは、あなたを何も知りません | `egg_alt_outlined` | 物語の起点。AIが白紙であることを伝える |
| 2 | 話すだけでいい | `chat_bubble_outline` | 性格テスト不要。チャット自動解析 |
| 3 | 30回話すと、あなたの元素が決まる | `local_fire_department` | 9元素の判定とAIの成長（赤ちゃん→幼少期） |
| 4 | 迷ったら、自分に聞けばいい | `groups` | 自分会議（6人の分身） |
| 5 | 悩みは、倒せる | `explore_outlined` | 冒険（心の迷宮） |
| 6 | さあ、最初のひと言を | `send_outlined` | 最初のチャットへの誘導。日記の存在もここで伝える |

#### 文言の方針

- **キャラクターは「AI」と呼ぶ**（「この子」等の呼称は使わない）
- **タイトルは語りかけにする**。「性格タイプが明らかに」のような体言止めの機能名は使わない
- **日記・相性診断は独立した枠を与えない**。6枚目の余韻に溶かし、枚数を増やさない
- 3枚目は「30回で元素が決まる」と「30回で幼少期に育つ」が**同時に起きる**ことを明示する
  （どちらも判定条件は `signalCount >= 30`。`axisCalculator.js` の `growthStage` と
  `character_detail_screen.dart` の表示条件が一致している）

#### ビジュアル

アイコンの代わりに画像を出すページがある（`_OnboardingPage.imagePath`）。

| # | 表示 | パス |
|---|------|------|
| 3 | 成長キャラ（赤ちゃん） | `assets/images/character_growth/赤ちゃん.png` |
| 5 | 敵「もやもや」 | `assets/images/roguelike_enemies/haze.png` |
| 6 | 成長キャラ（赤ちゃん） | `assets/images/character_growth/赤ちゃん.png` |

- **成長キャラの画像は背景がグレーで透過していない**ため、`clipImageToCircle: true` で
  円形に切り抜き（`BoxFit.cover`）カード背景に馴染ませる
- **敵画像は透過済み**なので切り抜かない。横長のため `BoxFit.contain` で高さだけ指定し、
  左右が切れないようにする
- サイズは `compactLayout` のページだけ一回り小さくして本文に高さを譲る

| ビジュアル | 通常ページ | compactLayout（3枚目） |
|-----------|-----------|----------------------|
| 円形の成長キャラ | 130px | 80px |
| 敵画像の高さ | 120px | 76px |
| アイコン | 80px | 56px |
- 画像の読み込みに失敗した場合は `errorBuilder` でアイコン表示に退避する

#### レイアウト

ホーム画面の上に**ダイアログ（小ウィンドウ）**として重ねて表示する。画面いっぱいには広げない。
背後のホーム画面は暗幕越しにうっすら見える。

| 項目 | 値 | 定義箇所 |
|------|----|---------|
| カード最大幅 | 420px | `_OnboardingScreenState._cardMaxWidth` |
| カード最大高さ | 620px | `_OnboardingScreenState._cardMaxHeight` |
| カード外側の余白 | 24px（四辺） | `_OnboardingScreenState._cardMargin` |
| 角丸 / 影 | 20px / `elevation: 8` | `Material` |
| カード背景色 | `colorScheme.surface` | `Material.color` |
| 暗幕の濃さ | 黒 45%（`_scrimOpacity = 0.45`） | `Scaffold.body` の `Container.color` |

- ルートは `CustomTransitionPage(opaque: false)` + フェード200msで開く（`app_router.dart`）。
  `opaque: false` により、下に積まれたホーム画面が描画されたまま残る
- `barrierDismissible: false`。背景タップでは閉じない（スキップ／最終ページのボタンでのみ閉じる）
- 暗幕は `Scaffold`（`backgroundColor: Colors.transparent`）の body に敷いた半透明の `Container`
- `SafeArea` → `Center` → `Padding` → `LayoutBuilder` → `SizedBox` の順で構成する
- `SizedBox` の幅・高さは `min(利用可能サイズ, 最大値)` で決める。
  `Center` から渡される制約は緩い（min 0）ため、高さを確定させないと
  カード内 `Column` の `Expanded`（PageView）が成立しない
- 端末が小さい場合はカードが利用可能サイズまで縮む（余白24pxは常に確保される）
- スキップ・PageView・ドットインジケーター・ボタンはすべてカード内に収まる
- 各ページは `LayoutBuilder` + `SingleChildScrollView` + `ConstrainedBox` で構成する。
  収まらない場合はカード内でスクロールする
- 配置は `_OnboardingPage.compactLayout` でページごとに切り替える。
  本文が一番長い**3枚目だけ `compactLayout: true`** にして上へ寄せている

| 項目 | 通常ページ | compactLayout（3枚目） |
|------|-----------|----------------------|
| 縦の配置 | 上下中央（`MainAxisAlignment.center`） | 上寄せ（`MainAxisAlignment.start`） |
| ページ内余白（上下） | 16px | 0px |
| ビジュアル↔タイトル | 32px | 12px |
| タイトル↔本文 | 20px | 12px |

  ※ 左右の内側余白は共通で24px

### 操作

| ボタン | 動作 |
|--------|------|
| スキップ | Firestoreに`hasSeenOnboardingSlides: true`を書き込み → ダイアログを閉じる（`context.pop()`） |
| 次へ | 次のスライドへ |
| チャットを始める！（最終ページ） | Firestoreに`hasSeenOnboardingSlides: true`を書き込み → ダイアログを閉じる（`context.pop()`） |

閉じたあとは下に残っていたホーム画面がそのまま現れる。
`pop` できない状態（`/onboarding` を直接開いた場合など）では `context.go('/')` でホームへ送る。

### Firestore管理

- **フィールド**: `users/{userId}.hasSeenOnboardingSlides` (`boolean`)
- **設定タイミング**: スキップ or 始める！ボタン押下時
- **初期値**: フィールドなし（= `false` 扱い）
- **目的**: 端末・ブラウザ問わずアカウント単位での表示制御

> **注意**: 既存フィールド `hasCompletedOnboarding` はキャラクター作成完了フラグとして独立して使用。オンボーディングスライドの表示制御には `hasSeenOnboardingSlides` を使用する。

### 実装ファイル

- `lib/presentation/screens/onboarding/onboarding_screen.dart`（ダイアログ本体）
- `lib/presentation/screens/splash/splash_screen.dart`（ログイン時の判定・`needsOnboardingProvider` セット）
- `lib/presentation/screens/auth/register_screen.dart`（`needsOnboardingProvider` セット）

- `lib/presentation/router/app_router.dart`（`/onboarding` の透明ルート定義・`needsOnboardingProvider` 定義）

## 相性診断 性格解析チェック

### 概要

相性診断はフレンドと自分双方の性格解析が必要。  
性格解析は `confirmedBig5Scores`（旧BIG5 100問方式、後方互換）または `convertedBig5Scores`（チャット自動解析の5軸変換済みスコア）のいずれかが存在すれば利用可能。  
どちらも存在しない場合は「診断する」ボタンを非活性にし、理由を画面に表示する。

> **旧BIG5方式について**: `confirmedBig5Scores` はBIG5 100問診断を完了したユーザーのスコアで、既存ユーザーの後方互換として残存する。新規ユーザーはチャット自動解析（30回以上）により `convertedBig5Scores` が生成される。

### 判定ロジック

```dart
// 自分の性格解析スコア（confirmedBig5Scores OR convertedBig5Scores）
final myDetails = ref.watch(characterDetailsProvider).valueOrNull;
final myBig5Done = (myDetails?.confirmedBig5Scores?.isNotEmpty ?? false)
    || (myDetails?.convertedBig5Scores?.isNotEmpty ?? false);

// フレンドの性格解析スコア
final friendDetailsAsync = ref.watch(userCharacterDetailsProvider(friend.id));
final friendBig5Done =
    (friendDetailsAsync.valueOrNull?.confirmedBig5Scores?.isNotEmpty ?? false)
    || (friendDetailsAsync.valueOrNull?.convertedBig5Scores?.isNotEmpty ?? false);

// ロード中は誤表示を防ぐため活性にしておく
final dataLoaded = !characterDetailsProvider.isLoading && !friendDetailsAsync.isLoading;
final ready = !dataLoaded || (myBig5Done && friendBig5Done);
```

### UI表示

| 状態 | 表示内容 |
|------|---------|
| 両方未解析 | 「診断には自分と〇〇さん双方の性格解析（30回以上チャット）が必要です」 |
| 自分のみ未解析 | 「診断にはあなたの性格解析が必要です。チャットを30回以上続けてください」 |
| フレンドのみ未解析 | 「診断には〇〇さんの性格解析が必要です」 |
| 両方完了 | 警告非表示。「診断する」ボタン活性 |
| ロード中 | 警告非表示。「診断する」ボタン活性（誤表示防止） |

### Cloud Function側の処理

`diagnoseCompatibility` は `confirmedBig5Scores` → `convertedBig5Scores` の順でフォールバックしてスコアを取得する。どちらも存在しない場合は `{error: "BIG5データが不足しています"}` を返す。

### 実装ファイル

- `lib/presentation/screens/friend/compatibility_screen.dart`
- `lib/presentation/providers/character_provider.dart`（`userCharacterDetailsProvider`）
