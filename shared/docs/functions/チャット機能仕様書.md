## アーキテクチャ概要

```
ユーザー入力（ホーム画面）
    │
    ▼
ChatDatasource.sendMessage()
    │
    ▼
classifyAndExtract（Cloud Function / gpt-4o-mini）
    │
    ├─① type: "app_qa"   → answerAppQuestion（Cloud Function）
    │
    └─② type: "chat"     → generateCharacterReply（Cloud Function）
            ├─ 直近2件のチャット履歴（posts）
            ├─ キャラクターの記憶 最大5件（memory/current）
            ├─ 直近30日の会議結論（meeting_history → shared_meetings）[Case 4]
            ├─ 悩み系キーワード検出 → meetingSuggested フラグ [Case 2]
            └→ posts コレクションに保存
```

会話履歴は直近2往復しか渡らないため、**昨日以前の話題を思い出せるのは「キャラクターの記憶」だけ**。記憶は毎晩の日記生成で作られる（[キャラクターの記憶](#キャラクターの記憶)）。

## メッセージ振り分けロジック

振り分けは `classifyAndExtract` Cloud Function（AI）が行う。キーワードによる静的な判定は廃止。

### 分類の優先順位と判定基準

| 分類 | 判定基準 | 例 |
|------|---------|-----|
| `app_qa` | アプリの使い方・機能に関する質問 | 「日記はどこで見れる？」「自分会議って何？」 |
| `chat` | 上記以外の会話・相談・雑談 | すべての一般的な会話 |

分類とあわせて性格シグナルタグ（最大3件）も抽出される。

## AIメッセージ分類

### Cloud Function: `classifyAndExtract`

メッセージを `app_qa` / `chat` の2種類に分類し、あわせて性格シグナルタグを抽出して返す。1回のAI呼び出しで分類と抽出を同時実行（コスト効率）。

**モデル**: `gpt-4o-mini`（固定）

**入力:**
```javascript
{
  userMessage: string,
}
```

**返却（分類別）:**

```javascript
// app_qa（アプリの使い方の質問）
{ "type": "app_qa", "tags": [] }

// chat（通常の会話）
{ "type": "chat", "tags": ["emotional_expression"] }
```

---

### Flutter側のハンドリング

```dart
// classifyAndExtract 呼び出し
final callable = _functions.httpsCallable('classifyAndExtract');
final result = await callable.call({'userMessage': trimmed});
final type = result.data['type']; // "app_qa" | "chat"
```

`app_qa` なら `answerAppQuestion` へ、それ以外は `generateCharacterReply` へ流す。

## 通常チャット

### Cloud Function: `generateCharacterReply`

**Cloud Function 側の処理の振り分け（優先順）:**

1. **無意味な入力検出**（3文字未満・記号のみ・繰り返し文字等）→ フォールバック固定返答
2. **通常チャット** → OpenAI でキャラクター返答を生成

### 入力パラメータ

```javascript
{
  characterId: string,
  userMessage: string,      // 400文字まで処理（超過分は直前の 。！？ までで打ち切る）
  userId: string,
  isPremium: boolean,
  chatHistory: [            // 直近2件の会話履歴
    { userMessage: string, aiResponse: string }
  ],
  meetingContext?: string,  // 直近30日の会議結論（後述 Case 4）
  openerContext?: string,   // 会話のきっかけテキスト（スマートオープナーの文言）
  phase: 1 | 2 | 3,        // 返答フェーズ（Flutter側で算出して送信、デフォルト: 1）
}
```

### 返却値

```javascript
{
  reply: string,
  voiceUrl: "",              // 常に空文字（音声は別途生成）
  // 感情表現（通常チャット時のみ値あり）:
  emotion?: string,          // "" (normal) / "_smile" / "_angry" / "_cry" / "_sleep"

}
```

### モデル選択

| 処理 | ユーザータイプ | モデル | 該当箇所 |
|------|-------------|--------|---------|
| 感情検出（`emotionDetect`） | 共通 | `gpt-4o-mini` | `generateCharacterReply.js` の `detectEmotion` |
| チャット返信 | 無料 | `gpt-4o-mini` | `generateCharacterReply.js`（`isPremium` による分岐） |
| チャット返信 | プレミアム | `gpt-4o-2024-11-20` | 同上 |

### キャラクタープロンプトの構成

`OPTIMIZED_PROMPTS.characterReply()` を使用。入力は以下:

- **type**: 性格タイプ（AI / Learning / Human）
- **gender**: male / female / neutral
- **big5**: 5つのスコア（openness, conscientiousness, extraversion, agreeableness, neuroticism）
  - `convertedBig5Scores`（チャットシグナルから変換）を優先し、なければ `confirmedBig5Scores` を使用
- **dreamText**: キャラクターの夢。`users/{uid}/characters/{cid}/dream/current` の `dream` から取得する（5分キャッシュ。未移行ユーザーは `details/current.dream` にフォールバック）。未選択の場合は「夢はまだ決まっていません」を送る。詳細は [性格解析仕様書の夢の選択フロー](性格解析仕様書.md#夢の選択フロー) を参照
- **userMessage**: ユーザーのメッセージ
- **meetingContext**: 直近30日の会議結論（Case 4）
- **memoryContext**: キャラクターの記憶 最大5件。`memory/current.items` の新しい順に `・{text}（{M/D}）` を並べた文字列（5分キャッシュ）。「今の話題に関係するときだけ自然に触れる」指示を添えて `【覚えていること】` としてシステムプロンプトに挿入する。記憶が無ければ挿入しない
- **openerContext**: スマートオープナーの文言（省略可。存在する場合「会話のきっかけ: {text}」としてシステムプロンプトに挿入）

> **スコアの送り方**: `characterReply` は `buildPersonalityTraits()` で自然言語に変換して送信（数値は送らない）。`diary` / `activityDiary` / `characterDetails` は `formatBig5ShortWithTraits()` で数値＋短いラベルのコンパクト形式（例: `O3(バランス型)C4(計画的)E2(内向的)A5(共感型)N1(超安定)`）で送信。（2026-04-04 変更）

性格タイプは `androidScore` で決定:
```
androidScore = (6 - agreeableness) + (6 - extraversion) + (6 - neuroticism)

>= 9 → AI型    (論理的・システマティック)
<= 6 → 人間型  (共感・感情重視)
それ以外 → 学習型 (論理+感情のミックス)
```

### 返答プロンプトの構造 ― フェーズ別システム（2026-05-20 更新）

`characterReply` プロンプトは `phase` パラメータに応じて3段階の指示文を切り替える。  
性格データが不十分な段階（`signalCount < 10`）ではPhase 1固定とし、誤った性格言及を防ぐ。

#### フェーズ対応表

| フェーズ | 適用条件 | 文字数上限 | 返答スタイル | ユーザー体験 |
|---------|---------|----------|-------------|------------|
| **Phase 1** | signalCount < 10（全ターン）または signalCount ≥ 30 の session turn 1 | 120文字 | 受け止め＋読み＋質問（性格反映なし） | 自然な受け答え |
| **Phase 2** | signalCount 10〜29（全ターン）または signalCount ≥ 30 の session turn 2〜4 | 150文字 | 受け止め＋性格仮説＋質問 | 「あたってるかも？」体験 |
| **Phase 3** | signalCount ≥ 30 かつ session turn 5以上 | 220文字 | 受け止め＋性格言語化＋質問（任意） | 「なるほど、そういう人間なんだ」体験 |

#### フェーズ算出ロジック（Flutter: `home_screen.dart`）

```dart
int _calcPhase(int signalCount, int sessionTurn) {
  if (signalCount < 10) return 1;  // 性格データ未確定 → 性格反映なし
  if (signalCount < 30) return 2;  // 初回解析済み・元素未確定 → 性格仮説
  if (sessionTurn <= 1) return 1;
  if (sessionTurn <= 4) return 2;
  return 3;
}
```

- `sessionChatCountProvider`：アプリ起動ごとにリセット（セッション単位で管理）
- `phase` は Flutter側で算出し、Cloud Function に渡す（サーバーは受け取ったphaseをそのまま使用）
- 自分会議の結論を送る経路（`home_screen.dart` `_triggerMeetingFollowup`）も
  通常チャットと同じ `_calcPhase` の結果を渡す

#### Phase別プロンプト指示文

全フェーズ共通の**最優先ルール**（フェーズ指示より優先）:
```
- ユーザーが「〜ってこと？」「〜なの？」「なんで？」「どういうこと？」など疑問形で返してきた場合は、
  まずその質問に直接答える。①②③の構造より質問への応答を最優先する。
- ユーザーがすでに答えた内容（「〜です」「〜かな」「〜だと思う」と明言したこと）を
  改めて同じ質問で聞き返さない。
```

**Phase 1（120文字以内）:**
```
① ユーザーの言葉を1文で受け止める（共感・肯定）
② あなたが読み取ったことを返す：「〜ってことかな」「〜が気になってるのかも」など（1文）
   ※答えを教えるのではなく、あなたの"読み"を提示する。ズレていれば訂正させてよい
③ 本音を引き出す問いを1つ（任意：会話の流れ上ぎこちなくなるなら省いてよい）
質問することが目的ではなく、ユーザー自身が気づくよう促すことが目的。
```

**Phase 2（150文字以内）:**
```
① ユーザーの言葉を1文で受け止める
② 性格特性を踏まえた"仮説"を返す：「〜な面が出てる気がする」「あなたらしい選択だと思う」など（1〜2文）
   ※正解ではなく仮説として提示する。ズレていれば訂正させてよい
③ 仮説を確認するか深掘りする問いを1つ（任意：会話の流れ上ぎこちなくなるなら省いてよい）
「あたってるかも？」と感じてもらえるような性格の洞察を心がける。質問することが目的ではなく、洞察を届けることが目的。
```

**Phase 3（220文字以内）:**
```
① ユーザーの言葉を受け止め、感じたことを1文で返す
② 性格特性に基づく深い洞察を2〜3文で：「〜という傾向があるから〜と感じるのは自然」「〜タイプはこういう場面でこう動きやすい」など
   ※性格タイプ名（炎タイプ等）を自然に使ってよい。ラベルを貼るのでなく"なぜそう感じるのか"を説明する
③ 自己理解を深める問いを1つ（任意：洞察で会話が完結するなら省いてよい）
"なるほど、自分ってそういう人間なんだ"と納得させることを目指す。質問することが目的ではなく、気づきを届けることが目的。
```

#### `max_completion_tokens` 設定

```javascript
// generateCharacterReply.js  getMaxTokensForPhase()
if (phase === 2) return 250; // ~150文字
if (phase === 3) return 350; // ~220文字
return 200;                  // ~120文字 (phase 1)
```

**設計意図:**
- signalCount < 10 は性格データ未確定のため Phase 1 固定（誤った性格言及を防ぐ）
- signalCount 10〜29 は初回解析済みだが元素タイプ未確定のため Phase 2 固定（性格仮説を提示）
- Phase 3 は元素タイプ確定後（signalCount ≥ 30）かつ session turn 5以上のみ有効
- Phase 3 ではtypeName（「炎タイプ」等）が返答中に自然に使われる
- 全フェーズで質問は任意。会話の流れ上ぎこちない場合は省いてよい。質問することが目的ではなく、気づき・洞察を届けることが目的

## アプリQ&A

### Cloud Function: `answerAppQuestion`

アプリの使い方に関する質問、またはユーザーデータ参照が必要な質問に回答。`classifyAndExtract` が `app_qa` と判定した場合に呼び出される。

**入力:**

```javascript
{
  userId: string,
  userMessage: string,
}
```

**処理:**
1. `APP_GUIDE`（アプリ全機能の説明）をシステムプロンプトに組み込み
2. `gpt-4o-mini` で回答生成。Firestore へのアクセスは行わない

**APP_GUIDE でカバーするトピック（`answerAppQuestion.js` 内に定義）:**
- チャット操作・チャット履歴・日記の確認方法
- キャラクターについて（BIG5診断・変更方法）
- 日記の自動生成（アクティビティ型）
- 自分会議（6人会議）の使い方・利用制限
- フレンド機能（追加・申請・承認）
- 相性診断（カテゴリ・解放方法・条件）
- プレミアム機能（高品質AI・自分会議月30回）
- 設定（テーマ・音量・通知）
- アカウント管理（削除時の注意事項）

**返却:** `{ reply: string }` （postsに保存しない）

## 会議連携

### Case 1: 会議後フォローアップ（ホーム画面への固定メッセージ）

会議画面で「チャットで深掘りする」ボタンを押すと:

1. `meetingFollowupConclusionProvider`（`StateProvider<String?>`）に会議結論を書き込む
2. ホームタブ（index 0）に遷移
3. ホーム画面の `ref.listen<String?>` がプロバイダーの変化を検知
4. 固定メッセージ「会議お疲れ様！続きがあれば話しかけてね」を表示

**特徴:**
- Cloud Function の呼び出しなし（固定文）
- `IndexedStack` でホーム画面は常にマウント済みのため `ref.listen` が機能する

```dart
// meeting_screen.dart
ref.read(meetingFollowupConclusionProvider.notifier).state =
    _meetingResponse!.conversation.conclusion.summary;
ref.read(selectedTabProvider.notifier).state = 0;
context.go('/');

// home_screen.dart（build内）
ref.listen<String?>(meetingFollowupConclusionProvider, (prev, next) {
  if (next != null) {
    ref.read(meetingFollowupConclusionProvider.notifier).state = null;
    _triggerMeetingFollowup(next);
  }
});
```

### Case 2: 悩み系キーワードへの会議提案

通常チャット時に悩み系キーワードを検出すると `meetingSuggested: true` を返す。

**トリガーワード:**
```dart
'どうしよう', '迷ってる', '迷っている', '決められない', '悩んでいる',
'悩んでる', 'どうすればいい', 'どうしたらいい', '困ってる', '困っている',
'迷い', '悩み', 'どうしたら', '相談したい', '判断できない', 'わからなくなってきた'
```

Flutter側で `meetingSuggested == true` の場合に「6人会議を試す？」等のUIを表示（呼び出し元の実装依存）。

### Case 4: 会議結論をチャットのコンテキストに注入

通常チャット時、直近30日以内の会議結論を `generateCharacterReply` に `meetingContext` として渡す。

```dart
Future<String?> _fetchRecentMeetingConclusion(userId, characterId) async {
  // meeting_history から最新1件取得
  // 30日以内かチェック
  // shared_meetings から conclusion.summary を取得
  // "相談:{concern} / 結論:{summary(80文字)}" 形式で返す
}
```

Cloud Function 側ではこれをシステムプロンプトに組み込む。プロンプト形式:

```
【会議コンテキスト】相談:{concern} / 結論:{summary(80文字)}
（ユーザーが会議について話している場合はこの内容を踏まえて返答してください）
```

会議に関係する話題のときのみ言及するよう明示的に指示している。

## チャットオープナー

### 概要

ホーム画面を開いたとき（初回マウント時）に、ユーザーがチャットを始めるきっかけとなる「オープナーメッセージ」をキャラクターの吹き出しに表示する仕組み。**表示時点でのAI呼び出しは行わない**（M は前夜の日記生成で作り置きしたものを読むだけ）。

実装ファイル: `lib/presentation/screens/home/chat_opener.dart`

### 優先順位（M → F → A）

```
M: 記憶オープナー（前夜の日記生成が用意した、昨日までの話題に触れる問いかけ）
    ↓（なければ or 今日すでに出したなら）
F: 前回のAI返答から保存した問いかけ（未使用のもの）
    ↓（なければ or 使用済みなら）
A: デイリープロンプト（47種・日付ベースローテーション）
```

#### M: 記憶オープナー（1日1回）

`users/{uid}/characters/{cid}/memory/current` の `opener` を読み、`openerDate` が当日（JST）と一致する場合だけ表示する。

例: 「昨日言ってた面接、どうだった？」

- 生成は毎晩の日記生成（`generateDiary`）。翌日の日付を `openerDate` に入れて保存する
- 表示したことは **SharedPreferences に記録する**（Firestoreは書き換えない）。読み取り失敗・オフラインでも従来の F → A にフォールバックするだけで壊れない
- `openerDate` が当日でないものは表示しない（使い残したオープナーが何日も出続けるのを防ぐ）
- `characterId` が必要なため、`userDocProvider` のロードを最大3秒待つ（`home_screen.dart` の `_waitForCharacterId()`）。取れなければ M を諦めて F → A へ進む

**SharedPreferences キー:**

| キー | 型 | 用途 |
|-----|-----|------|
| `memory_opener_used_date_{userId}` | `String` | 記憶オープナーを表示した日付（`YYYY-MM-DD`）。同日内の重複表示を防ぐ |

#### F: 前回の問い（1回限り）

AI返答の末尾から `？` で終わる最後の文を `saveLastQuestion()` で抽出・保存。次回起動時に1回だけ「前回の問い、その後どうなった？」として再提示し、表示後は使用済みフラグを立てる。

**SharedPreferences キー:**

| キー | 型 | 用途 |
|-----|-----|------|
| `chat_last_question` | `String` | 前回の問いかけ文 |
| `chat_question_used` | `bool` | 使用済みフラグ（true = 表示済み） |
| `chat_opener_saved_date` | `String` | オープナーをFirestoreに保存した最終日付（`YYYY-MM-DD`形式）。同日内の重複保存を防ぐ |

```dart
// 表示時
await prefs.setBool(_sharedPrefKeyUsed, true);
return ChatOpener(
  type: OpenerType.previousQuestion,
  text: '前回の問い、その後どうなった？\n「$lastQuestion」',
);
```

#### A: デイリープロンプト

47種類の問いかけが `dailyPrompts` リストにハードコード。

```dart
final dayIndex = today.difference(DateTime(2024, 1, 1)).inDays.abs();
final prompt = dailyPrompts[dayIndex % dailyPrompts.length];
```

1日中同じプロンプトを表示（同日内は不変）。カテゴリは以下:

| カテゴリ | 件数 |
|---------|------|
| 朝・スタート系 | 7 |
| 振り返り系 | 6 |
| 自己探求系 | 11 |
| 思考整理系 | 7 |
| 軽め・雑談系 | 6 |
| 深掘り系 | 7 |

### `saveLastQuestion()` の呼び出しタイミング

AI返答が返るたびに末尾の問いかけ文を保存する。

```dart
// _sendMessage() 内
if (result != null) saveLastQuestion(result.reply);

// _triggerMeetingFollowup() 内
if (result != null) saveLastQuestion(result.reply);
```

`saveLastQuestion()` は返答を `。！\n` で分割し、`？` または `?` で終わる最後の文を抽出。抽出できた場合のみ `chat_question_used: false` で保存（次回Fオープナーとして使用可能になる）。

### ロード処理・Firestore保存

```dart
// home_screen.dart initState()
WidgetsBinding.instance.addPostFrameCallback((_) => _loadChatOpener());

Future<void> _loadChatOpener() async {
  if (!mounted || _openerLoaded) return;
  _openerLoaded = true;  // 再実行防止
  final characterId = await _waitForCharacterId();  // M（記憶オープナー）に必要
  final opener = await computeChatOpener(userId: userId, characterId: characterId);
  if (mounted) {
    setState(() {
      _displayedMessage = opener.text;
      _isCharacterReply = true;
    });
    await _saveOpenerIfNeeded(opener.text);  // 1日1回Firestoreに保存
  }
}
```

オープナーは `_saveOpenerIfNeeded()` で1日1回だけ `posts` コレクションに保存される（`content: ""`, `analysis_result: opener.text`）。`chat_opener_saved_date` と当日日付が一致する場合はスキップする。

初期表示時は時間帯挨拶/ランダムメッセージを暫定表示し、プロバイダーのデータがロードされてから上書きする。

## キャラクターの記憶

### 概要

チャットで AI に渡る会話履歴は**直近2往復（各100文字まで）**しかない。そのため昨日以前に話したことは、そのままでは思い出せない。これを補うのが「キャラクターの記憶」。

毎晩の日記生成（23:50 JST）で、その日の会話から「明日以降も覚えておく価値のあること」を抽出して保存し、次の日からのチャットでプロンプトに載せる。

**AI呼び出しは増えていない。** 日記生成はもともと当日のユーザー発言を最大5件プロンプトに渡している（`generateDiary.js` の `chatSummary`）ので、同じ1回の生成の出力項目を増やしているだけ。

実装ファイル:
- `shared/functions/src/utils/memoryStore.js`（保存・取得・整形）
- `shared/functions/const/generateDiary.js`（抽出と保存）
- `shared/functions/const/generateCharacterReply.js`（チャットへの注入）

### 保存先

`users/{uid}/characters/{cid}/memory/current`

```jsonc
{
  "items": [                                  // 新しい順。最大10件
    {"text": "面接の結果を今週中に聞く", "date": "2026-09-23"}
  ],
  "opener": "昨日言ってた面接、どうだった？",   // 翌朝のオープナー
  "openerDate": "2026-09-24",                 // このオープナーを出す日（JST）
  "updated_at": "Timestamp"
}
```

`details/current` は firestore.rules で認証済みユーザー全員に単体取得が許可されている（フレンドのアバター表示のため）。記憶はユーザーの発言から作られる私的な内容なので、**夢と同じく本人限定のサブコレクションに置く**。`users/{userId}/{subcollection=**}` の既存ルールで本人のみ読み書き可能になるため、`firestore.rules` の変更は不要。

### 制限値（`memoryStore.js`）

| 定数 | 値 | 意味 |
|-----|----|-----|
| `MEMORY_MAX_LENGTH` | 40 | 記憶1件の最大文字数 |
| `MEMORY_MAX_ITEMS` | 10 | 保持する最大件数。超えた古い記憶は捨てる |
| `MEMORY_NEW_PER_DAY` | 3 | 1日に新しく追加できる件数 |
| `MEMORY_PROMPT_ITEMS` | 5 | チャットのプロンプトに載せる件数 |
| `OPENER_MAX_LENGTH` | 40 | オープナーの最大文字数 |

**件数を固定しているため、何年使ってもプロンプトは伸びない。** これがこの設計の要点。

### 生成（日記プロンプト）

`OPTIMIZED_PROMPTS.activityDiary()` の出力が3項目になった:

```json
{"ai_comment":"コメント","memories":["覚えておくこと"],"opener":"明日の問いかけ"}
```

- **memories**: 0〜3件。予定・出来事・悩み・好み・目標など、後日また話題にできる事実のみ。感想や評価は書かせない
- **opener**: 40文字以内の短い問いかけ。**memories に書いた話題にだけ触れる**。memories が空なら空文字

#### 有ること無いことを書かせない（最重要）

記憶はチャットで何度も蒸し返されるため、**会話に無いことが1件でも混ざると体験が壊れる**。プロンプトで次を指示している:

- **ユーザーが実際に言ったことだけを書く。** 会話に出ていない事情・理由・気持ち・結果・日付・固有名詞を推測で補わない
- 会話に出てきた言葉をそのまま使う。言い換えて意味を足さない
- 日付・曜日・場所・人名は、**会話に出てきたときだけ**書く
- 会話が雑談だけ、または会話が無かったときは空配列にする。**無理に埋めない**
- **迷ったら書かない**

実地検証（2026-09-24・gpt-4o-mini で実行）:

| 入力した会話 | memories | opener |
|------------|----------|--------|
| 「なんか今日は疲れた」「うーん、わかんない」「そうかも」 | `[]` | `""` |
| 「映画観た」だけ | `[]` | `""` |
| 「来週の水曜に転職の最終面接がある」「ランニング、今日で3日続いた」「週末は実家に帰る予定」 | 3件とも発言どおり | 「最終面接、緊張してるかな？」 |

曖昧な会話での空配列は3回とも再現した。

> **補足**: 当初は重複回避の指示（「すでに覚えていることは書かない」）が強すぎて、**具体的な会話でも memories が常に空**になっていた。「一字一句同じ内容は繰り返さない。ただし進展・具体化・結果が出たなら新しい事実として書く」＋例示に変えて解決している。捏造防止と取りこぼし防止はトレードオフなので、プロンプトを変えたら上の3ケースで必ず確認すること。

重複を防ぐため、**既に覚えている内容（最大10件）をプロンプトに渡して「同じ内容は書かない」と指示している**。それでも重複した場合は `saveMemory()` が同じ `text` を弾く。

### 品質保証

`ai_comment` の検証（`isUsableComment()`）と再試行は従来どおり。**再試行の判定基準は `ai_comment` だけ**で、`memories` と `opener` が空でも再試行しない（ユーザーに即座に出るものではなく、空で保存すれば済むため）。

2回とも失敗して定型文にフォールバックした場合、`memories` と `opener` は空で保存される。

記憶とオープナーはチャットのシステムプロンプトに埋め込まれるため、`sanitizeText()` / `sanitizeOpener()` で制御文字を除去し、コードポイント単位で長さを切る（絵文字が途中で割れない）。

### 記憶の保存に失敗した場合

`saveMemory()` の例外は握りつぶして日記の保存は続行する。記憶は翌日また作られるが、日記はその日限りのため。

## 性格解析システムとの連携

### チャットシグナルによる軸スコア・元素タイプ解析（主要システム）

チャットメッセージを `classifyAndExtract` が分類する際、メッセージの特徴を示す**パーソナリティタグ**（最大3件）も同時に抽出する。有効なタグが含まれる場合は `personalitySignals` に保存し、累積カウントが **10の倍数**になるたびに `calculateAndSaveAxisScores` が実行されて `details/current` の軸スコア・元素タイプを更新する。

**有効なパーソナリティタグ（16種）:**
```
social_reference, solo_preference, group_activity, initiating,
quiet_environment, planning_language, spontaneous_language, goal_oriented,
emotional_expression, logical_reasoning, intuitive_decision, data_driven,
cooperative_language, independent_stance, change_seeking, worry_anxiety
```

**軸スコア計算:**
- 過去90日・最大200件のシグナルを使用（時間減衰: 0.95^日数）
- 5軸スコア（energy / lifestyle / relationship / processing / judgment）を -1.0〜+1.0 で算出
- 軸スコアから元素（炎/風/雷/光/水/土/氷/闇/無）と typeName を決定
- `details/current` に `axisScores`, `element`, `typeName`, `convertedBig5Scores`, `axisUpdatedAt` を書き込む

**`_Big5AnalysisSection`（✨人格解析欄）の表示条件:**

```dart
if (signalCount >= 30 && detail.element != null)
  // _Big5AnalysisSection を表示
```

- `element` は10シグナル時点でも `calculateAndSaveAxisScores` によって書き込まれる
- しかし `generateCharacterDetails`（実際の詳細解析テキスト生成）が最初に実行されるのは **30シグナル到達時**（`axisGeneratedAt` がない場合のみ）。以降は性格タイプが変化するたびに再実行される
- 10シグナル時点では `element` が存在しても詳細解析データが未生成のため、ローディング状態が続く
- このためキャラクター詳細画面の表示しきい値を `signalCount >= 30` としている

### 診断リセット（性格リセット）

リセット起点: 設定画面「性格診断をリセット」ボタン（`big5_datasource.dart: resetDiagnosis()`）

| 対象 | 操作 |
|------|------|
| `users/{userId}/characters/{characterId}/big5Progress/current` | ドキュメント削除 |
| `users/{userId}/characters/{characterId}/details/current` | `confirmedBig5Scores`, `personalityKey`, `analysis_level`, `sixPersonalities`, キャラクター属性15項目, `axisScores`, `element`, `typeName`, `convertedBig5Scores`, `axisUpdatedAt`, `axisGeneratedAt`, `personalityNarrative` を削除 |
| `users/{userId}/characters/{characterId}/generationStatus/current` | ドキュメント削除 |
| `users/{userId}/personalityMeta/current` | ドキュメント削除（signalCount=0相当） |
| `users/{userId}/personalitySignals/{*}` | サブコレクション内全ドキュメント削除 |
| `users/{userId}.growthStage` | `0` にリセット |
| `sessionChatCountProvider`（Flutter in-memory） | `0` にリセット（フェーズ算出のセッションターン数） |

## Firestoreへの保存

### postsに保存されるケース

**保存される**:
- 通常チャット（`generateCharacterReply`）→ `content` + `analysis_result` 両方あり

- 診断リセット

### 保存データ

```
├── content: string        // ユーザーメッセージ（最大100文字）。オープナー保存時は ""

```

**書き込み場所**: Cloud Function ではなく Flutter クライアントが保存する。

- `content` が空のドキュメント（オープナー）はユーザーバブルを表示せず、`analysis_result` のキャラクターバブルのみ表示する
- `analysis_result` が空の場合もキャラクターバブルを表示しない（`if (message.analysisResult.isNotEmpty)` チェック済み）
