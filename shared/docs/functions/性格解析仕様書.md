**ステータス**: 全フェーズ実装済み（週次スケジューラーはデプロイ要）
**作成日**: 2026-05-09
**最終更新**: 2026-10-07（性格の判定を、チャットのタグを数える方式から、バッジ診断の質問への回答をAIが軸ごとに採点する方式に変えた。成長段階はバッジで決まる）

> 旧称「性格診断リニューアル設計書」。BIG5 100問方式を廃止し、チャットから継続的に性格を自動推定する新システムの完全仕様。

## 概要

キャラクターが性格の質問をし、ユーザーが答えて「バッジ」を集めると性格タイプが決まるシステム。質問は5つの性格軸ごとに用意してあり、回答をAIが軸の上で直接採点する。普段の雑談は性格の判定に使わない。

- 第1弾：5つのバッジ × 各2問 ＝ 10問。全部答えると元素・タイプ名が決まり、キャラクターが幼少期に成長する
- 第2弾：5つのバッジ × 各2問 ＝ 10問（より深い質問）。全部答えると20問で計算し直し、キャラクターが大人に成長する
- 取得済みのバッジは答え直せる。答え直すと性格を計算し直す
- 性格タイプ: 9元素 × 各2役割 = 18タイプ
- 旧BIG5診断（`confirmedBig5Scores`）は既存ユーザーの後方互換として残存するが、新規ユーザーへの提供は停止

質問の出し方・採点・会話の進め方は [バッジ診断](#バッジ診断) を参照。設計の経緯と判断は `バッジ診断_設計書.md`、質問の一覧は `バッジ質問一覧.md`。

## 5つの性格軸

各軸の値はバッジ診断の回答の点数から計算する。元素・役割の判定はその結果から行う。

| 軸 | フィールド名 | -1.0（左端） | +1.0（右端） |
|----|------------|------------|------------|
| エネルギー | `energy` | 内向的 | 外向的 |
| 判断基準 | `judgment` | 感情重視 | 論理重視 |
| 関わり方 | `relationship` | 独立 | 協調 |
| 行動スタイル | `lifestyle` | 自由奔放 | 計画的 |
| 処理スタイル | `processing` | 直感 | 分析 |

---

## 軸スコアの計算方法

```
axis_score = その軸の回答の点数（-2〜+2）の平均 ÷ 2
→ 結果は必ず -1.0〜+1.0 に収まる
```

- 第1弾だけ答えた人は第1弾の10問（各軸2問）、第2弾まで答えた人は20問（各軸4問）で計算する
- 期限や時間による減衰はかけない（回答は答え直すまで有効）
- 0点（中間）も有効な回答として平均に入る。無・風・土の判定に必要なため
- 回答からほかの軸も読み取れたときの点数（`sub`）は保存しているが、計算には入れていない

**計算するタイミング**: 第1弾がそろったとき・第2弾がそろったとき・答え直しが終わったとき（`badgeStore.js` の `handleAnswer`）

## 9元素システム

### 元素の対応関係

外向と内向が鏡になる対称構造。対の元素は相性表の軸となる。

```
外向グループ               内向グループ
  炎（感情）       ↔         水（感情）
  風（判断中間）   ↔         土（判断中間）
  雷（論理×直感）  ↔         氷（論理×直感）
  光（論理×分析）  ↔         闇（論理×分析）

           無（エネルギー中間・真の中心）
```

### 各元素のイメージ

| 元素 | 性格イメージ |
|------|------------|
| 炎 | 情熱・衝動・感情が外に爆発する |
| 風 | 自由・好奇心・軽やか・感情にも論理にも縛られない |
| 雷 | 決断力・瞬発力・直感的な論理で外へ放電 |
| 光 | 明晰・計画的・分析的な論理で外を照らす |
| 水 | 共感・深さ・感情が内に深まる |
| 土 | どっしり安定・内に根を張る・ぶれない |
| 氷 | 冷静・冷たい本能・直感的な判断を内で凍てつかせる |
| 闇 | 内省・思索・分析的な論理を内に深める |
| 無 | 形がない・全てを受け入れる・観察者 |

### 元素カラー定義

| 元素 | カラー（HEX） |
|------|-------------|
| 炎 | `#E53935`（赤） |
| 水 | `#1E88E5`（青） |
| 風 | `#43A047`（ティール） |
| 土 | `#8D6E63`（ブラウン） |
| 氷 | `#4FC3F7`（ライトブルー） |
| 雷 | `#FDD835`（黄） |
| 光 | `#FFB300`（ゴールド） |
| 闇 | `#6A1B9A`（ダークパープル） |
| 無 | `#9E9E9E`（グレー） |

### 対の元素と相性

| 対 | 共通点 | 対立点 | 相性の性質 |
|----|--------|--------|----------|
| 炎 ↔ 水 | 感情重視 | 外に爆発 vs 内に深まる | 感情で深く繋がるが、ぶつかることも |
| 風 ↔ 土 | 判断が中間 | 自由に動く vs 動かない | 完全な対極、刺激し合うか相容れないか |
| 雷 ↔ 氷 | 論理×直感 | 熱く放電 vs 冷たく凍てつく | 同じ直感型、熱量の違いで惹かれ合う |
| 光 ↔ 闇 | 論理×分析 | 外を照らす vs 内を深める | 同じ分析型、視点の向きが逆 |
| 無 | ― | ― | 全元素と一定の相性（形がなく相手に合わせられる） |

## 元素判定ロジック

### Step 1：元素の決定（3軸使用）

```
エネルギー軸が中間（-0.3〜+0.3）
  → 無

エネルギー軸が外向（>+0.3）
  ├ 判断基準 < -0.3（感情重視）           → 炎
  ├ 判断基準 -0.3〜+0.3（中間）           → 風
  └ 判断基準 > +0.3（論理重視）
      ├ 処理スタイル < 0（直感寄り）       → 雷
      └ 処理スタイル >= 0（分析寄り）      → 光

エネルギー軸が内向（<-0.3）
  ├ 判断基準 < -0.3（感情重視）           → 水
  ├ 判断基準 -0.3〜+0.3（中間）           → 土
  └ 判断基準 > +0.3（論理重視）
      ├ 処理スタイル < 0（直感寄り）       → 氷
      └ 処理スタイル >= 0（分析寄り）      → 闇
```

### Step 2：役割の決定（元素ごとに使う軸が異なる）

| 元素 | 役割判定に使う軸 | 条件 | タイプ名 |
|------|--------------|------|---------|
| 炎 | 関わり方 | < 0（独立） | 独り燃える炎タイプ |
| 炎 | 関わり方 | >= 0（協調） | 場を沸かす炎タイプ |
| 風 | 行動スタイル | < 0（自由） | 自在に舞う風タイプ |
| 風 | 行動スタイル | >= 0（計画） | 目的へ吹く風タイプ |
| 雷 | 関わり方 | < 0（独立） | 単独で閃く雷タイプ |
| 雷 | 関わり方 | >= 0（協調） | 場を揺らす雷タイプ |
| 光 | 行動スタイル | >= 0（計画） | 道を照らす光タイプ |
| 光 | 行動スタイル | < 0（自由） | 先を駆ける光タイプ |
| 水 | 行動スタイル | < 0（自由） | 形を変える水タイプ |
| 水 | 行動スタイル | >= 0（計画） | 深く湛える水タイプ |
| 土 | 関わり方 | >= 0（協調） | 静かに支える土タイプ |
| 土 | 関わり方 | < 0（独立） | 独り立つ土タイプ |
| 氷 | 関わり方 | < 0（独立） | 研ぎ澄ます氷タイプ |
| 氷 | 関わり方 | >= 0（協調） | 凛として守る氷タイプ |
| 闇 | 行動スタイル | < 0（自由） | 深く問い続ける闇タイプ |
| 闇 | 行動スタイル | >= 0（計画） | 先を読む闇タイプ |
| 無 | 関わり方 | >= 0（協調） | 全てに溶け込む無タイプ |
| 無 | 関わり方 | < 0（独立） | 何にも染まらぬ無タイプ |

## バッジ診断

### バッジ

| 軸 | 第1弾 | 第2弾 |
|---|---|---|
| エネルギー `energy` | つながりバッジ | 共鳴バッジ |
| 判断 `judgment` | こころバッジ | 心核バッジ |
| 処理 `processing` | ひらめきバッジ | 洞察バッジ |
| 関わり方 `relationship` | きずなバッジ | 信頼バッジ |
| 行動 `lifestyle` | あゆみバッジ | 道標バッジ |

- 1つのバッジは「枠」2つでできている（例 `r1_energy_a` / `r1_energy_b`）。2枠とも採点できたらバッジを取得
- 第1弾がそろうまで第2弾は出さない
- バッジの定義は Functions の `src/personality/badgeQuestions.js` と Flutter の `lib/core/constants/badges.dart` で揃えている

### 質問

5軸 × 第1弾・第2弾 × 各10問 ＝ 100問（`badgeQuestions.js`。一覧は `バッジ質問一覧.md`）。第1弾は日常の身近な場面、第2弾は価値観や葛藤に触れる場面。どちらの答えでも材料になるよう、両方向を示す聞き方にしている。

**選び方**（`badgeState.js` の `planQuestion`）:
- 枠ごとに、その軸・その弾の10問から、その人にまだ出していない質問をランダムに選ぶ。同じバッジのもう一方の枠と同じ質問は避ける。出し切ったら一番前に出した質問から再利用する
- 出したのに答えが確定しなかった質問は、同じ質問を「この前の質問、もう一度聞いてもいい？」と前置きして出し直す
- 答え直しの途中なら、先にそれを終わらせる
- 続けて出すときは、なるべく直前と別のバッジから選ぶ

### 質問を出す場所

| 場所 | 内容 |
|---|---|
| ホームの最初の話題 | 優先順位は「記憶 → **未回答のバッジ質問** → 前回の問い → 日替わり」（[チャット機能仕様書](チャット機能仕様書.md#チャットオープナー)）。全部答えた人には、最後に答えてから180日たったバッジの答え直しを「久しぶりに聞いてもいい？」と前置きして出す |
| バッジ一覧から選ぶ | ホーム・キャラクター詳細のバッジのカード、自分会議のロック画面のボタンから開く。選んだら「〇〇バッジの質問に話題を変えます」の確認ダイアログを出してから質問する。取得済みのバッジは答え直しになる |
| 回答のあと続けて | 採点できて話が落ち着いたら、キャラクターが締めの返答に続けて次の質問を出す（「ねえ、もう一つ聞いてみたいんだけど…」） |

### 質問中の会話

回答を受け取ってすぐ次の質問へ行かない。回答に反応して深掘りし、話が落ち着いてから次へ進む。

1回のユーザー発言ごとに、`generateCharacterReply` が**返答を作る前に採点する**（`badgeScoring.js` の `scoreBadgeConversation`、gpt-4o-mini）。採点には質問からのやり取り全体を渡す。結果を返答の指示に使う。

| 採点の結果 | 返答（`templates.js` の `buildBadgeInstruction`） |
|---|---|
| まだ採点できない・3往復目まで | 回答に具体的に反応して共感し、場面・理由・その後のどれか1つだけ聞いて深掘りする |
| まだ採点できない・4往復目以降／採点済みで話が続いている | 普通に会話を続ける。深掘りの質問を重ねない |
| 採点済みで話が落ち着いた | 短く共感し、お礼で締める（質問しない）。アプリが続けて次の質問を出す |
| ユーザーが別の話題を始めた | 通常の返答（回答中を終える） |

共通の指示: 性格の言い当てや評価をしない／診断・バッジ・採点に触れない／自分から別の質問や話題を出さない。回答中はフェーズ別の指示（Phase 2・3の性格の仮説・洞察）を使わない。

**採点の出力**:

```json
{"score": -2, "sub": {"processing": -1}, "scoreReady": true, "windingDown": false, "topicChanged": false}
```

| 項目 | 意味 |
|---|---|
| `score` | 質問の軸の点数（-2〜+2）。質問に答えていなければ `null` |
| `scoreReady` | 具体的な場面や理由つきで傾向を読み取れたか。**ユーザーの1回目の発言では必ず false**（最低1回は深掘りする） |
| `windingDown` | 返事が相づちや締めの言葉になり、話を広げていないか |
| `topicChanged` | 質問と関係のない話を始めたか |
| `sub` | ほかの軸もはっきり読み取れたときだけの点数（保存のみ） |

**中間（0）と判定できない（null）の分け方**: まず質問の場面について本人の好み・行動・気持ちが書かれているかを見る。書かれていなければ `null`（「うん」「わからん」、関係のない話、「場合による」だけで中身がない）。書かれていて、両方を同じくらい挙げた・どちらにも強い好みがないと中身を添えて答えたなら `0`。`0` は取得になる。

**回答中の終わり方**:
- `scoreReady` が初めて true になった発言で点数を保存する（バッジの表示が更新される）
- 採点済みかつ `windingDown` → 締めて次の質問へ
- `topicChanged` → 回答中を終える。採点できていなければ質問は回答待ちに戻る
- ユーザーの発言5回で採点をやめる。採点できていなければ何も言わずに回答待ちに戻し、会話はそのまま続ける（話題を切らない）
- 最後のやり取りから6時間たった回答中の状態は終わったものとして扱う

回答中は「うん」などの短い返事も締めの判断に使うため、無意味な入力の定型返答より先に採点する。

### 答え直し

- 取得済みのバッジを選ぶと、そのバッジの2枠にまだ出していない質問を出す
- 2問とも採点できたら、2枠をまとめて新しい回答に置き換えて計算し直す。1問だけで止まったら前の回答のまま（続きから答えられる）
- 成長段階は下がらない

### 状態の保存先

`users/{uid}/personalityBadges/current`（[Firestoreスキーマ](#firestoreスキーマ新規追加分)）。書き込みは Cloud Function だけ。回答の本文は回答中だけ `active.turns` に持ち、回答中が終わったら消える。保存するのは点数と日時だけ。

| 変化通知フラグ | 軸スコア計算時（タイプが変化した場合のみ） | なし | `pendingTypeChangeNotification` フラグをセット（FCM送信は将来実装） |

> **初回にタイプ変化通知は出ない**: 変化通知の条件は `typeChanged && prevElement !== undefined`（`axisCalculator.js`）。初めて `element` がセットされる回は `prevElement` が未定義で通知条件を満たさない。初回に性格が確定したことを伝えるのは `pendingFirstDreamSelection` を使った夢選択ダイアログの役割。
>
> **元素を持っている人が第1弾をそろえたとき**: 過去の元素に関係なく、バッジの回答だけで計算し直す。元素やタイプが変われば通常の「タイプ変化」として扱う（進化ダイアログ・性格履歴・相性診断の stale 化・キャラクター詳細の再生成）。
>
> **第2弾がそろったときも計算し直す**: 20問で計算し直し、`growthStage` を2にする。タイプ・性格キーが変わったときだけキャラクター詳細を作り直す。

### 性格キーの変化による再生成（ヒステリシス付き）

タイプ名も元素も変わらないまま Big5スコアだけが動くと、`personalityKey` と実際のスコアがずれて、口癖・長所・夢の候補が古い性格のまま残る。これを防ぐため、タイプ変化に加えて **性格キーがはっきり変わったとき** も再生成する（`axisCalculator.js`）。

判定は `const/generatePersonalityKey.js` の `hasDecisiveKeyChange()` が行う。

| 条件 | 再生成 |
|------|-------|
| 丸め値が変わり、丸め境界（x.5）から `KEY_CHANGE_MARGIN`（0.15）以上離れている | する |
| 丸め値は変わるが、境界から0.15未満（例 3.49 ↔ 3.60 の往復） | しない |
| 2段階以上動いた（例 3 → 1） | する |
| 性別が変わった | する |
| `personalityKey` が未設定・旧形式で解釈できない | する |

**ヒステリシスを入れる理由**: 答え直しでスコアが少し動いただけで、境界付近では 3.49 と 3.51 を往復するだけで丸め値が 3↔4 と変わり、そのたびに属性と夢の候補が作り直されてしまう。境界から一定以上離れて初めて変化と認める。

`parsePersonalityKey()` は接頭辞で解釈するため、並び順が違う旧形式（`O3_C3_A3_E3_N3`）や、丸めずに保存された小数キー（`O4.77…_C2.46…_男性`）も読める。

再生成時はフレンドとの相性診断も `isStale` にする（相性はBig5スコアから算出しているため）。

### 既存ユーザーへのバックフィル（2026-08-14 実施）

夢を5候補から選ぶ方式（2026-08-05）より前に性格が確定したユーザーは、`dream/current` が作られず候補を持たないため、詳細画面の「変更」ボタンが出ず夢を選び直せなかった。該当した10人に対して `generateCharacterDetails` を1回ずつ実行し、以下を是正した。

- 夢の候補5個を配布（既存の夢は上書きせず、`pendingDreamProposal` で提案）
- `personalityKey` を現在のスコアで再計算（小数キー5件・スコアとずれていた3件を是正）
- 口癖・長所などの属性を現在の性格で更新
- 新しいキーの `Big5Analysis` を8件生成（アプリはFirestoreを読むだけで自動生成しないため）

AIコールは キャラクター詳細10回 ＋ Big5解析8回 の計18回。以後は上記のキー変化判定により、同じ取りこぼしは起きない。

### 既存キャラの口癖バックフィル（2026-08-22 実施）

口癖に生成条件が無かった頃に作られた値が、相手への相づち（`「面白いね！」`）・単語だけ（`安定`）・鉤括弧込みで残っていた。一回限りのスクリプトで **73キャラ / 60性格キー** の `favorite_word` だけを新条件で作り直した。

- 性格キーごとに1回だけAIを呼び、同じキーのキャラと `CharacterDetailsTemplate/{personalityKey}.attributes.favorite_word` に反映
- 既存の口癖を種として渡し、雰囲気を保ったまま独白でも使える形に直す（`「面白いね！」` → `これは面白い展開だ`）
- **口癖以外の属性と夢には触らない**。夢を更新しないため `pendingDreamProposal`（夢の再提案）は立たない

## キャラクター属性（得意・好き／苦手・注意）

性格キー（BIG5 を四捨五入した5値＋性別）から、自己理解に役立つ属性を作る。バッジ診断の回答 → 5軸 → BIG5 → 属性、の流れで作られ、本人の発言を直接読むわけではない。同じ性格キーのユーザーは同じ内容になる（`CharacterDetailsTemplate` で共有）。

### 項目

キーは `src/utils/characterTraits.js` の `TRAIT_LABELS` と、Flutter の `lib/core/constants/character_traits.dart` の `kCharacterTraits` で揃えている。

| タブ | キー | 表示名 |
|---|---|---|
| 得意・好き | `favorite_color` / `favorite_place` / `favorite_word` / `word_tendency` / `strength` / `skill` / `hobby` / `aptitude` / `energizer` | 好きな色 / 好きな場所 / 口癖 / 話し方の特徴 / 長所 / 特技 / 趣味 / 適性 / 元気が出ること |
| 苦手・注意 | `uneasy_place` / `trigger_word` / `disliked_approach` / `weakness` / `weak_task` / `uninterested` / `unsuited_environment` / `feared_self` / `dislike` / `stress_trigger` | 落ち着かない場所 / 言われるとモヤっとする言葉 / 苦手な接し方 / 短所 / 苦手な作業 / 興味が湧きにくいこと / 向いていない環境・役割 / なりたくない自分 / 嫌いなこと / ストレスを感じる瞬間 |

- `favorite_entertainment_genre`（好きな娯楽ジャンル）も作るが、画面には出さず理由も持たない
- 夢は得意・好きタブの最後に出す（保存先は `dream/current`。[夢の選択フロー](#夢の選択フロー)）

### 理由

各項目に「なぜそうなのか」を1文（30文字以内）で付け、`<キー>_reason`（例: `strength_reason`）に保存する。夢は AI が作った候補5個にだけ理由がある。

### 生成ルール（`templates.js` の `characterDetails`）

- 項目ごとに `{"value","reason"}` で返させ、`generateCharacterDetails.js` の `pickAttributes()` が `strength` と `strength_reason` に平らにする（読み取り側は従来どおり `strength` を読める）。`response_format: json_object` を指定
- value は20文字以内（口癖は12文字以内）。**抽象語だけの値は不可**で、具体的な行動・場面・物で書く
- reason は「その人が何を大事にしているか・どう感じるか」で書き、**性格用語（外向的・几帳面・協調性など）を使わない**。性格用語の言い換えだと自己理解に役立たないため
- 苦手・注意の項目は人格を否定せず「〜な場面」「〜なこと」で書く
- 言われるとモヤっとする言葉は口癖と同じく、保存時に外側の鉤括弧を取り除く
- 生成1回あたり入力約1,100トークン・出力約720トークン（2026-10-02 に本番モデルで4パターン実測。出力は性格により約700〜1,040）

### テンプレートの補完

`fetchOrCreateTemplate()` は、テンプレートが今の項目（`ADDED_TRAIT_KEYS`・長所の理由・`dream_reasons`）を揃えているかを確かめ、足りなければ作り直す。その際、既存の値（口癖・長所・夢の候補など）は**そのまま維持**し、理由と足りない項目だけを作る（プロンプトに既存の値を渡し、さらに保存時にも既存の値で上書きする）。ユーザーが見慣れた内容が急に変わらないようにするため。

### プライバシー

属性は `details/current` に置く（ログインしている人なら誰でも読める。フレンドのアバター表示のため）。性格タイプから決まる一般的な内容でユーザーの自由入力を含まないため、従来の「短所」と同じ扱いにしている。自由入力がありうる夢とその理由は本人限定の `dream/current` に置く。

### 各機能への渡し方

渡すのは**値だけ**（理由は渡さない）。「今の話題に直接関係するときだけ踏まえる。関係なければ触れない。項目名や文言をそのまま言わない。苦手・嫌いなことを勧めない」を同じブロックに書く（`buildTraitReferenceBlock`）。

| 機能 | 渡す項目 | 備考 |
|---|---|---|
| チャット（`characterReply`） | 趣味・元気が出ること・嫌いなこと・苦手な接し方・ストレスを感じる瞬間（＋既存の夢） | [チャット機能仕様書](チャット機能仕様書.md) |
| 日記（`activityDiary`） | 元気が出ること・嫌いなこと・苦手な接し方・ストレスを感じる瞬間（＋既存の口癖・話し方・長所・夢） | 苦手なことに取り組んだ日は頑張りを認める |
| 自分会議（`createMeetingPrompt`） | 夢・長所・元気が出ること・短所・嫌いなこと・ストレスを感じる瞬間・なりたくない自分 | 「今の自分の自己像」として渡し、主に今の自分・本音が使う。ほかの人格が触れるときは今のあなたのこととして扱わせる。夢は仕事・将来・生き方の悩みのときだけ |
| フレンドに聞く（`askAboutFriend`） | 相手の 趣味・好きな場所・元気が出ること・言われるとモヤっとする言葉・苦手な接し方・嫌いなこと・興味が湧きにくいこと | 相手の詳細画面の内容と提案が食い違わないようにするため |

**検証（2026-10-02）**: 本番と同じモデルで、チャットは無関係な発言20件で項目に触れた回数0件、関係ある発言10件で自然に踏まえることを確認。日記・フレンドに聞く（無関係な質問で0件）・自分会議（運動・買い物の悩みで夢を持ち出さない）も同様に確認した。

## キャラクター画像との連携

5軸スコアをBIG5スコアに変換して既存の画像システムを継続使用する。新しい画像生成は不要。

```
Extraversion(E)      = (エネルギー軸 + 1.0) / 2.0 × 4.0 + 1.0
Conscientiousness(C) = (行動スタイル軸 + 1.0) / 2.0 × 4.0 + 1.0
Agreeableness(A)     = (関わり方軸 + 1.0) / 2.0 × 4.0 + 1.0
Openness(O)          = (-処理スタイル軸 + 1.0) / 2.0 × 4.0 + 1.0  ※反転
Neuroticism(N)       = (-判断基準軸 + 1.0) / 2.0 × 4.0 + 1.0      ※反転

結果はすべて 1.0〜5.0 に収まり、既存のL/M/H変換に渡せる
```

変換結果は `details/current.convertedBig5Scores` に保存。

**画像変更のタイミング:**

| 成長段階（`users/{uid}.growthStage`） | 条件 | 画像 |
|---|---|---|
| 0 | 第1弾がそろう前 | 赤ちゃん |
| 1 | 第1弾がそろった | 幼少期_{element} |
| 2 | 第2弾もそろった | 成人_{gender}_{element} |

- 画像は `growthStage < 1 || element == null` の間は赤ちゃん固定
- 答え直しで element が変わったら、Flutter がリアルタイムに画像を更新する
- 成長段階は下がらない（`max(今の値, バッジから決まる値)` で保存する）

## 変動の安定性

性格が変わるのは、第1弾・第2弾がそろったときと、答え直しが終わったときだけ。雑談を続けても変わらない。

## generateCharacterReply への5軸反映

`generateCharacterReply` はキャラクター返答生成時に性格特性テキストをプロンプトに渡す。  
`axisScores` が存在する場合は `buildPersonalityTraitsFromAxes()` で生成した5軸ベーステキストを優先使用し、存在しない場合は旧来の `buildPersonalityTraits(big5)` にフォールバックする。

```javascript
// templates.js
function buildPersonalityTraitsFromAxes(axisScores, element, typeName) {
  // 各軸の値からフレーズを選択・連結
  // 例: energy>0.3 → "外向的で人との交流から活力を得る"
  // 例: judgment<-0.3 → "感情や直感を重視して判断する"
  // typeName が存在する場合: "場を沸かす炎タイプ。外向的で..." の形で先頭に付与
}
```

### フェーズ別チャット返答との連携

成長段階（`growthStage`）に応じて、返答の深度（フェーズ）を切り替える。

| 成長段階 | 返答フェーズ | 性格反映 |
|------------|------------|---------|
| 0（元素が決まる前） | Phase 1 固定 | **なし**（性格データがないため誤言及を防ぐ） |
| 1以上（元素確定済み） | session turn に応じて P1〜P3 | **あり** |

- **Phase 2**（成長段階1以上の session turn 2〜4）: 性格特性を「仮説」として提示
- **Phase 3**（成長段階1以上かつ session turn 5〜）: 性格を言語化して説明。`typeName`（「炎タイプ」等）を自然に使う
- バッジの質問に答えている間はフェーズの指示を使わず、[質問中の会話](#質問中の会話)の指示にする
- フェーズはFlutter側（`home_screen.dart` の `_calcPhase`）で算出し、`phase` パラメータで Cloud Function に渡す
- `sessionChatCountProvider`（`chat_provider.dart`）でセッション内ターンを管理。アプリ起動時と性格リセット時に 0 にリセット

## 週次ナラティブ生成（Cloud Scheduler）

毎週日曜9:00 JSTに全アクティブユーザーの性格ナラティブを再生成する。

- **対象**: `element` フィールドが存在するユーザー
- **取得**: `collectionGroup('details').where('element', 'in', VALID_ELEMENTS)`
- **生成**: `「最近〜な傾向があります」`形式の100〜150文字テキスト（gpt-4o-mini）
- **保存先**: `details/current.personalityNarrative`・`narrativeUpdatedAt`
- **変化検知**: `element` または `typeName` が前回と異なる場合、`personalityMeta/current.pendingTypeChangeNotification = true` をセット

1. Cloud Function (`diagnoseFromAxisScores`) が element/typeName の変化を検知 → `pendingTypeChangeNotification: true`、`newElement`・`newTypeName` をセット
2. Flutter がリアルタイムで検知 → ダイアログ表示
3. ユーザーが「確認する」ボタンをタップ → `pendingTypeChangeNotification: false` に更新してフラグクリア

**重複表示防止**: `_isShowingEvolutionDialog` フラグで同時に複数ダイアログが表示されないよう制御

**夢の提案セクション**: 性格タイプが変わって夢の候補が作り直された場合（`dream/current.pendingDreamProposal == true`）、ダイアログ内に現在の夢と「このまま」「候補を見る」を表示する。**現在の夢は自動で差し替えない。** 「確認する」で閉じたときもフラグを下ろす（このダイアログは性格変化時にしか出ないため、残すと再表示の機会がない）。

## 夢の選択フロー

キャラクターの夢は、性格から生成した5個の候補からユーザーが選ぶ。1個だけを提示すると「それはやりたくない」となった際に離脱の原因になるため。既に叶えたい夢がある人のために自由入力欄も用意する。

### データの持ち方

| 場所 | フィールド | 内容 |
|------|-----------|------|
| `CharacterDetailsTemplate/{personalityKey}` | `dreams` | AIが生成した候補5個（同じ性格の全ユーザーで共有） |
| 同上 | `dream_reasons` | 候補ごとの理由（`dreams` と同じ並び） |
| `users/{uid}/characters/{cid}/dream/current` | `dreamOptions` | そのユーザーに提示中の候補5個 |
| 同上 | `dream` | 現在採用中の夢（1個） |
| 同上 | `dreamSource` | `user`（ユーザーが選択・入力）/ `ai`（暫定採用） |
| 同上 | `pendingDreamProposal` | 新しい候補ができたことを示すフラグ |
| 同上 | `dreamOptionReasons` | 候補ごとの理由（`dreamOptions` と同じ並び） |

**`details/current` には夢を置かない。** `details` は firestore.rules で認証済みユーザーの単体取得が許可されており（フレンドのアバター表示用）、自由入力を含む夢が他ユーザーから読めてしまうため。

### 生成と上書きのルール

- 候補は `generateCharacterDetails` が `dreamOptions` に保存する（`src/utils/dreamStore.js` の `saveDreamOptions`）
- **`dream` は再生成で上書きしない。** ユーザーが選んだ夢が性格変化で勝手に消えないようにするため
- 既存ユーザーの `details/current.dream` は、初回の候補保存時に `dream/current` へ移行する（`dreamSource: 'ai'`）。読み取り側（`generateCharacterReply` / `generateDiary`）は未移行ユーザーのために `details.dream` へフォールバックする

### 選択の導線

| タイミング | 画面 | 挙動 |
|-----------|------|------|
| 初回（第1弾のバッジがそろって初めて診断したとき） | ホーム画面のダイアログ | `pendingFirstDreamSelection` を検知して「性格が決まりました」＋夢選択を表示。「あとで選ぶ」を押した場合は候補1個目を暫定採用（`dreamSource: 'ai'`）し、チャットが「夢はまだ決まっていません」に切り替わるのを防ぐ |
| 性格タイプ変化時 | 進化ダイアログ内 | `pendingDreamProposal` を検知して提案。現在の夢は維持 |
| 性格キー変化時・既存ユーザーへの配布時 | ホーム画面のポップアップ | `pendingDreamProposal` を検知して単独のダイアログを表示。進化ダイアログはタイプ名が変わったときしか開かないため、それ以外の経路を拾う |
| いつでも | キャラクター詳細画面の「夢」欄 | 「変更」ボタンから選び直せる |

**ポップアップと進化ダイアログは重ねない**: 進化ダイアログ・初回選択ダイアログの表示中はポップアップを抑制し、進化ダイアログを閉じるときに `pendingDreamProposal` が下りるため二重には出ない。

**選択シートから戻れる**: シート左上の戻るボタン（または下スワイプ）で閉じると、呼び出し元のポップアップへ戻り「このまま」を選び直せる。夢を保存したときだけ完了する。詳細画面から開いた場合は、閉じると何も起きない。

**シートの見た目**: 背景はホーム画面と同じ `backgroundGradientProvider` のグラデーションを使い、背景の明度から文字色（濃いグレー／白）を決める。タイトルは中央揃え。「自分で入力する」の初期値には現在の夢が入る（候補に含まれているかどうかに関わらず）。

### 入力のサニタイズ

夢はチャット（`characterReply`）と日記（`activityDiary`）のシステムプロンプトに `夢: ○○` の形で埋め込まれるため、プロンプトインジェクションの経路になりうる。クライアント（`DreamService.sanitize`）とCloud Functions（`sanitizeDream`）の両方で以下を適用する。

- 制御文字（改行・タブを含む）を空白に置換し、連続する空白を1つにまとめる
- **40文字**で切り詰める（サロゲートペアを割らないようコードポイント単位）
- 空文字は保存しない

| 層 | ファイル |
|----|---------|
| Cloud Functions | `src/utils/dreamStore.js`（保存・取得・サニタイズ）、`const/generateCharacterDetails.js`（候補生成）、`src/personality/axisCalculator.js`（初回フラグ・キー変化での再生成）、`const/generatePersonalityKey.js`（キー生成・変化判定） |
| Flutter | `presentation/providers/dream_provider.dart`（状態・保存）、`presentation/widgets/dream_select_sheet.dart`（選択シート）、`screens/home/home_screen.dart`（初回ダイアログ・進化ダイアログ内の提案・新候補のポップアップ）、`screens/character/character_detail_screen.dart`（`_DreamRow`） |

## キャラクター成長システム

### 概要

成長段階（`users/{uid}.growthStage`。0=赤ちゃん 1=幼少期 2=大人）に連動してキャラクターが3段階に成長する。第1弾のバッジがそろうと1、第2弾もそろうと2になる（`axisCalculator.js` が保存。下がらない）。成長段階ごとにローカルアセット画像を切り替え、元素確定（成長段階1以上）後は属性別エフェクトを表示する。

### 成長段階と画像アセット

| ステージ | growthStage | ファイル | 備考 |
|---------|------------|---------|------|
| 赤ちゃん | 0 | `assets/images/character_growth/赤ちゃん.png` | 全ユーザー共通 |
| 幼少期 | 1 | `assets/images/character_growth/幼少期_{元素}.png` | 9元素 × 1枚 |
| 大人 | 2 | `assets/images/character_growth/成人_{性別}_{元素}.png` | 2性別 × 9元素 = 18枚 |

アセット合計: 1 + 9 + 18 = **28枚**

### パス生成関数（`characterGrowthAssetPath`）

`lib/presentation/widgets/character/element_effect_widget.dart` に定義。

```dart
String characterGrowthAssetPath({
  required int growthStage,
  required String? element,
  required String? gender,
}) {
  if (growthStage < 1 || element == null) return '赤ちゃん.png';
  if (growthStage < 2) return '幼少期_$element.png';
  final g = gender == '男性' ? '男性' : '女性';
  return '成人_${g}_$element.png';
}
```

### 元素エフェクト（`ElementEffectWidget`）

成長段階1以上（元素確定後）に、キャラクター画像の背後に属性別アニメーションエフェクトを表示する。

- **表示画面**: ホーム画面・キャラクター詳細画面

### キャラクターアバター（`CharacterAvatarWidget`）

設定画面アカウントカード・フレンド一覧・フレンド検索で使用する丸アバター。

- **表示方式**: `ClipOval` + `OverflowBox(maxHeight: size * 1.8, alignment: Alignment.topCenter)` で1.8倍ズームして上部（顔部分）をトリミング表示
- **自分のアバター**: `growthStageProvider` + `characterDetailsProvider` をリアルタイム購読
- **フレンドアバター**: `userCharacterDetailsProvider(userId)` から `growthStage` と `element` を取得し段階を決定
- **フォールバック**: `growthStage == 0` かつ `element != null` → 幼少期として扱う（growthStage 書き込み前の既存ユーザー向け）

## Firestoreスキーマ（新規追加分）

### `users/{userId}/personalityBadges/current`

バッジ診断の状態。書き込みは Cloud Function（Admin SDK）だけ。本人は読み取りと削除（性格のリセット）だけできる（`firestore.rules`）。

```json
{
  "slots": {
    "r1_energy_a": {"questionId": "r1_energy_03", "axis": "energy", "round": 1, "score": -2, "sub": {"processing": -1}, "answeredAt": 1759800000000}
  },
  "assigned": {
    "r1_judgment_a": {"questionId": "r1_judgment_07", "askedAt": 1759800000000, "askCount": 1}
  },
  "askedQuestionIds": ["r1_energy_03", "r1_judgment_07"],
  "retake": {"badge": "r1_energy", "answers": {}},
  "active": {
    "slotKey": "r1_judgment_a", "questionId": "r1_judgment_07", "isRetake": false,
    "startedAt": 1759800000000, "updatedAt": 1759800000000,
    "turns": [{"u": "ユーザーの発言", "a": "キャラクターの返答"}],
    "scored": false
  },
  "round1CompletedAt": null,
  "round2CompletedAt": null
}
```

| フィールド | 内容 |
|---|---|
| `slots` | 採点できた回答（枠ごと）。点数と日時だけで、回答の本文は持たない |
| `assigned` | 出したが答えが確定していない質問。`askCount` が1以上なら次は前置きを付けて出し直す。答え直しの分はキー先頭に `retake_` が付く |
| `askedQuestionIds` | 出した質問の順番（次に選ぶときに避ける・出し切ったら古い順に再利用） |
| `retake` | 答え直し中のバッジと、答え直しで答えた回答。2枠そろったら `slots` を置き換えて `null` に戻る |
| `active` | 回答中の質問と、その間のやり取り。回答中が終わると `null` になり、やり取りの本文も消える |
| `round1CompletedAt` / `round2CompletedAt` | 各弾が初めてそろった日時（ミリ秒） |

日時はすべてミリ秒の数値で持つ。

### `users/{userId}/personalityMeta/current`

```json
{
  "pendingTypeChangeNotification": false,
  "pendingFirstDreamSelection": false
}
```

- タイプ変化の通知・初回の夢選択のフラグを持つ
- 回数制の頃に作られた `signalCount` と `users/{userId}/personalitySignals` は既存ユーザーの文書に残っているが、書き込みも読み取りもしない

### `users/{userId}/characters/{charId}/details/current`（既存ドキュメントへの追加フィールド）

```json
{
  "axisScores": {
    "energy":       0.4,
    "judgment":    -0.3,
    "relationship": 0.2,
    "lifestyle":    0.1,
    "processing":  -0.2
  },
  "element":    "炎",
  "typeName":   "場を沸かす炎タイプ",
  "convertedBig5Scores": {
    "openness": 2.8,
    "conscientiousness": 3.4,
    "extraversion": 3.8,
    "agreeableness": 3.6,
    "neuroticism": 2.1
  },
  "personalityNarrative": "最近、周りを巻き込む行動が目立っています",
  "axisUpdatedAt":      "Timestamp",
  "axisGeneratedAt":    "Timestamp",
  "narrativeUpdatedAt": "Timestamp"
}
```

- `axisGeneratedAt`: null なら初めて診断したときに `generateCharacterDetails` を実行・保存。初回生成を1回に限るためのフラグ
- キャラクター属性（得意・好き9項目・苦手・注意10項目・`favorite_entertainment_genre`）と各項目の理由 `<キー>_reason` は `CharacterDetailsTemplate/{personalityKey}` からコピーされる（[キャラクター属性](#キャラクター属性得意好き苦手注意)）。チャット・日記の参照先を変えないため、共有テンプレートを直接読ませずここに複製している
- `favorite_word`（口癖）は生成時に条件を課す: **12文字以内 / 独り言としても会話の中でも自然に使える言い切りの形 / 相手への相づち（`面白いね！`）や単語だけ（`安定`）は不可 / 性格に合ったトーン（外向的なら前向き、内省的なら落ち着いた言葉） / 迷い・不安の調子は神経症傾向が高いときだけ / 鉤括弧・引用符を含めない**。日記の ai_comment はキャラクターの独白なので、会話相手がいないと成立しない言葉だと文脈に合わなくなるため。保存時にも `pickAttributes()`（`generateCharacterDetails.js`）で外側の鉤括弧・引用符を取り除く
- **`dream` は含まない**（本人限定の `dream/current` に置く。既存ユーザーの残存値は移行後もフォールバック用に残る）
- 既存フィールド（`confirmedBig5Scores`・`analysisLevel` 等）はそのまま残存（既存ユーザーの後方互換）

### `users/{userId}/characters/{charId}/dream/current`（新規）

```json
{
  "dream":                 "世界中を旅して回ること",
  "dreamOptions":          ["夢1", "夢2", "夢3", "夢4", "夢5"],
  "dreamOptionReasons":    ["理由1", "理由2", "理由3", "理由4", "理由5"],

```

`details` と違い全体公開の例外ルールが無いため、`users/{userId}/{subcollection=**}` の本人限定ルールが適用される。

### `CharacterDetailsTemplate/{personalityKey}`（新規・トップレベル）

```json
{
  "personality_key": "O3_C4_E2_A5_N1_female",
  "attributes":      {"favorite_color": "...", "favorite_color_reason": "...", "dislike": "...", "dislike_reason": "...", "...": "..."},
  "dreams":          ["夢1", "夢2", "夢3", "夢4", "夢5"],
```

### `users/{userId}/characters/{charId}/big5Progress/current`（既存・後方互換）

旧BIG5 100問診断の進捗。新規ユーザーは使用しない。既存ユーザーのデータとして残存。

## `analysisLevel` フィールドの扱い

BIG5 100問診断廃止に伴い、`analysisLevel` フィールドは新システムでは使用しない。

| ユーザー種別 | 状態 |
|------------|------|

Flutter の表示ロジックは `analysisLevel` への依存を除去し、代わりに `element` の有無で判定する。
