# 性格項目の拡張（苦手・注意タブと理由）設計書

**作成日**: 2026-10-02
**状態**: 設計（未実装）。実装が終わった部分から `性格解析仕様書.md` などの仕様書へ反映する

## 目的

性格解析の結果に「嫌いなこと・苦手なこと・興味が湧きにくいこと」などのネガティブな面を加え、すべての項目に「なぜそうなのか」の理由を付ける。得意なことと苦手なことを並べて見られるようにして、自己理解を深める。同じ項目をチャット・日記・自分会議・フレンドに聞く機能にも渡し、会話や提案の精度を上げる。

## 前提（今の作り）

| 段階 | 処理 | ファイル |
|---|---|---|
| 1 | チャットの発言から性格タグを取る | `const/classifyAndExtract.js` |
| 2 | タグを積み上げて5軸スコアと BIG5 を計算する（10シグナルごと） | `src/personality/axisCalculator.js` |
| 3 | BIG5（四捨五入）＋性別から、口癖・長所・夢などを AI が一度にまとめて作る | `const/generateCharacterDetails.js`・`templates.js` の `characterDetails` |

3 の結果は性格キー（`personalityKey`）ごとに `CharacterDetailsTemplate/{personalityKey}` へ保存し、同じキーのユーザーで使い回す。**今回の項目もこの3に足す**ので、作り方・タイミング・使い回しの仕組みは変わらない。

## 理由

- すべての表示項目に理由を1文で付ける。保存は値と別のフィールド `<キー>_reason`（例: `strength_reason`）
- **30文字以内・1文**。「〜から」「〜ため」で終える
- 夢は AI が作った候補5個にだけ理由を付ける（ユーザーが自分で入力した夢には付かない）

## 生成プロンプトの変更（`templates.js` の `characterDetails`）

- 出力を項目ごとに `{"value":"…","reason":"…"}` の入れ子にする。保存時に `pickAttributes()` が `strength` と `strength_reason` に平らにする（既存の読み取り側が `strength` をそのまま読めるようにするため）
- 夢は `"dreams":[{"value":"…","reason":"…"} × 5]`
- **具体性のルール**: 「人間関係」「仕事」のような抽象語だけの値は不可。具体的な行動・場面・物で書く。例を添える
- 値は20文字以内（口癖は今のルールどおり12文字以内）
- ネガティブ項目は人格を否定する書き方をしない（「〜な人間」ではなく「〜な場面」「〜なこと」で書く）
- モデル・呼び出し回数は変えない（`gpt-4o-2024-11-20`・性格キーごとに1回）。出力が増えるぶん、生成時間と出力トークンは増える。実際の増分は実装後にプロンプトと出力を数えて仕様書に書く

## 保存

| 場所 | 追加するもの |
|---|---|
| `CharacterDetailsTemplate/{personalityKey}.attributes` | 新規キー8個（`energizer`〜`stress_trigger`）と、全表示項目の `<キー>_reason` |
| 同 `dream_reasons` | 夢候補5個の理由（`dreams` と同じ並び） |
| `users/{uid}/characters/{cid}/details/current` | `attributes` と同じもの（今と同じくテンプレートからコピー） |
| `users/{uid}/characters/{cid}/dream/current` | `dreamOptionReasons`（`dreamOptions` と同じ並び） |

- `ATTRIBUTE_KEYS`（`generateCharacterDetails.js`）に新規キーを足す
- 性格のリセット（`flutter/lib/data/datasources/remote/big5_datasource.dart`）で消すフィールドに新規キーと `_reason` を足す

### プライバシー

`details/current` はフレンドのアバター表示のため、ログインしている人なら誰でも読める（`firestore.rules`）。新しい項目も**性格タイプから決まる一般的な内容で、ユーザーの自由入力を含まない**ため、今の「短所」と同じ扱いで `details/current` に置く。夢は自由入力があるため本人限定の `dream/current` に置いている（理由も同じ場所に置く）。

## 既存テンプレートの作り直し

保存済みのテンプレートには新しい項目が無い。

1. **自動の補完**: `fetchOrCreateTemplate()` の「テンプレートが揃っているか」の判定に、新規キーと理由が揃っていることを加える。揃っていなければ作り直す（次に性格タイプ・性格キーが変わったときに自然に直る）
2. **一括の作り直し**: 今使われている性格キーのテンプレートを1回ずつ作り直し、同じキーのユーザーの `details/current` と `dream/current.dreamOptionReasons` に反映する。一回限りのスクリプトで行い、終わったら削除する
   - 既存の値（口癖・長所・夢の候補など）は**変えない**。既存の値を入力として渡し、新しい項目と理由だけを作る（2026-08-22 の口癖の作り直しと同じ方式）。ユーザーが見慣れた内容が急に変わるのを防ぐため
   - 選択済みの夢は変えない。`pendingDreamProposal`（夢の再提案）も立てない
   - 対象件数とコストは実行前に数えて、ユーザーの確認を取る

## 詳細画面（`character_detail_screen.dart`）

- 情報エリア（今の `_InfoRow` 一覧）を2つのタブ「**得意・好き**」「**苦手・注意**」に分ける。性格タイプカード・成長ゲージ・人格解析セクションは今のままタブの上に置く
- 各項目はアコーディオンのカードにする
  - 閉じているとき: 表示名＋値（今の `_InfoRow` と同じ見た目）
  - タップで開くと理由を表示。理由が無い項目（作り直し前のデータ）は開けない見た目にする
- 夢の行（`_DreamRow`・「変更」ボタン）は得意・好きタブの最後に置き、理由は選択中の夢が AI の候補にある場合だけ出す
- 値が無い項目は今と同じく表示しない。苦手・注意タブの項目が1つも無いとき（作り直し前のユーザー）は「性格が更新されると表示されます」と出す

## 各機能への反映

渡すのは**項目の値だけ**（理由は渡さない）。プロンプトを伸ばさず、AI が理由をそのまま読み上げるのも防ぐ。得意・好きと苦手・注意の両方を渡し、偏らないようにする（2026-10-02 ユーザー確認）。

| 機能 | 得意・好き（既存＋追加） | 苦手・注意（追加） | ファイル |
|---|---|---|---|
| チャット | 夢（既存）・趣味・元気が出ること | 嫌いなこと・苦手な接し方・ストレスを感じる瞬間 | `const/generateCharacterReply.js`・`templates.js` の `characterReply` |
| 日記 | 口癖・話し方・長所・夢（既存）・元気が出ること | 嫌いなこと・苦手な接し方・ストレスを感じる瞬間 | `const/generateDiary.js`・`templates.js` の `activityDiary` |
| 自分会議 | 夢・長所・元気が出ること | 短所・嫌いなこと・ストレスを感じる瞬間・なりたくない自分 | `src/functions/generateSixPersonMeeting.js`・`src/prompts/sixPersonMeetingTemplates.js` |
| フレンドに聞く（相手の項目） | 趣味・好きな場所・元気が出ること | 言われるとモヤっとする言葉・苦手な接し方・嫌いなこと・興味が湧きにくいこと | `const/askAboutFriend.js` |

自分会議では「今の自分の自己像」として渡し、**主に「今の自分」「本音」が使う**。ほかの人格（真逆・理想・子供の頃・未来）が触れるときは「今のあなたの夢・苦手」として扱わせ、自分自身の好みとして語らせない（真逆の自分などは BIG5 を作り替えた別人格で性格が違うため）。当初は2人格に限定したが、検証で理想の自分が夢に触れることがあり、同じ人の一面として不自然ではないため扱い方の指定に改めた。自分会議は毎回その悩みに合わせて新規生成しており（共有会議の再利用は停止中）、項目を足してもコストの構造は変わらない。

### AI が無理に使わないための対策

1. 参考情報として独立した欄に入れ、使い方を明記する: 「今の話題に直接関係するときだけ使う。関係なければ触れない。項目名や文言をそのまま言わない。苦手なことを勧めない」（今の「覚えていること」と同じ書き方）
2. 渡すのは上の表の項目だけにする
3. **実装後、デプロイ前に本番と同じモデルで試す**（`shared/functions/.env` の OPENAI_API_KEY で直接呼ぶ。キャラクターの記憶のときと同じ方法）
   - 無関係な発言 約20件（例: 「今日カレー食べた」）: 項目に触れた回数が**0件**になるまで指示を直す
   - 関係ある発言 約10件（例: 「明日みんなの前で発表がある」）: 自然に触れられているかを見る
   - 日記・自分会議・フレンドに聞く機能も同じように確かめる
   - 結果は実際の返答例と一緒にユーザーに報告する
