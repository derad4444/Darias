# バッジ診断（回数制から質問バッジ制へ）設計書

**作成日**: 2026-10-07
**状態**: 2026-10-07 実装済み（Functions・Flutter・firestore.rules）。デプロイ・リリースは未実施。現在の仕様は `性格解析仕様書.md` の「バッジ診断」と `チャット機能仕様書.md` を正とする

## 実装で設計から変えたこと

- **採点は独立した関数にせず、`generateCharacterReply` の中で行う**（`badgeStore.js` の `handleAnswer`）。回答中かどうか・やり取りの記録をサーバー側（`personalityBadges/current.active`）で持てるので、アプリから軸ややり取りを送らなくて済み、通信も1往復で済む
- **質問を出す Callable `startBadgeQuestion` を追加した**。質問の選択と「出した」記録をサーバー側で行うため（`personalityBadges` は本人が書き込めない）
- **ホームの吹き出しは1つしかない**ので、締めの返答と次の質問は「返答＋空行＋次の質問」として1つの吹き出しに出す。投稿（`posts`）は別々に保存する
- **性格のリセットのため、`personalityBadges` は本人に削除だけ許可した**（作成・更新は不可）
- **回答中の状態は最後のやり取りから6時間で終わったものとして扱う**（質問は回答待ちに戻る）

## 目的

性格診断の正確さを上げる。今は「性格タグが30件たまったら元素が決まる」方式で、雑談を続けるだけで決まってしまい、結果も特定の元素に偏っている。これを「5つの性格軸ごとに用意した質問に答えてバッジを集めると診断される」方式に変える。

あわせて「質問に答えて元素を見つける」という分かりやすい体験にし、SNSでも伝えやすくする。

## 今の方式の問題（2026-10-07 本番データで確認）

本番の `personalitySignals`（42人・1,163件）を読み取りのみで集計した。

| 問題 | 数値 |
|---|---|
| 元素が偏っている | 30件以上の13人：炎9・水2・無2。風・土・雷・光・氷・闇は0人 |
| 「気持ちを話した」が「感情重視」と数えられる | `emotional_expression` 486件＋`worry_anxiety` 253件に対し、`logical_reasoning`＋`data_driven` は35件 |
| 判断軸と処理軸がほぼ同じ値になる | 相関0.975。タグが両方の軸を同じ向きに動かすため、雷・氷は構造上ほぼ出ない |
| 関わり方の軸の材料が少ない | 中央値5件。13人中5人は3件以下 |
| 回数で決まるため結果が安定しない | 60件以上の4人のうち、30件時点の元素が最終結果と一致したのは2人 |
| 短時間で30件に到達して止まる | 30件以上の人の多くは1日で30件に到達している |

**結論**: 質問を変えるだけでは直らない。タグで測る方式そのものをやめる。

## 方針

1. **診断は「バッジ質問への回答」だけで行う**。普段のチャットは診断に使わない
2. **タグを使わず、回答をAIが軸ごとに直接採点する**（回答採点方式）
3. **測るのは今の5つの軸**。元素・役割の判定ロジックと BIG5 への変換（`convertToBig5`）はそのまま使う
4. **成長段階はバッジで決める**。第1弾がそろったら幼少期（元素確定）、第2弾がそろったら大人
5. **バッジを埋めたら、過去の元素に関係なく回答だけで再診断する**

### タグをやめて回答採点方式にする理由

- 質問ごとに測りたい軸が決まっているので、「その軸のどのあたりか」をAIに直接聞く方が正確になる
- 何を話しても「感情」に寄るという、タグの偏りが起きない
- 判断軸と処理軸を、それぞれ別の質問で測れる（相関の問題が消える）
- 「うん」のような中身のない回答は「判定できない」と返させ、バッジを渡さない

## バッジの構成

| 測る軸 | -側 | +側 | 対応するBIG5 | 第1弾のバッジ（仮） | 第2弾のバッジ（仮） |
|---|---|---|---|---|---|
| エネルギー `energy` | 内向 | 外向 | 外向性 | つながりバッジ | 共鳴バッジ |
| 判断 `judgment` | 感情 | 論理 | 神経症傾向（反転） | こころバッジ | 心核バッジ |
| 処理 `processing` | 直感 | 分析 | 開放性（反転） | ひらめきバッジ | 洞察バッジ |
| 関わり方 `relationship` | 独立 | 協調 | 協調性 | きずなバッジ | 信頼バッジ |
| 行動 `lifestyle` | 自由 | 計画 | 誠実性 | あゆみバッジ | 道標バッジ |

第2弾は第1弾より深く見えるように、第1弾はひらがなのやわらかい言葉、第2弾は漢字の重い言葉にする。

- 第1弾：5バッジ × 各2問 ＝ 10問。全部そろうと元素が決まり、幼少期になる
- 第2弾：5バッジ × 各2問 ＝ 10問（別の質問）。全部そろうと大人になる。診断は第1弾と第2弾の20問で計算し直す
- 1つのバッジは2問とも採点できたら取得とする

## 質問（プール方式）

5つの軸 × 第1弾・第2弾 × 各10問 ＝ **100問**を用意し、そこから出題する。一覧は `バッジ質問一覧.md`。

- 第1弾は日常の身近な場面、第2弾は価値観や葛藤に触れる深い場面
- 1つのバッジは「枠」2つでできている（例：第1弾のエネルギーは `r1_energy_a`・`r1_energy_b`）。枠ごとに、その軸・その弾の10問から1問を選んで出す
- 選び方：その人にまだ出していない質問からランダムに選ぶ。同じバッジの2枠には別の質問を出す。10問を出し切ったら、一番前に出した質問から再利用する
- 採点はどの質問でも同じ「軸ごとの採点基準」で行うので、人によって質問が違っても点数は比べられる
- 質問はコード上の定数として持つ（Functions と Flutter で同じIDを使う）。ID は `r1_energy_01` の形にする

## 体験の流れ

1. ホームのゲージを、5つのバッジの並びに置き換える。各バッジには2問の進み具合を表示する
2. 質問を出すのは次の2か所
   - **バッジ画面でバッジをタップ**：キャラクターがそのバッジの未回答の質問をする。質問に移る前に、背後の画面が見えるダイアログで「〇〇バッジの質問に話題を変えます」と表示し、「話題を変える」「やめる」を選んでもらう。会話の途中で急に話題が変わったように見えないようにするため
   - **ホームの最初の話題**：優先順位を「記憶 → **未回答のバッジ質問** → 前回の問い → 日替わり」にする（`chat_opener.dart`）
3. 質問はキャラクターの吹き出しに出す。回答への反応と深掘り、採点のタイミング、次の質問へのつなぎ方は「[質問中の会話](#質問中の会話話をぶった斬らない)」のとおり
4. 会話が終わるまでに採点できなかったときは、その質問を回答待ちに戻す（会話は切らない。下の「[採点できないまま話が盛り上がったとき](#採点できないまま話が盛り上がったとき)」）。**診断されなくなるわけではない**。翌日以降の最初の話題やバッジ画面から、同じ質問がまた出る。2回目以降は「この前の質問、もう一度聞いてもいい？」のような前置きを付ける
5. 採点できたら、ホームに「〇〇バッジ 1/2」のような小さい表示を出す。バッジがそろったら演出を出す
6. 第1弾がすべてそろったら診断する。今の「タイプ確定の演出」と「夢の選択」の流れにつなぐ

## 質問中の会話（話をぶった斬らない）

回答を受け取ってすぐ「はい次の質問」とならないようにする。回答にしっかり反応して深掘りし、「もう十分に分かった」と判断できたら、キャラクターが自分で話を締めて次の質問へつなぐ。ボタンは出さない。

### 流れ

```
キャラ: 休みの日、誰かと過ごすのと一人で過ごすの、どっちが元気出る？
ユーザー: 一人かな。人と会うのも好きだけど                 ← まだ採点できない（深掘りが要る）
キャラ: なんか分かる気がする。会ったあとって、どんな感じになる？
ユーザー: 楽しいけど、帰ったらどっと疲れてる               ← まだ採点できない
キャラ: 楽しいのに疲れちゃうんだね。帰ってからはどうやって回復してる？
ユーザー: 好きな音楽聴いてゴロゴロしてる                   ← 採点できた（-1 で保存）・話も落ち着いた
キャラ: いいね、自分だけの回復タイム大事だよね。教えてくれてありがとう！
        ［つながりバッジ 1/2 ✓］                          ← 小さい表示
キャラ: ねえ、もう一つ聞いてみたいんだけど…
        旅行に行くなら、予定をしっかり決める？その場で決める？  ← 次の質問（別の吹き出し）
```

### 「採点できた」と「話が落ち着いた」を分けて判断する

採点できたからといって、すぐ次の質問へ行くと、盛り上がっている話を切ってしまう。そこで次の2つを別々に判断する。

| 判断 | 意味 | 使い道 |
|---|---|---|
| 採点できた（`scoreReady`） | その軸のどちら寄りか（または中間か）を、具体的な場面や理由つきで読み取れる | 点数を保存する（バッジ表示が更新される） |
| 話が落ち着いた（`windingDown`） | ユーザーの返事が相づちや締めの言葉になった（「そうだね」「そんな感じ」「ありがとう」）。新しい話を広げていない | 締めて次の質問へつなぐ |

**次の質問へ進むのは「採点できた」かつ「話が落ち着いた」ときだけ**。採点できても、ユーザーがまだ話を広げている間は、キャラクターはその話に付き合い続ける。

### 1回の発言で行う処理の順番

回答中（質問を出してから次の質問へ進むまで）のユーザー発言では、**採点を先に行い、その結果を返答の生成に渡す**。

1. 採点（`handleAnswer`）に、質問からのやり取り全体を渡す
2. `scoreReady` が初めて `true` になったら、点数をその場で保存する
3. `generateCharacterReply` に結果を渡して返答を作る
   - 採点前 → 反応して深掘りする（深掘りは3往復目まで。それ以降は普通に会話する）
   - 採点後・話が続いている → 普通に会話を続ける（性格の言い当てはしない）
   - 採点後・話が落ち着いた → 締める。次に出す質問があれば、続けて次の質問を別の吹き出しで出す

採点を先にするぶん、回答中だけ返答が遅くなる（gpt-4o-mini の短い呼び出し1回分）。返答と同時に採点すると、判断を返答に反映できず、締めと次の質問が1往復遅れてしまうため、この順番にする。

### 採点が確定するタイミング

- **採点できたと判断された発言の時点で確定する**
- **確定は早くてもユーザーの2回目の発言から**。1回目の回答がどれだけ詳しくても、最低1回は反応して深掘りする（すぐ次へ行くと「ぶった斬られた」感じになるため）
- 1回の回答だけで採点するより、深掘りした分だけ材料が増えて正確になる

### 採点できないまま話が盛り上がったとき

同じ話題で何往復も続くのは、その人にとって話が盛り上がっている可能性が高い。**回数で打ち切って話題を変えることはしない**。

- 深掘りは3往復目まで。それ以降はキャラクターから深掘りの質問はせず、普通に会話を続ける（質問攻めにしないため）
- 会話が続いている間は、裏で採点を続ける。話の中で傾向が読み取れれば、その時点で保存する
- 採点の呼び出しは**ユーザーの発言5回**まで。それを過ぎたら採点をやめ、その質問は回答待ちに戻す。キャラクターは何も言わず、そのまま会話を続ける（「採点できなかった」のような表示もしない）
- 話題が自然に変わった（`topicChanged`）ときも同じ。読み取れていれば保存し、読み取れていなければ回答待ちに戻す。次の質問は出さず、その話に付き合う
- 回答待ちに戻った質問は、翌日以降の最初の話題やバッジ画面から「もう一度聞いてもいい？」と前置きして出す

### 次の質問へつなぐ条件

次のすべてを満たすときだけ、キャラクターが次の質問を出す。

- 今の質問の採点が確定した（`null` ではない）
- 話が落ち着いた（`windingDown`）。ユーザーの発言5回までに落ち着かなければ、次の質問は出さずにそのまま会話を続ける
- 未回答のバッジ質問が残っている
- ユーザーが別の話題を始めていない（始めていたら、その話に付き合う。採点できていなければ質問は回答待ちに戻し、別の日に「もう一度聞いてもいい？」と前置きして出す）

次の質問はなるべく別のバッジから選ぶ（同じ軸が続くと尋問のように感じるため）。

### 回答中の返答（`generateCharacterReply`）

- 新しい入力 `badgeContext`（今の質問文・何往復目か・採点の結果・次に出す質問）を渡す。今の会話履歴は直近2往復しか渡らないため、往復が進むと質問が履歴から消えてしまう。質問を毎回渡して、話がそれないようにする
- 返答への指示：
  - 回答の中身に具体的に反応して、共感する
  - 深掘りするときは、具体的な場面・理由・その後どうなったかを1つだけ聞く
  - 回答を評価しない（「外向的だね」のような性格の言い当てはしない。診断前に結果を匂わせないため）
  - 締めるときは、話してくれたことへのお礼で終える。次の質問はアプリが別の吹き出しで出すので、返答の中では出さない

## 採点（Functions）

### 採点（`generateCharacterReply` の中。`badgeScoring.js` の `scoreBadgeConversation`）

- 入力：回答中の質問（`active.questionId`）、質問からのやり取り（ユーザーの発言とキャラクターの返答。ユーザー発言は1件400文字まで、最大5往復）、何往復目か
- 質問ID からサーバー側で質問文と軸を引く（クライアントからは軸を受け取らない）
- AI に、その軸の説明と採点基準を渡して、次の JSON を返させる

```json
{"score": -2, "sub": {"processing": -1}, "scoreReady": true, "windingDown": false, "topicChanged": false}
```

- `scoreReady` は点数を確定してよいほど読み取れたか。`false` の間は点数を保存せず、次の発言でやり取り全体を採点し直す。ユーザーの1回目の発言では `true` にしない
- `windingDown` は話が落ち着いたか（次の質問へ進んでよいか）
- `topicChanged` はユーザーが質問と関係のない話を始めたか。`true` なら回答中を終える（`scoreReady` なら保存、そうでなければ回答待ちに戻す）。次の質問は出さない

- `score` は質問の軸の点数。**`null` 以外（0 を含む）ならバッジの1問分を取得**とする。0 は「中間の性格」という正しい結果で、無・風・土の判定に必要なため
- `sub` は、回答から**ほかの軸**もはっきり読み取れたときだけ入れる（例：協調性の質問に「みんなに合わせるけど、決めるときは直感」と答えた → 処理の軸に -1）。読み取れなければ空にする

| score | 意味（energy の例） |
|---|---|
| -2 | はっきり内向（一人の方が元気が出る、と明言） |
| -1 | やや内向 |
| 0 | 中間（両方を同じくらい挙げた。またはどちらにも強い好みがないと、中身を添えて答えた） |
| +1 | やや外向 |
| +2 | はっきり外向 |
| null | 判定できない（「うん」・質問と関係のない話・冗談） |

### 「中間（0）」と「判定できない（null）」の分け方

AIには2段階で判断させる。

1. **質問に答えているか**：回答の中に、質問の場面についての本人の好み・行動・気持ちが書かれているか
   - 書かれていない → `null`（「うん」「わからん」「別に」、関係のない話、冗談、答えたくない）
   - 「場合による」「どっちも」だけで中身がない → `null`。キャラクターが具体的な場面を聞き返す
2. **答えている場合に、どちら寄りか**：両方を同じくらい挙げた、またはどちらにも強い好みがないと中身を添えて答えた → `0`

| 回答 | 判定 |
|---|---|
| うん | null |
| 場合によるかな | null（聞き返す） |
| 人と会うのも好きだけど、一人の時間も同じくらい要る。週に半分ずつくらい | 0 |
| どっちでも平気。誘われたら行くし、なければ家で過ごすのも苦じゃない | 0 |
| 一人の方が落ち着く。人と会うと楽しいけど、あとでどっと疲れる | -1 |

採点基準にはこの表のような例を軸ごとに入れる。

- `null` のときはバッジを渡さない。その質問は回答待ちのまま残る
- モデルは `gpt-4o-mini` を想定する。1問あたり最大5回（発言ごと）呼ぶので、1人あたり初回で最大100回＋答え直し1回につき最大10回。多くは2〜4回で終わる見込み。gpt-4o-mini で短い入出力のため費用は小さい見込み（トークン数は実装後に実測して仕様書に書く）
- 回答の本文は保存しない。保存するのは点数と日時だけ

### 保存先 `users/{uid}/personalityBadges/current`

```
slots: {
  r1_energy_a: { questionId: "r1_energy_03", axis: "energy", round: 1, score: -2, sub: { processing: -1 }, answeredAt },
  r1_energy_b: { ... },
  ...（20枠）
}
askedQuestionIds: ["r1_energy_03", ...]   // 出題済みの質問（次に選ぶときに避ける）
retake: { badge: "r1_energy", slots: { a: {...}, b: {...} } } | null   // 答え直し中の一時的な回答
round1CompletedAt: Timestamp | null
round2CompletedAt: Timestamp | null
lastDiagnosedAt: Timestamp | null
```

- 書き込みはサーバー（Admin SDK）だけ。本人は読み取りと削除（性格のリセット）だけ（`firestore.rules`）

## 診断の計算

`axisCalculator.js` に、シグナルではなくバッジの点数から計算する処理を足す。

```
軸スコア = その軸の回答の score の平均 ÷ 2   → -1.0〜+1.0
```

- 第1弾の診断は10問、第2弾の診断は20問で計算する
- `sub`（ほかの軸の読み取り）は保存しておき、計算に入れるかどうかはペルソナテストで「入れる／入れない」を比べて決める。入れる場合は重みを0.5にする。質問の軸の点数より弱い根拠のため
- **期限と減衰はかけない**（今の90日・減衰の仕組みのままだと、3か月で回答が外れてしまうため）
- 元素・役割の判定（±0.3の境界）、BIG5変換、`details/current` への保存、性格履歴の記録、キャラクター詳細の生成・再生成、相性診断の stale 化は今の処理をそのまま使う
- 呼ぶタイミングは「第1弾がそろったとき」「第2弾がそろったとき」「答え直しが終わったとき」
- 計算に使うのは各枠の**今の回答**（第1弾だけの人は10枠、第2弾までの人は20枠）

## 再診断（答え直し）

大人になった後も含めて、次の2つの方法で再診断する。

### A. バッジ画面からの答え直し

- 取得済みのバッジに「答え直す」を付ける。タップすると、話題切り替えのダイアログを出してから、そのバッジの2枠に**まだ出していない質問**を出す
- 2問とも採点できたら、そのバッジの2枠を新しい回答に置き換えて再診断する。1問だけで止まった場合は、前の回答のまま（`retake` に途中経過を残し、続きから答えられる）
- 元素やタイプが変わったときは、今の「タイプ変化」の流れ（性格履歴・相性診断の stale 化・キャラクター詳細の再生成）にそのままつなぐ

### B. 半年ごとの提案

- 最後に答えた日（各枠の `answeredAt`）から180日たった枠があると、ホームの最初の話題で「久しぶりに聞いてもいい？」と前置きして、一番古いバッジの答え直しの質問を出す
- 出す優先順位は、未回答のバッジ質問と同じ位置（記憶の次）。未回答の質問がある間は、そちらを先に出す
- 断られたり答えなかったりしても、翌日以降にまた出るだけで、何も失われない

### 共通

- 答え直しで成長段階は下がらない
- 一度に置き換えるのはバッジ単位（2枠）。1問ずつ置き換えると、2問のうち片方だけ新しい状態で診断が動いてしまうため

## 確認方法（実装後）

既存データでは比べる基準そのものが偏っているため、合成した回答で確かめる。

1. **9元素のペルソナテスト**：9元素それぞれの人物像をAIに演じさせて20問に答えさせ、採点から元素を計算する。狙った元素が出るかを確かめる（特に雷・氷・光・闇）
2. **回答の揺れ**：同じペルソナで3回答えさせ、元素が変わらないかを確かめる
3. **判定できない回答**：「うん」「わからん」や関係のない話で `null` になるかを確かめる
4. **質問ごとの偏り**：中間の人物像に100問すべてを答えさせ、平均点が0から大きくずれる質問（どちらかの答えに寄りやすい質問）を差し替える
5. **中間の人**：どの軸も中間の人物像（無になるはずの人）を演じさせ、`null` ではなく `0` が付いて診断まで進むかを確かめる
6. 本番と同じモデルで、採点1回あたりのトークン数を実測する

## 確認結果（2026-10-07・実装後）

本番と同じ採点処理（`badgeScoring.js`・gpt-4o-mini）を、ローカルから合成した会話で動かした。人物像を演じる側（ユーザー役）は gpt-4o、キャラクター役は gpt-4o-mini で、質問ごとに深掘り・締めの流れも本番と同じ条件にした。

| 確認 | 結果 |
|---|---|
| 9元素のペルソナ（各20問） | **第1弾の10問で9/9、第2弾までの20問で9/9 が狙った元素になった**。雷・氷・光・闇も出る |
| 1問ごとの向き | 中間以外の軸で 140/140 が正しい向き（+/-）に採点された |
| 判定できない回答 | 180問中0件（きちんと答えた会話では null にならない） |
| 中間の人（無） | 100問すべて採点でき、59問が0点。各軸の平均は -0.25〜+0.45（-2〜+2）で、軸スコアにすると境界±0.3の内側 → 無になる |
| 1問あたりのユーザー発言数 | 平均3.6〜3.7回（上限5回） |
| 採点1回のトークン | 入力 平均1,189・出力 平均29（1,006回の実測） |

**注意**: 最初にユーザー役も gpt-4o-mini で動かしたところ、5/9 しか合わなかった。会話ログを読むと、「論理で決める人」の役なのに「気分で買っちゃう！」と答えるなど、**ユーザー役が人物像どおりに答えていなかった**（採点はその答えどおりに付いていた）。人物像を明示し、ユーザー役を gpt-4o に変えたら 9/9 になった。つまり採点は回答の中身を正しく読めている。実際のユーザーの回答がどれだけ本人の性格を表すかは、リリース後のデータで確かめる。

- 質問ごとの偏り（中間の人で平均が大きくずれる質問）は、1回ずつの会話では揺れが大きく判断できなかった。差し替えはリリース後の実データで見直す
- `sub`（ほかの軸の読み取り）を計算に入れるかは、主軸だけで 9/9 になったため入れない
