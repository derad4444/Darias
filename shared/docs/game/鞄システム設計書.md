## 1. 目的

現在の装備システムは「武器スロット1・防具スロット1、今より強ければ自動で乗り換え」で、
プレイヤーに判断の余地がない。**持ち物の管理そのものを性格診断の測定装置にする**ため、
容量制限のある鞄を導入する。

### なぜ性格診断に効くのか

既存のイベント選択は「その場でどう振る舞うか」しか測れない。
鞄は**一度した選択が持ち越され、後で見直しを迫られる**点が決定的に違う。

- 上位装備が手に入っても、今の装備を手放せない → **執着性**
- 状況に合わせて何度も持ち替える → **柔軟性**
- 満杯のとき何を捨てるかで、その人が何を守ろうとするかが出る

「手放す／捨てる」はアプリのテーマである**思考整理そのもの**であり、
「手放せない人は現実でも手放せない」という診断文に接続できる。

**執着性・柔軟性は現状イベントと戦闘でしか測れておらず、測定機会が少ない軸**でもある。

## 2. 鞄の仕様

### 2.1 容量

初期リソース（HP・食料・金貨・回復薬）が成長段階で増える既存設計に揃える。

| 成長段階 | 容量 |
|---------|------|
| 赤ちゃん | 3 |
| 幼少期 | 4 |
| 大人 | 5 |

> 数値は要プレイテスト。大人で「武器＋防具＋回復薬2＋地図」がちょうど埋まる想定。

### 2.2 何が枠を使うか

**装備中の武器・防具も枠を消費する。** 装備を鞄の外に置くと「強くなるほど得」になり、
判断が生まれない。枠を食うからこそ**「強さを取るか、備えを取るか」**のトレードオフになる。

| 対象 | 消費 |
|------|------|
| 武器（装備中・未装備を問わず） | 1枠 |
| 防具（装備中・未装備を問わず） | 1枠 |
| 回復薬 | **1個につき1枠** |
| 宝の地図 | 1枠 |
| **食料** | **枠を使わない（別枠・スタック）** |

回復薬を1個1枠にすることで、初めて「守りを厚くするか、装備を持つか」の緊張が生まれる。

### 食料だけ別枠にする理由

食料は**初期状態で大人5個**あり、1個1枠にすると鞄が食料だけで埋まってしまう。
また食料は**イベントで自動的に減る**もので、装備や回復薬と違って「使う」判断が無い。
持ち物としては受け身なので、容量を奪い合う対象から外す。

UI上はアイテム枠の右に区切り線を挟んで**6つ目の枠**として並べ、個数バッジを出す。
「持ち物ではあるが枠は使わない」ことが一目で分かるようにする。
食料に「使う」ボタンは出さない（自動消費のため）。

### 2.3 装備スロットとの関係

鞄の中の武器・防具のうち、**それぞれ1つを「装備中」にできる**。
装備中かどうかは鞄の中のフラグであり、枠の消費量は変わらない。

## 3. 「売る」と「捨てる」

**この2つを別物として分けることが、このシステムの核心。**

| | 場所 | 対価 | 意味 |
|---|------|------|------|
| 売る | **行商人のみ** | 買値の半分（端数切り捨て） | 得だが、行商人に会えるとは限らない |
| 捨てる | **いつでも** | なし | 損だが、今すぐ枠を空けられる |

商人ノードの出現確率は10分の2。**目の前で拾ったものを金貨に換えられるとは限らない。**
「行商人まで持ち堪えるか、今ここで捨てるか」という我慢自体が執着性の測定になる。

### 売値（買値の半分・端数切り捨て）

| アイテム | 買値 | 売値 |
|---------|------|------|
| 回復薬 | 💰3 | 💰1 |
| 木の枝 / 布の服 | 💰2 | 💰1 |
| 鉄の剣 / 鉄の鎧 | 💰5 | 💰2 |
| 名刀 / 聖なるローブ | 💰9 | 💰4 |
| 宝の地図 | 💰2 | 💰1 |

**買値 > 売値が全アイテムで成立するため、売買を繰り返して金貨を増やす抜け穴は無い。**

## 4. 入手時の分岐

### 4.1 鞄に空きがある場合

拾った装備は**鞄に入るだけで自動装備しない**。その上で
**［持ち替える／このまま］**（未装備なら［そうびする／カバンにしまう］）を選ばせる。
「今より強ければ自動で乗り換え」はやめる。

ダイアログには今の装備との差分（「持ち替えれば 2 上がる」など）を出して判断材料にする。
外した装備は鞄に残るため、持ち替えても失われない。

実装は `GameState.pendingEquipId` に立て、`resolvePendingEquip(bool)` で解決する。

### 4.2 鞄が満杯の場合

**「何を捨てるか」を選ばせる。** 選択肢には**「新しいものを諦める」も必ず含める。**

```
鞄がいっぱいだ。何を手放す？
  ⚔️ 鉄の剣（装備中）
  🛡️ 布の服
  🧪 回復薬
  🧪 回復薬
  🗺️ 宝の地図
  ── 名刀を諦める
```

「今あるものを守って新しいものを諦める」こと自体が強い執着性のシグナルになる。

実装は `GameState.pendingPickupId` に立て、`resolvePickupByDiscard(int)` /
`abandonPickup()` で解決する。**回復薬が鞄に入りきらない場合も同じ分岐に乗せる。**

## 5. 特性への反映

| 行動 | 加算 |
|------|------|
| 上位装備に持ち替える | 柔軟性+1 挑戦性+1 |
| 上位装備を断って今の装備を維持 | **執着性+2** |
| 満杯時に「新しいものを諦める」 | **執着性+2** |
| 弱い装備を売らずに持ち続けたままクリア | 執着性+1 |
| 手に入れてすぐ売る／捨てる | 論理性+1 計画性+1 |
| 回復薬を3個以上抱えて進む | 慎重性+2 |
| 回復薬を売って装備を買う | 挑戦性+2 |
| 満杯時に**回復薬**を捨てる | 挑戦性+1 |
| 満杯時に**装備**を捨てる | 慎重性+1 |
| 宝の地図を買う | 計画性+1 好奇心+1 |
| 地図を使わないまま冒険を終える | 執着性+1 |

**「満杯時に何を捨てたか」が回復薬（守り）か装備（攻め）かで挑戦性と慎重性が分かれる**のが設計の要。

## 6. 宝の地図のアイテム化

現在は購入した瞬間に `revealTreasure` が発動する。**これを鞄に入るアイテムに変える。**

- 買う／拾う → 鞄に入る（1枠）
- 鞄から**任意のタイミングで「使う」** → 宝箱の位置が判明
- 使わずに持ち続けると枠を圧迫し続ける

「いつ使うか」「使わずに抱え続けるか」という計画性・執着性の判断が加わる。

## 7. UI

### 7.1 鞄画面

リソースバーの装備ピルをタップで開く。**探索中・戦闘中を問わずいつでも開ける。**

```
鞄（4/5）
┌──────────────────────────┐
│ ⚔️ 鉄の剣    攻+3   装備中 │  [外す]  [捨てる]
│ ⚔️ 木の枝    攻+1          │  [装備]  [捨てる]
│ 🛡️ 鉄の鎧    防-2   装備中 │  [外す]  [捨てる]
│ 🧪 回復薬                   │  [使う]  [捨てる]
│ （空き1）                    │
└──────────────────────────┘
```

「捨てる」は誤操作防止のため確認ダイアログを挟む。

### 7.2 行商人

「立ち去る」まで取引を続けられるループにする。

```
行商人
├ ⚔️ 武器を買う   → 木の枝💰2 / 鉄の剣💰5 / 名刀💰9 / 戻る
├ 🛡️ 防具を買う   → 布の服💰2 / 鉄の鎧💰5 / 聖なるローブ💰9 / 戻る
├ 🧪 回復薬を買う（💰3）
├ 🗺️ 宝の地図を買う（💰2）
├ 💰 売る         → 鞄の中身から選択 / 戻る
├ 🎒 鞄を開く     → 装備変更・使う・捨てる
└ 立ち去る
```

鞄が満杯なら購入時に §4.2 の「何を捨てるか」を挟む。

### 7.3 結果画面

**「鞄の使い方」を1行加える。** この機能が診断に効いていることをユーザーに伝えるため。

- 執着性が高い → 「あなたは手に入れたものを手放さない人」
- 柔軟性が高い → 「あなたは状況に合わせて持ち物を変えられる人」

## 8. 実装方針

### 8.1 データ構造

`GameState` に鞄を追加する。**実行中の `GameState` は永続化されていない**
（保存は結果画面の `saveRun` で要約のみ）ため、**セーブ形式の変更は不要**。

```dart
class BagItem {
  final String id;        // Equipments の id / 'potion' / 'treasure_map'
  final bool equipped;    // 武器・防具のみ意味を持つ
}

// GameState
final List<BagItem> bag;
final int bagCapacity;    // 成長段階から決まる
```

既存の `weapon` / `armor` / `itemCount` は鞄からの導出に置き換える。
`weaponAtk` / `armorDef` は装備中フラグから計算する。

### 8.2 イベントループ

現在は `chooseEvent()` が `lastChoice` を立て、結果表示 →「進む」→ `closeEvent()` で
探索へ戻る（`if (s.lastChoice != null) return;` で1イベント1選択に制限）。

行商人だけこの流れを変える。

- `GameEvent` に「繰り返し取引できる」フラグを追加
- 結果表示のボタンを「進む」ではなく**「続ける」**にし、`lastChoice` のみクリアして
  `phase: event` のまま店に戻る
- 「立ち去る」を選んだときだけ `closeEvent()`

### 8.3 波及ファイル

| ファイル | 変更 |
|---------|------|
| `models/game_state.dart` | `bag` / `bagCapacity` 追加、`weapon`/`armor`/`itemCount` を導出化 |
| `models/equipment.dart` | 売値（`price ~/ 2`）を追加 |
| `models/game_event.dart` | 行商人イベントを階層構造・ループ対応に |
| `providers/roguelike_provider.dart` | 購入・売却・破棄・装備変更・特性加算 |
| `widgets/resource_bar_widget.dart` | 鞄の残量表示、タップで鞄画面 |
| `screens/roguelike_game_screen.dart` | 鞄画面、満杯時の破棄ダイアログ、入手時の選択 |
| `screens/roguelike_result_screen.dart` | 「鞄の使い方」1行 |
