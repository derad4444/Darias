## 0'. 開始画面（冒険タブ）

メインタブ下部の「冒険」タブの中身。マスコット見出し「冒険の準備をしよう！」（**右端に敵図鑑ボタン＝アイコンのみ**）＋冒険の準備（**キャラクター画像**＝本編アバター＋冒険者名・成長段階。名前は省略せず全表示）＋**ダンジョン選択カード**で構成。

**扉オープン演出**: 冒険タブに切り替わった瞬間、ダンジョンの両開き扉が開く演出を画面に重ねる（`AdventureDoorTransition`）。閉じた石扉（夜の紫の羽目板＋四隅の鋲＋中央の合わせ目に金のコンパス紋章）が、少しの溜めのあと外側の蝶番を軸に3D swing で開く。**扉の奥は光**（中心が白く溢れる放射グラデーション）で、扉が開くと光が満ち、**一拍おいてから光がフェードしてゲーム画面（`RoguelikeHomeScreen`）が現れる**。所要 約2000ms（溜め0.08→扉開0.55→一拍0.68→光フェード1.0のタイムライン）。`selectedTabProvider` を購読し、冒険タブ（index 4）に「入った」瞬間だけ再生する。演出中は `IgnorePointer` で操作を透過させ、開ききると自動的にオーバーレイを消す（`dungeon_theme.dart` とは独立した専用配色）。

**効果音**: 演出開始と同時に扉が開く効果音（`assets/audio/gate_open.mp3`）を鳴らす。BGMとは別インスタンスの専用プレーヤー（`SoundEffectPlayer`、`just_audio`）で一度だけ再生し、BGMを止めない。音量・ミュートは**BGM設定に連動**（`volumeSettingsProvider` の `bgmMuted` が true、または `bgmVolume` が0なら鳴らさない。再生音量は `bgmVolume` に合わせる）。初回タップの遅延を防ぐため `initState` で先読みする。

- 旧「おすすめ属性」欄は**廃止**（キャラの診断属性を出していただけでローグライクの挙動には未使用のため。混乱を避け削除）。startGame には引き続き `element` を渡し保存はする。

ダンジョン選択カードの表示要素（画像風レイアウト）:
- 絵文字の画像エリア（テーマカラーのグラデ） ＋ 悩み名 ＋（克服済みなら）克服バッジ ＋ 一言説明（`tagline`） ＋ **分岐マップ・全◯層（`GameState.mapLayerCount`）** ＋「出発する 👟」ボタン。
- **テーマカラーはその悩み（ボス）の元素色**（`dungeon_theme.dart` の `dungeonColor(id) = elementColor(boss.element)`、本編の `ElementType.color` と一致）。枠線・画像エリア・出発ボタンの色に使う。**色は難易度ではなく属性を表す**。出発ボタンの文字色は `elementInk()` で背景の明暗に応じて自動調整（黄/金/水色でも可読）。
- **最終ダンジョン**は施錠時 🔒＋「全ての悩みを克服すると解禁」＋進捗バー（克服数 / 総数）を表示し、出発不可。
- **難易度・報酬・推奨レベルは表示しない**。難易度はボスHP以外の要素（反撃力・escalates・fleeWorsens・封じ等）が効くため単純化できず、誤解を招くので廃止した。
- ヘッダーに **「敵図鑑」ボタン**（`/roguelike/codex` へ push）。

**スタミナ（基本1回＋広告で+1回）**: ダンジョン挑戦は**無料ユーザーは基本1回**。使い切ると「出発する」が「🎬 広告で挑戦」に変わり、**リワード動画を視聴すれば同サイクルでもう1回**挑戦できる（＝最大2回）。両方使うと回復待ちで無効化。**プレミアムは無制限**。回復は**基本プレイ（`basePlayAt`）から24時間経過**で満タン（毎日0時などの固定時刻ではない）。消費は**「出発」時**（中断・失敗しても消費）。状態はダンジョン選択の一覧上部に**常時ゲージ表示**（満タン時も表示。使い切ると回復ゲージ＋「回復まで 約N時間」）。実装: `roguelikeStaminaProvider` / `RoguelikeStamina`（`basePlayAt`/`adPlayUsed`, `roguelike_datasource.dart`）/ `_startDungeon`・`_StaminaBanner`（`roguelike_home_screen.dart`）。保存先 `roguelike_meta/stamina`（§Firestore）。

### 敵図鑑（`/roguelike/codex`）

ダンジョン選択画面の「敵図鑑」ボタンから push 遷移。**上部ステータスバー（HP/食料等）は出さない**。

- 一覧対象は `Dungeons.allEnemies`（ボス＋固有ザコ＋共通ザコ）。タブ「すべて / 通常の敵 / ボス」で絞り込み、各タブに「出会った数 / 総数」を表示。**タブの背景は敵カードと同じ色（`kRoguelikeCard`）で一覧と統一**し、選択中タブのみピンク（`kRoguelikePink`）のアクセント（枠・文字）を付ける。
- **出会った敵**（`codexProvider` の `enemies`）は通常表示、**未遭遇は「？？？」のグレー表示**（※出会った敵は色がつく）。
- カードは**全て同サイズ**（イメージにあった先頭の大カットは廃止）。表示要素：種別バッジ（通常の敵/ボス）＋（ボスが克服済みなら）討伐済みバッジ＋絵文字アート＋名前＋説明＋HP＋**敵の特徴**（`counterDrain`/`escalates`/`fleeWorsens`/`trait`/`counterBaseDamage` から導出）＋**ドロップ報酬**（`defeatReward`。ボスは「克服そのものが報酬」）。
- 絵文字：ボスは対応ダンジョンの絵文字、ザコは💭。色は `enemyColor`＝その敵の元素色（共通ザコ＝無＝グレー）。
- 一覧の**先頭（一番上）に図鑑コンプリート達成度**（出会った数 / 総数、全遭遇で COMPLETE）。タブ切替に関わらず全体（`allEnemies`）に対する達成度を表示する。
- **討伐回数・初回討伐ターンは表示しない**（未保存のため。イメージにはあるが、必要なら別途 Firestore にカウンタを追加する）。
- **出会った敵カードはタップで詳細画面**（`/roguelike/codex/enemy`、`Enemy` を `extra` で渡す）へ遷移。未遭遇カードはタップ不可。

### 敵詳細（`/roguelike/codex/enemy`）

- 大きなアート＋種別/討伐済みバッジ＋名前＋説明＋HP＋戦い方（`nextAction`）＋敵の特徴＋ドロップ報酬。
- **ボスかつ踏破済みの場合は「踏破時の解析結果」**を表示：そのダンジョンの**最新クリアラン**（`latestClearRunProvider((userId, dungeonId))` → `roguelike_runs` を `dungeonId` 等価で取得し `result=='clear'` を新しい順で先頭）から、**称号・推定元素・行動特性レーダー（保存済み `traits` マップ）・結果・踏破日**を再表示する。未踏破のボスは「まだ踏破していません」の案内。
  - レーダーの下に**解析コメント**を表示する（グラフだけにしない）。コメント文はrunに保存していないため、**保存済み `traits`／`inferredElement` から再生成**：踏破＋上位特性の要約文＋**目立った力（上位3特性）**の `TraitInfo`（絵文字＋説明）＋**推定元素の一言**（`ElementInfo`。無のときは省略）。
- 敵の表示ヘルパー（絵文字・色・特徴・ドロップ・画像）は `widgets/dungeon_theme.dart` に集約し図鑑と共用。

### 敵キャラ画像

敵キャラ画像は `flutter/assets/images/roguelike_enemies/{id}.png` に配置（一覧画像から個別に切り出し、**背景透過**）。**全25体**：ボス11体（＝ダンジョンid）＋固有ザコ11体（`awkward_silence` 等）＋共通ザコ3体（`haze`/`small_unease`/`idle_thoughts`）。`enemyImageAsset(id)` でパス取得、`enemyArt(id, emoji, size, seen)` で画像（透過PNG・`BoxFit.contain`、背景はコンテナのテーマ色グラデが透ける）or 絵文字フォールバックを表示。適用箇所：ダンジョン選択カード／敵図鑑カード／敵詳細／戦闘の敵カード（小アイコン＋シーン）。
- 背景透過は「**フチに連結した背景色のみ塗りつぶし透過**」（rembg等の主体抽出は炎・もや等の演出まで消すため不採用）。`scipy.ndimage.label` で画像端に接する背景連結成分のみ alpha=0。暗いキャラ×暗背景（孤独・ぽつんとした寂しさ等）は許容差を個別に下げる。
- `enemyColor(e) = elementColor(e.element)`：敵の元素色（本編 `ElementType.color` と一致。共通ザコ＝無＝グレー）。図鑑カード・敵詳細・戦闘の敵カード（枠・HPバー・アイコン背景）で使用。
- `pubspec.yaml` に `assets/images/roguelike_enemies/` を追加。

## 0. ダンジョン構造（悩み別ダンジョン制）

ゲームは「**悩みごとのダンジョン**」で構成される。各ダンジョンの最奥のボス＝その悩み本体で、**踏破（ボス撃破）＝その悩みの克服**。

- **初期10ダンジョン**（通常の悩み）＋**最終1ダンジョン**（全悩み克服で解禁）。
- プレイヤーは**タイトルで自由に「向き合う悩み」を選ぶ**（`roguelike_home_screen.dart` の選択リスト）。
- 克服した悩みは **「心の図鑑」（`roguelike_clears`）** に記録し、選択画面に「克服済み」を表示。全悩み克服で最終ダンジョンが解禁される。

| 10 | 先延ばし | 🐢 | あとでいいや |
| 最終 | 心の迷宮の守護者 | 🌀 | 残り火の迷い（全悩み克服で解禁） |

### ザコ（通常敵）— ハイブリッド方式

敵ノードには **固有ザコ（そのダンジョンの悩みの小さな現れ・1体）** と **共通ザコ（全ダンジョン共通の「もやもや／ささいな不安／とりとめのない雑念」）** が混在して出現する（`Dungeon.mobPool`）。ザコもボスもテーマで貫かれ、「小さな症状を越えて根っこと対峙する」構成自体が克服のメタファになる。

## 1. リソースと使い道

| リソース | 範囲 | 主な入手手段 | 主な消費・減少 | 枯渇時 |
|---|---|---|---|---|
| HP (❤️) | 0〜maxHp | 休憩、廃墟、回復薬、謎（気づき＝最大HP増加・小回復）、仲間の励まし | 戦闘ダメージ、罠（宝箱）、謎（未知に触れる）、餓死、敵の反撃 | **0で冒険終了（ゲームオーバー）** |
| 食料 (🍞) | 0〜99 | （基本は減るのみ。入手イベントなし） | 移動2回ごとに1、休憩・迂回・励まし、将来不安等の反撃、逃走 | **0だと移動時にHP-5（餓死）** |
| 金貨 (💰) | 0〜99 | 宝箱、廃墟（大成功）、旅人、ザコ撃破 | 行商人での購入（回復薬・地図・**武器/防具**）、旅人への施し | なし（買い物ができないだけ） |
| 回復薬 (🧪) | 0〜9 | 行商人で購入、廃墟、休憩、旅人、ザコ撃破 | 戦闘「回復薬を使う」(HP回復)、助けを求める声での手当て | なし（消費する選択肢が出ない/選べない） |
| 絆 (🤝) | 0〜10 | （**相棒がいる時のみ**）人助け・休憩・戦闘で仲間に話す等 | 仲間に相談/力を合わせる、説得、対人/孤独の反撃 | 絆0で**相棒が離脱**（§1.2） |

**設計意図**: 食料は基本減る一方なので「進行のコスト」になり、金貨・回復薬・絆は使い切り型の戦略リソースになる。マップは枝道式で必ずボスに到達するため、緊張感は「HP・食料をどこまで保たせるか」と「どの分岐（敵の少ない安全ルート／報酬の多い寄り道）を選ぶか」で生まれる。

### 1.1 回復薬（旧「アイテム」）

旧「アイテム」は「何のアイテムか」が曖昧で違和感があったため、**「回復薬」1種に統一**した。

- **用途はHP回復／手当てに集約**: 戦闘の「回復薬を使う」（HP+12・全戦闘共通・全段階）と、「助けを求める声」での負傷者の手当て（相棒加入の投資）。
- 旧アイテムの汎用ツール用途（罠解除・鍵開け・戦闘バースト）は**廃止**し、各イベント/戦闘の別選択肢（調べる・観察する等）に集約した。
- 所持0の時は回復薬を消費する選択肢を**非表示**にする（`requiresItem`）。
- 内部のリソースキーは `items` のまま（影響範囲を抑えるため）。

### 1.2 絆＝相棒（Companion）システム

絆は「**相棒（仲間）**」との関係を表すリソース。**相棒がいない間は意味を持たず、初期値は全段階で0**（相棒不在時はUI非表示）。

- **相棒の加入**: 冒険中の加入イベント「助けを求める声」で相棒（レオ）が仲間になると絆が解禁される（ゲーム内NPC）。`Companion.source` に `friend` を予約済みで、将来フレンド/マルチ連動に拡張可能。
- **絆が増減するのは相棒がいる時だけ**（イベント・戦闘・敵の反撃すべて）。一過性NPC（旅人・商人）では絆は動かない。
- **相棒の離脱**: 絆が0になると相棒は去り、絆要素は再びロックされる。
- **可視化**: リソースバーの2段目に「🤝 絆」ピル（値＝絆ポイント）を相棒がいる時だけ表示（ピル上は省スペースのためラベルは「絆」のみで相棒名は出さない）。結果画面では「相棒: ◯◯／相棒なし」を表示。
- 関連: `models/game_state.dart`（`Companion`）、`requiresCompanion`（イベント/戦闘選択肢）、`Outcome.recruitCompanion`（加入）。

### 1.3 装備（武器・防具）システム

戦闘に厚みを持たせ、金貨に使い道を与えるための装備システム（`models/equipment.dart` の `Equipment`／`Equipments`）。効果は**固定値**で、**ランごとにリセット**（ラン間の持ち越しなし）。

**装備は鞄（インベントリ）で管理する。** 装備中の武器・防具も鞄の枠を1つ消費するため、
「強さを取るか、備えを取るか」の判断が生まれる。詳細は
[`鞄システム設計書.md`](鞄システム設計書.md)。

| 種別 | 効果 | 一覧（名前 / 効果 / 商人価格） |
|---|---|---|
| 武器 ⚔️ | 与ダメ **+power** | 木の枝(+1/💰2) / 鉄の剣(+3/💰5) / 名刀(+5/💰9) |
| 防具 🛡️ | 被ダメ **-power** | 布の服(-1/💰2) / 鉄の鎧(-2/💰5) / 聖なるローブ(-3/💰9) |

- **戦闘への反映**（`roguelike_provider.dart`）:
  - 与ダメ ＝ `(選択肢の damageToEnemy + weaponAtk) × 元素相性倍率`（攻撃系のみ）。
  - 被ダメ ＝ 敵から受けるダメージ（`damageToPlayer`＋敵の反撃 `_enemyCounter`）を `armorDef` 減算。**下限1は必ず通す**（完全無効化しない）。**自傷コスト（`resourceChanges['hp']`＝ボス特効の自傷等）は軽減対象外**＝「敵からのダメージ」だけ軽減。
  - 想定ダメージ表示にも装備補正を反映（元素倍率は含まない目安）。
- **入手**:
  - **行商人**：**全6種を販売**（§5.9）。買っても自動装備はせず鞄に入る。
  - **宝箱のドロップ**：`Outcome.equipRewardId`。古い宝箱「すぐ開ける」で鉄の剣/鉄の鎧、廃墟「入って探索する」で稀に名刀/聖なるローブ。（謎ノードは物質報酬を出さない＝最大HP/地図開示のみ）
  - **拾った装備は自動装備しない。** その場で「持ち替える／このまま」を選ばせる。
    鞄が満杯なら「何を手放すか／諦めるか」を選ばせる。**この選択自体が
    執着性⇔柔軟性の測定になる**（設計書 §4 §5）。
- **UI**：**ヘッダーには装備を出さない**（持ち物はカバンの中で一元的に確認する）。
  ヘッダーの「🎒 カバン n/N」をタップすると鞄画面が開き、探索中・戦闘中を問わず
  いつでも装備を変更できる。装備は元素を持たない（`power` のみ）ため、
  敵を見てから持ち替えても有利にならず、戦闘中の変更を制限していない。

## 2. 成長段階（GrowthStage）

`signalCount`（蓄積シグナル数）で決まる。**段階が上がるほど初期リソース（HP・食料・金貨・回復薬）が増え**、選択肢も増える。

| 段階 | 条件 | 初期 HP/食料/金貨/回復薬/絆 |
|---|---|---|
| 赤ちゃん (baby) | count < 10 | 20 / 1 / 1 / 0 / 0 |
| 幼少期 (young) | 10〜29 | 30 / 3 / 3 / 0 / 0 |
| 大人 (adult) | count ≥ 30 | 40 / 5 / 5 / 1 / 0 |

絆は**全段階0スタート**（相棒が加入して初めて意味を持つ）。各選択肢は `minStage` を持ち、その段階以上で出現する。
**成人の選択肢は「ただ強い上位互換」ではなく「高度だがクセのある選択」とする**（絆/金貨/食料を消費する、当たり外れがある等）。

> 大人ほど HP・食料・金貨・回復薬を多く持って始められる。段階差は初期リソースと出現する選択肢（`minStage`）で表す。

## 3. マップ（枝道式の層状分岐マップ）

**層（レイヤー）の並びで構成される分岐マップ**（Slay the Spire 風）。スタート層（下）からボス層（上）へ、つながった次の層のノードをタップして**一方向**に進む。どのルートを選んでも**必ずボスに合流**する（`game_state.dart` の `_generateMap` / `map_cell.dart` の `MapCell`）。

- **全 `mapLayerCount = 7` 層**（`GameState.mapLayerCount`）: スタート層(1ノード) → 中間5層 → ボス層(1ノード)。
- 中間層は各 **2〜3ノード**（生成時にランダム）。
- 各ノードは次の層の **1〜2ノード**へつながる。生成時に「全ノードがスタートから到達可能／全ノードからボスへ到達可能」を保証し、**行き止まり・到達不能ノードを作らない**（`_connectLayers`）。

| ノード種類 | 配置 | 発生内容 |
|---|---|---|
| スタート (start) | 層0・1ノード | 開始地点 |
| 敵 (enemy) | **敵専用層 {2,4}** の全ノード ＋ 中間層に重み付きでも配置 | そのダンジョンの**固有ザコ＋共通ザコ**からランダムで戦闘 |
| 宝箱 (chest) / 休憩 (rest) / 商人 (merchant) / 仲間 (companion) / 謎 (mystery) / 敵 (enemy) / 空 (empty) | それ以外の中間層に**重み付きランダム配置**（`eventPool`・合計10枠：宝箱2/謎2/商人2/休憩1/敵1/仲間1/空1 ＝ 20%×3 + 10%×4） | イベント／戦闘（空は何も起きない） |
| ボス (boss) | 最終層(層6)・1ノード | **そのダンジョンの悩み本体**（`Dungeon.boss`）。全ルートの合流点 |

**敵の遭遇**: 中間層のうち **2層（層 index 2・4）を「敵専用層」**とし、各層は必ず1ノードを通るので**どのルートでも確定2回の敵戦闘＋ボス**が保証される。さらに他のイベント層にも `eventPool` から**敵ノードが配置されうる**（`CellType.enemy`。層に関係なく `_triggerCellEvent` がザコ戦闘を起こす）ため、ルートによっては戦闘が増える（分岐で避けられる）。宝箱・休憩などのイベント層は分岐で選べる。

**表示の起点（マップの下から表示）**: マップは縦スクロールで、スタート層（下）が起点。探索ビュー（`_ExploringView`）は `ScrollController` を持ち、**入場時に現在地ノードがビューポート下寄りに来るようスクロール**する（`_scrollToPlayer`。初期は下＝スタート＝現在地を表示）。現在地が上の層へ進むたびに**追従してスクロール**（`didUpdateWidget` で現在地変化を検知しアニメーション）。目的地のボス（上）は上方向へスクロールして確認する。

進むたびに**2歩ごとに食料1消費**（到達層が偶数=L2,4,6のとき1消費、`moveToCell`）。ノードの種類に応じてイベント・戦闘が発生する。一方向のため**再訪は起きない**（各ノードのイベントは1回だけ）。

### ノードの判明・地図開示

- ノードは **未判明（🌫️）/ 判明（種別アイコン＋ラベル）** で表示。判明条件は `isVisited || 現在地 || isRevealed || これから進める(次の層のつながり) || ボス`（`map_grid_widget.dart`）。**ボスは目的地として常に表示**する。
- **通り過ぎたノード**（現在地以外の訪問済み）は内容を**半透明（グレーアウト）**にして「もう通った」ことを明示する。
- 層間の**枝道は線でつなぎ**、現在ノードから進める枝はアクセント色で強調する（`_EdgePainter`）。
- **地図イベントの開示**（`Outcome.revealCells` / `revealTreasure`、`_applyReveal`）：
  - 旅人「話を聞く」(成功) … ランダムな未判明ノードを **3つ判明**（`revealCells: 3`）。
  - 宝の地図（行商人で購入、💰2）… **鞄に入るアイテム**。鞄から「つかう」と**宝箱ノードを全て判明**させる（`useTreasureMapFromBag`）。買った瞬間には発動しないため「いつ使うか」の判断が生まれる。

### ノード種別ごとのイベントプール

ノード種別に合ったイベントだけを抽選する（`GameEvents.poolByCell`）。**各イベントは1つのノード種別のみに割り当て、ノード種別をまたいで同じイベントが出ないようにする**。さらに**相棒の有無でフィルタ**する:

- `requiresCompanion`（仲間の疲労など）… 相棒がいる時だけ抽選
- `excludeWithCompanion`（助けを求める声＝加入イベント）… 相棒がいない時だけ抽選

相棒フィルタで「抽選候補が0件」になるノードが生じないよう、各ノード種別に**常時抽選できる（相棒フラグなしの）イベントを最低1つ**含める。

| ノード | 抽選されるイベント |
|---|---|
| 宝箱 (chest) | 古い宝箱 / 廃墟 |
| 休憩 (rest) | 焚き火 / 仲間の疲労※ |
| 商人 (merchant) | 行商人 |
| 仲間 (companion) | 助けを求める声※ / 旅人 |
| 謎 (mystery) | 奇妙な光 / もう一人の自分の声 / 古い壁の記述 |

※「助けを求める声」は相棒不在時のみ、「仲間の疲労」は相棒在席時のみ出現。商人ノードはイベント1種（行商人）。

### 宝箱 と 謎 の役割分担

**宝箱＝物質報酬（度胸・リスク志向）**、**謎＝内面の探究（好奇心・探究）**で軸を分ける。

- **宝箱 (chest)**：`古い宝箱`／`廃墟`。**挑戦/直感 ⇔ 慎重**を測り、報酬は**金貨・装備**（廃墟の奥に稀に上位装備＝名刀/聖なるローブ、宝箱に鉄の剣/鉄の鎧）。
- **謎 (mystery)**：**好奇心・探究 ⇔ 回避・慎重**を測り、報酬は**最大HP増加（＝「気づき」で心が強くなる。`resourceChanges['maxHp']`）・地図開示（`revealCells`/`revealTreasure`）・小回復**で、**金貨・装備は出さない**（宝箱と重複させない）。
  - `奇妙な光`（環境の未知）／`もう一人の自分の声`（内省・心の迷宮テーマ）／`古い壁の記述`（探究・地図中心）。すべて重み付き抽選（大成功/成功/失敗）。

## 4. 確率・結果システム（Outcome）

**選択結果は固定ではなく、選択肢ごとに成功率とリスクが変わる重み付き抽選で決まる。**
「一度最適解が分かると作業化する」のを避け、毎回「今なら賭けるか？」の判断が発生するようにする。

### 4.1 Outcome モデル（`outcome.dart`）

- `OutcomeTier { great, success, failure }` … 大成功 / 成功 / 失敗
- `Outcome` … `tier` / `weight`（抽選の相対重み） / `resultText` / `resourceChanges` / `traitDelta` / `damageToEnemy` / `damageToPlayer` / `recruitCompanion`（加入する相棒名）
- `WeightedChoice` mixin（EventChoice / BattleChoice が実装）
  - `successRate`：大成功＋成功の重み割合（%）。失敗枠が無ければ100
  - `isGuaranteed`：結果が1通り（確定枠）か
  - `roll(rng)`：重みに従って結果を1つ抽選

### 4.2 抽選アルゴリズム

```
total = Σ weight
r = rng.nextInt(total)      // 0 〜 total-1
各 outcome を順に走査し、r < weight なら採用。違えば r -= weight。
```

### 4.3 選択肢の共通プロパティ

| プロパティ | 説明 |
|---|---|
| `outcomes` | 重み付き結果リスト |
| `riskHint` | 選ぶ前の短い説明（例「危険だが速い」「安全だが確実」） |
| `selectTrait` | **その選択を「選んだ」こと自体が示す判断傾向**。成功/失敗に関わらず加算（§7.1） |
| `upfrontCost` | 選んだ瞬間に確定で支払うコスト（抽選結果とは別に必ず適用） |
| `extraFoodCost`（イベントのみ） | 確定で消費する追加の食料（**安全だが遅い**を表現）。**食料が足りない分はHPで払う**（🍞不足1につき❤️-3。食料0でもトレードオフが効く。`chooseEvent` で `food<0` の分を `hp` に変換、結果文に「体力を削って切り抜けた（❤️-N）」を追記）。同様に `upfrontCost['food']`・結果の食料減少も食料が尽きればHP換算される |
| `minStage` | 出現する最低成長段階 |
| `requiresCompanion` | 相棒がいる時だけ表示する選択肢 |
| `requiresItem` | 回復薬を消費する選択肢（所持0で非表示） |
| `isFlee`（戦闘のみ） | 逃走アクション |

### 4.4 表示（ゲーム画面）

- **選択前**：各選択肢に成功率%（確定枠は「確定」）＋ `riskHint`
  - 成功率の色: 85%以上=緑 / 60%以上=橙 / それ未満=赤
  - **戦闘の選択肢**は成功率の下に **想定ダメージ**（敵に／自分に）または **想定効果**（回復・絆など）を表示する。
    - この数値は **代表的な結果（最も重みの大きい outcome）に基づく目安** であり、実際は重み付き抽選で変動する。そのことを明示するため、抽選枠は「**想定ダメージ／想定効果**」、確定枠（`isGuaranteed`）は「**ダメージ（確定）／効果（確定）**」とラベルを出し分ける。
- **選択後（イベント）**：実際に出た結果の **大成功/成功/失敗バッジ** ＋ 結果テキスト ＋ リソース変化（確定コスト＋抽選結果を合算表示）＋ 相棒の加入/離脱通知
- **選択後（戦闘）＝メッセージウィンドウ（RPG風・タップ送り）**：
  - 行動・敵の反撃・蝕み・封じ・撃破・**報酬**などの文言を、画面下部のメッセージウィンドウに **1文ずつタップで送って** 表示する（「タップで次へ ▶／タップで続ける ▶」、`n / N` のページ表示つき）。戦闘開始時の「〇〇が現れた！」も同様。
  - メッセージ送り中は選択肢を隠す。送り終えると、戦闘継続なら選択肢へ戻り、**死亡・撃破（ボス）・撤退・逃走成功などの画面遷移はメッセージを送り終えてから**適用する（途中で結果画面に飛ばない）。
  - 結果が確定するたびに、画面中央へ成否バッジ（大成功＝金 / 成功＝緑 / 失敗＝赤）を拡大フェードでポップ表示し、約0.9秒で自動消滅する。失敗時は本体を小刻みに横揺れ（シェイク）させる（逃走失敗・撤退も「失敗」演出）。
- 封じられた戦闘選択肢はグレーアウトして選べない
- **戦闘画面のレイアウト**：敵カード（キャラクター＆敵の画像・HP・経過ターン）は画面上部に**固定**し、スクロールしない。「どうする？（行動選択）」の見出しと選択肢リスト（またはメッセージウィンドウ）のみがその下に入る。
- **「ログ」ボタン**（下部バー左）：ボトムシートで **この戦闘で行った行動と成果だけ**を簡潔に一覧する（例「ガード → 大成功（敵に9 / 自分6）」「報酬: ❤️+3」）。反撃・蝕みなどの装飾描写はログには載せず、メッセージウィンドウ側で見せる。

> 実装メモ: 想定ダメージ表記・成否演出・メッセージウィンドウは `roguelike_game_screen.dart`（`_ChoiceCard` / `_BattleView` / `_messageWindow`）。メッセージ・履歴・保留遷移は `GameState.battleMessages` / `battleHistory` / `pendingPhase` / `pendingResult`（`game_state.dart`）、`roguelike_provider.dart` の `performBattleAction` / `_enemyCounter` / `_handleFlee` で組み立て、`finishBattleMessages()` で送り完了時に遷移を適用する。

### 4.5 設計指針（全イベント共通）

1. 各イベントに成功/失敗（必要なら大成功）を持たせ、**選択肢ごとに確率を変える**
2. 「安全だけど遅い（行動・食料消費）」「危険だけど速い」のトレードオフを必ず用意する
3. 「立ち去る/無視する」はリスクなし・体力温存の安定択として残す

## 6. 戦闘（敵＝悩み）

敵は **ダンジョンのボス（悩み本体・1体）** と **ザコ（固有1体＋共通3種）**。
**HP以外に `EnemyTrait` による個性を持ち、反撃挙動が異なる。** `isBoss` がボス（撃破＝クリア）を表す。

### 6.1 敵の共通フィールド（Enemy）

`trait` / `element`（敵の元素・単漢字） / `isBoss` / `counterBaseDamage`（反撃基礎ダメージ） / `counterDrain`（反撃時のリソース減） / `escalates`（経過ターン分ダメージ加算） / `fleeWorsens`（逃げると悪化） / `defeatReward`（撃破報酬・ザコのみ） / `defeatRewardText`（撃破/克服の一言）。

反撃ダメージ = `(counterBaseDamage + (escalates ? battleTurns : 0) + 0〜2のランダム揺らぎ) × 相性倍率`（最低1）。相性倍率は §6.4 を参照。
**絆を削る反撃（`counterDrain['bond']`）は相棒がいる時のみ適用**する。

### 6.2 ボス一覧（悩み・`Dungeons`）

各ボスは「正面から向き合う／逃げる／観察(幼少〜)／テーマ特効(成人)／回復薬を使う」を基本とする（既存3悩みは交渉・仲間相談など追加選択肢を持つ）。

- **観察系（確定・自傷小）の威力は控えめ**にして「安全だが遅い」を明確化（共通ボス6／対人5／将来不安6／自己否定7／最終7。`_bossChoices` の `observeDmg` 既定=6）。「正面から向き合う」の期待値より低くし、速さと安全のトレードオフを成立させる。
- **テーマ特効（`_special`, 成人）は高火力だが3重の制約**を持つ：(1) **成功率制**（成功60%＝敵に14／失敗40%＝空振りで小ダメージ。確定ではない）(2) **自傷HP-4**（成否問わず）(3) **1回の戦闘で1度だけ**（`oncePerBattle`。使うとその戦闘中は非表示）。ノーリスク連打を防ぐ。最終ボスの「仲間と力を合わせる」も同様に 成功60%＝敵に20／失敗40%＝小ダメージ・自傷HP-6・絆-2・1回のみ（相棒必須）。
- **戦闘画面では「逃げる」を選択肢の一番下に固定表示**する（`roguelike_game_screen.dart` でフィルタ後に flee を末尾へ並べ替え。敵定義の順序は不変）。

| ボス（悩み） | 元素 | HP | 反撃の特徴 | テーマ特効（成人） |
|---|---|---|---|---|
| 対人関係の悩み | 水 | 24 | 基礎3＋**絆-1** | 仲間に相談（相棒）/ 交渉して距離を縮める |
| 将来不安 | 風 | 24 | 基礎2＋**食料-1**＋escalate | 小さな目標を立てる |
| 自己否定 | 闇 | 26 | 基礎4・**最大火力封じ**・**逃げると悪化** | 過去の成功を思い出す |
| 評価への恐怖 | 光 | 24 | 基礎3＋**金貨-1** | 自分の物差しで測る |
| 孤独 | 闇 | 22 | 基礎3＋**絆-1** | 誰かに声をかける |
| 焦り | 雷 | 20 | 基礎2＋escalate | 一つずつ片付ける |
| 怒り | 炎 | 24 | 基礎5（強反撃） | 怒りの奥の本音を見る |
| 迷い | 風 | 20 | 基礎3 | 直感で決める |

### 6.3 ザコ（共通＋固有）

弱い障害として「立ち向かう／逃げる／観察していなす(幼少〜)／回復薬を使う」を持つ（`Enemies.mobChoices(dmg)`、基本 dmg=6・固有/一部7）。

- **立ち向かう**：成功70%→敵に`dmg`・自傷3／失敗30%→敵に`dmg/2`・自傷5。
- **観察していなす**：確定→敵に`dmg-3`・自傷2。**観察を立ち向かうより明確に弱く**して「速いが自傷あり（立ち向かう）／遅いが安全（観察）」のトレードオフを成立させる（以前は敵に`dmg-1`・自傷1で観察一択だった）。

> 補足: カードの「自分に」＝その行動の `damageToPlayer`（行動自体の反動）。戦闘後に必ず入る「○○の反撃！」（`counterBaseDamage` 由来の `_enemyCounter`）とは別物。

| 共通ザコ | HP | 撃破報酬 |
|---|---|---|
| もやもや | 9 | 💰+1 |
| ささいな不安 | 8 | 💰+1 |
| とりとめのない雑念 | 10 | 🧪+1 |

固有ザコ（各ダンジョン1体・§0表）は HP9〜10、撃破報酬 💰+1 程度。

### 6.4 共通の戦闘選択肢

| 選択肢 | 条件 | 効果 |
|---|---|---|
| 回復薬を使う | 回復薬所持時（`requiresItem`）・全段階 | 🧪-1 → ❤️+12（確定） |
| 仲間に相談/話す/力を合わせる | **相棒**（`requiresCompanion`）・成人 | 絆を消費 or 深め、特効ダメージ（自傷・成功率制・1回のみ） |
| 逃げる | 全段階 | 離脱を試みる（§6.6） |

### 6.5 撃破報酬

- **ザコ撃破**: お金/回復薬の**小報酬**（道中で使える）＋一言描写。「避けるのが最適」を避け、戦う意味を持たせる（HP消耗とのトレードオフは維持）。
- **ボス撃破**: 物質報酬は**なし**（撃破＝即クリア終了のため意味を持たないため）。報酬は **「克服」そのもの**＝心の図鑑への記録・最終ダンジョン解禁・結果画面の克服演出（克服メッセージ＝`boss.defeatRewardText`、図鑑進捗 N/10、解禁告知）。

### 6.6 戦闘フロー（performBattleAction）

1. 封じられた選択肢は選べない（自己否定の効果）
2. `upfrontCost` を先払い → 結果を抽選 → ダメージ・リソース・traitを適用（絆は相棒がいる時のみ動く）。**与ダメには本編元素×敵元素の相性倍率がかかる**（§6.7）。攻撃には本編元素の技名＋相性のひとことが付く
3. 絆が0になったら相棒離脱（バトルログに追記）
4. プレイヤー死亡判定 → 敵撃破判定（撃破時は撃破カードで**リワード広告のポップアップ**を出す。§10）。ザコ＝「次に進む（広告→探索継続）／進まない（記録せず選択へ）」、ボス＝「結果を見る（広告→結果画面＝クリア記録）／見ない（記録せず選択へ）」。ボスは自動でvictoryにせず `confirmBossVictory()` で確定する
5. 敵の反撃（`_enemyCounter`：trait別。絆/食料ドレイン、escalate、自己否定の封じを適用）→ 絆0で相棒離脱 → 死亡判定

**逃走（_handleFlee）**
- ボス: 逃げると**冒険終了**。**結果画面は出さずダンジョン選択へ戻る**（記録もしない）
- 自己否定/先延ばし（fleeWorsens）: 逃げると敵がHP+4回復し反撃を受ける（悪化）
- 通常敵: 70%で離脱成功（🍞-1して探索へ）、失敗時は反撃を受けて戦闘継続

### 6.7 元素相性（本編元素 × 戦闘）

本編キャラの元素（`CharacterDetails.element` → `GameState.element`）を戦闘に絡める。プレイヤーの元素と敵の元素の相性で、与ダメ・被ダメに倍率がかかる。元素はすべて単漢字で扱う（本編・推定元素と語彙が一致）。実装は `models/element_affinity.dart`。

**相性は本編の鏡構造（対極ペア）に準拠**: 炎↔水・風↔土・雷↔氷・光↔闇、無は中心（全てと互角）。各悩みは「その気質の人が陥りやすい悩み」として元素を持つ（敵元素＝§6.2/0表）。

- **得意（有利）＝自分の元素の対極（鏡）の悩み**: その悩みを乗り越える解毒剤を気質として持つ。例「独り燃える炎タイプ → 孤独・対人関係（水）に得意」。
- **苦手（不利）＝自分の元素と同じ悩み**: 自分の気質そのものの影なので手強い。例「炎タイプ → 怒り（炎）に苦手」。
- **互角＝それ以外、またはどちらかが無**。

| 相性 | 条件 | 与ダメ倍率 | 敵反撃倍率 |
|---|---|---|---|
| 有利（得意） | 敵＝自分の対極元素 | ×1.4 | ×0.75 |
| 不利（苦手） | 敵＝自分と同元素 | ×0.7 | ×1.3 |
| 互角 | それ以外／無が絡む | ×1.0 | ×1.0 |

各タイプの得意/苦手（敵元素割り当て＝§6.2より導出）:

| 本編元素 | 得意な悩み（対極） | 苦手な悩み（同元素） |
|---|---|---|
| 炎 | 対人関係（水） | 怒り |
| 水 | 怒り（炎） | 対人関係 |
| 風 | 先延ばし（土） | 迷い・将来不安 |
| 土 | 迷い・将来不安（風） | 先延ばし |
| 雷 | 完璧主義（氷） | 焦り |
| 氷 | 焦り（雷） | 完璧主義 |
| 光 | 自己否定・孤独（闇） | 評価への恐怖 |
| 闇 | 評価への恐怖（光） | 自己否定・孤独 |
| 無 | （なし・常に互角） | （なし） |

最終ボス（心の迷宮の守護者）＝無のため、どの元素のプレイヤーでも互角（元素では有利を取れない実力勝負）。
- **技名**: 攻撃メッセージ先頭に本編元素の技名を表示（炎=火炎の一撃／水=清流の一打／風=疾風の斬撃／土=大地の重撃／氷=氷結の刃／雷=雷光の貫き／光=光輝の裁き／闇=深淵の一撃／無=渾身の一撃）。有利時は「弱点を突いた！」、不利時は「手応えが薄い」を付記。
- **戦闘画面の表示**: 敵カードに「敵の元素・有利/不利/互角」バッジを表示（敵が無の時は非表示）。`_ElementMatchBadge`。
- **本編元素の取得元**: ダンジョン選択画面（`roguelike_home_screen.dart`）が `characterDetailsProvider`（`details/current` のストリーム）から `element` を読み、`startGame()` に渡す。ここで渡した元素が相性倍率・技名・配色すべてに使われるため、**フレンド表示用の `userCharacterDetailsProvider`（keepAlive付きの一度きり取得）は使わない**。使うと性格タイプが変わってもアプリを再起動するまで古い元素で戦うことになる。

### 6.8 画面UI（`roguelike_game_screen.dart` / `resource_bar_widget.dart`）

全フェーズ共通のカードUI。AppBarは持たず、上部ヘッダーに集約する。**背景は上＝夜の紫→下＝薄ピンクの縦グラデーション**（`kRoguelikeBgGradient`、全ローグライク画面共通）。カード背景は純白だとグラデから浮くため**ほんのりグレー**（`kRoguelikeCard`）に統一。グラデ上に直接置く見出し・補足テキストは白／白70%で可読性を確保。

- **上部ヘッダー（共有）**: アバター＋成長段階バッジ＋リソースピルを**2段表示**（横スクロールしない）。1段目＝**HPバー（全幅）**、2段目＝食料／金貨／回復薬／絆〔相棒名は省き「絆」表記・相棒時のみ〕を均等割り（`Expanded`）。右端にメニュー(☰＝中断)。`ResourceBarWidget`
- **探索盤面（`map_grid_widget.dart`）**: **層状の分岐マップ**（下＝スタート／上＝ボス）。各ノードはテーマ絵文字＋**種別色のラベルチップ**（未判明は🌫️で伏せる／ボスは常に表示）、現在地は黄ハイライト＋アバター、これから進めるノードは種別色で強調。層間の枝道は線でつなぎ、現在地から進める枝はアクセント色。**つながった次の層のノードのタップ**で前進する（一方向）。**マップは下から表示**＝入場時は現在地（スタート）が見えるようスクロールを合わせ、前進に合わせて上へ追従スクロールする（§3「表示の起点」）。下に**凡例（折りたたみ）**
- **敵カード**: 敵アイコン（ボスはダンジョン絵文字／ザコは💭）＋名前＋HPバー＋説明＋シーン（グラデ背景＋キャラ/敵の絵文字プレースホルダ）＋「ターン N」＋次の行動。イラスト素材は未使用で絵文字/グラデ代用
- **行動選択カード（戦闘・イベント共通 `_ChoiceCard`）**: アイコン＋タイトル＋**タイプタグ**（攻撃/安定/特効/回復、`riskHint`等から導出）＋**消費チップ**（HP/食料/絆/回復薬）＋説明＋**成功率**＋**予想ダメージ**（代表 outcome の 敵に/自分に、回復系は効果表示）。逃走は「離脱を試みる（成功率70%）」
- **下部バー（戦闘）**: ステータス（行動ログのボトムシート）＋「行動を選択してください」プロンプト

## 7. 結果の出し方（行動ログ → 性格 → 元素）

### 7.1 行動ログ（ActionLog）

10特性を選択ごとに加算する。各特性は0〜999でクランプ。

挑戦性(challenge) / 慎重性(caution) / 好奇心(curiosity) / 計画性(planning) / 直感性(intuition) / 論理性(logic) / 協調性(cooperation) / 利他性(altruism) / 執着性(persistence) / 柔軟性(flexibility)

**特性は「選択時」と「結果時」の2段階で加算する**（成功/失敗ではなく判断傾向を記録する思想）。

1. `EventChoice` / `BattleChoice` の **`selectTrait`** … その選択を選んだ時点で必ず加算される判断傾向（例「すぐ開ける」→ 挑戦性+2 直感性+1）
2. 抽選された `Outcome` の **`traitDelta`** … 結果による小さな追加（例 大成功→好奇心+1、失敗→慎重性+1）

逃走（`isFlee`）も `selectTrait` を持ち、逃げるという判断自体が加算される。

### 7.2 推定元素（inferredElement）

特性の合算で8元素のスコアを出し、最大の元素を採用する。
**8元素はそれぞれ異なる3特性の組み合わせ。光⇔闇・雷⇔氷は外向/内向の鏡として差別化している**（旧版は光=氷で重複していたバグを修正）。

| 元素 | スコア計算 | 性質 |
|---|---|---|
| 炎 | 挑戦性 + 直感性 + 執着性 | 衝動・前進 |
| 水 | 利他性 + 協調性 + 柔軟性 | 受容・つながり |
| 風 | 好奇心 + 柔軟性 + 直感性 | 自由・変化 |
| 土 | 慎重性 + 計画性 + 執着性 | 堅実・継続 |
| 雷 | 挑戦性 + 直感性 + 柔軟性 | 外向の瞬発（直感を外へ放つ） |
| 氷 | 慎重性 + 直感性 + **論理性** | 内向の瞬発（直感を内に止める） |
| 光 | 論理性 + 計画性 + 協調性 | 外向の理性（理性を他者へ向ける） |
| 闇 | 論理性 + 好奇心 + 慎重性 | 内向の理性（理性を内へ向ける） |

#### 判定は素点ではなく「平均からの突出度」で行う

素点をそのまま比べると、**イベントで付きやすい特性を持つ元素が有利**になる。
プレイヤーの選択と無関係なこの偏りを打ち消すため、2段階で正規化する。

```
突出度 = (元素スコア ÷ 特性の合計) ÷ 期待比率 × 補正係数
```

| 元素 | 期待比率 | 補正係数 |
|------|---------|---------|
| 炎 | 0.2920 | 0.9426 |
| 水 | 0.2568 | 0.8543 |
| 風 | 0.2858 | 1.0368 |
| 土 | 0.3165 | 0.9882 |
| 雷 | 0.3061 | 1.0201 |
| 氷 | 0.3099 | 1.1049 |
| 光 | 0.3342 | 1.0289 |
| 闇 | 0.3240 | 1.0242 |

- **期待比率**＝平均的な冒険での「元素スコア ÷ 特性合計」。特性の供給量の偏りを打ち消す
- **補正係数**＝元素どうしの相関による有利不利を打ち消す。水は利他性を独占するため
  他と競合せず勝ちやすく、雷は炎・風と特性を食い合って勝ちにくい。期待比率だけでは
  この構造は取れない

- 特性が一つも付いていない → 「無」
- **突出度の1位と2位の差が 0.04 未満 → 「無」**（傾向が割れている）

> **イベントの `selectTrait` 配分を変えたら期待比率・補正係数の再計算が必要。**
> 算出方法: 実データ（`game_event.dart` / `enemy.dart` / `dungeon.dart` の
> `selectTrait`）から1ラン（イベント5回＋ザコ戦6回＋ボス戦4回）をシミュレートし、
> 期待比率は元素スコア比の平均、補正係数は各元素の採用率が 1/8 に揃うまで
> 反復調整して求める。

#### 判定と特性配分の設計（2026-08-10 見直し）

**8元素は特性を共有している**（例: 炎と雷は挑戦性・直感性が共通で、差がつくのは
執着性 vs 柔軟性だけ）。そのため差は構造的に開きにくい。

見直し前は「差3未満で無」かつイベントの特性配分が偏っており、実測（実データを
使ったシミュレーション・1ラン＝イベント5回＋ザコ戦6回＋ボス戦4回）で
**無46% / 闇39% / 風・氷・雷・光はほぼ0%** という状態だった。

原因は2つ。

1. **戦闘の「観察していなす」が `論理性2 + 慎重性1`** で、闇（論理性+好奇心+慎重性）に
   一度に3点入っていた。戦闘は毎ターン繰り返されるため影響が大きい
2. **直感性の供給が全体の2%しかなく**、直感性を持つ炎・風・雷・氷が互いを区別できなかった

対策として (a) 閾値を差1へ、(b) 全 `selectTrait` の配分を見直し各特性の供給量を均した。
**元素の意味（本編 `axisCalculator.js` との対応）は変えていない。**
氷だけは本編で「内向・論理重視・直感」と定義されているのに論理性を持っておらず、
かつ全特性が炎・土と重なって埋もれていたため、本編に合わせて執着性→論理性とした。

| | 無 | 炎 | 水 | 風 | 土 | 雷 | 氷 | 光 | 闇 | 最大差 |
|---|---|---|---|---|---|---|---|---|---|---|
| 見直し前 | 46% | 8% | 4% | 0% | 1% | 1% | 0% | 2% | 39% | 39pt |
| 配分の均等化のみ | 18% | 12% | 10% | 5% | 13% | 9% | 2% | 17% | 13% | 15pt |
| **＋突出度で判定** | 20% | 10% | 11% | 11% | 10% | 9% | 9% | 11% | 9% | **2.3pt** |

配分の均等化だけでは氷が2%のままだった。氷が使う3特性はいずれも炎・土・闇と
重なっており、1位になるには複数の元素に同時に勝つ必要があるためで、
**供給側の調整では解消できない**。突出度による判定でこれを解消した。

### 7.3 称号（AdventureTitle）

冒険終了時、行動傾向・終了種別・推定元素から称号を1つ付与する（`adventure_title.dart`）。

- 推定元素が「無」でない場合は **元素称号** を優先（例 闇→「闇を覗く者」、炎→「最後まで進む炎」）
- 「無」の場合は **上位特性の称号**（例 挑戦性→「無謀な開拓者」、利他性→「仲間想いの旅人」）
- ボス撃破（clear）時は箔がつく称号
- 特性が何も立っていない場合は「迷宮の旅人」

### 7.4 結果画面（`roguelike_result_screen.dart`）

パステル調のカード型レイアウトで「冒険の記録」を可視化する。上から順に:

1. **ヘッダー**: 終了種別のリボン（クリアは「『◯◯』を克服！」）＋「おつかれさまでした！」＋サブ文＋**シェアボタン**（`share_plus` でテキスト共有）
2. **克服演出カード**（クリア時のみ）: 克服メッセージ・心の図鑑進捗・最終解禁告知
3. **キャラクター＋ステータス**: 本編アバター（`characterGrowthAssetPath`）＋成長段階バッジ／到達層（`reachedDepth`/`totalDepth`）・倒した敵（`enemiesDefeated`）・残り食料・金貨・絆（相棒がいる時）
4. **冒険のまとめ**: 行動傾向・終了種別から生成した短い総括
5. **元素 ＋ 上位の行動特性 TOP3**（横並び）: 元素カードは「今回の冒険での傾向（推定元素）」＋傾向強度（`elementStrengthLabel`）＋一言に加え、**本編の元素を必ず併記**し比較コメントを表示する（一致「本編の◯タイプらしい戦い方」／不一致「本編は◯ですが今回は△のように」）。`GameState.element` を `_ElementCard(homeElement:)` に渡す。TOP3はメダル・アイコン・説明（`TraitInfo`）・数値
6. **行動特性レーダー（10特性）**: `fl_chart` の `RadarChart`
7. **冒険で解放したもの（図鑑）**: イベント図鑑・敵図鑑・克服した悩み（累積／総数）。※称号は獲得数を表示しない（称号自体はヘッダーのリボンと図鑑コレクションに残す）
8. **今回の冒険で印象的だった行動**: `notableActions` を加算特性の大きい順に上位3件（行動ラベル＋特性＋増分）
9. **ひとことメッセージ**: 上位特性・相棒の有無から生成
10. **ボタン**（左→右）: **ホーム**（左・**色付きのメインボタン**。冒険タブ＝ダンジョン選択へ戻る。タブバーのあるシェル表示。状態クリアは遷移後に post-frame で行い `state==null` 単独ルート誘導との競合を防ぐ）／**記録**（右・アウトライン。`/roguelike/history` の記録一覧へ push、戻るで結果画面に復帰）

表示時に履歴を1件保存し、図鑑（出会ったイベント・敵・称号）を累積記録、クリア時は克服も記録する（§9）。
特性・元素の説明/アイコンは `models/roguelike_info.dart`（`TraitInfo` / `ElementInfo`）に定義。

## 8. ゲーム終了条件と終了種別（GameResult）

`phase`（victory/gameOver）に加え、`GameResult` で終了を3種に分類する。枝道式で必ずボスに到達するため、途中終了は撤退か失敗のみ。

| 終了種別 | 発生条件 | 結果画面の見出し | アイコン |
|---|---|---|---|
| `clear` | ボス撃破 → 撃破カードで**「結果を見る」**を選択 | **「◯◯」を克服！**（その悩みの名前） | 🏆 |
| `retreat` | ボスから逃走 | **結果画面を出さずダンジョン選択へ戻る**（記録なし） | 🚪 |
| `failed` | HP0 / 食料切れ餓死 | 冒険失敗 | 💀 |

- `clear` 時はその悩みを克服したものとして `roguelike_clears` に記録する（結果画面の初回表示で保存）。
- **ボス撃破後に「見ない」を選ぶと、結果画面を経由しないため克服は記録されない**（ダンジョン選択へ戻る）。ザコ撃破後の「進まない」も同様に記録なしでダンジョン選択へ戻る（§10）。
- **中断（メニュー☰）は記録せずに終了**する。確認ダイアログで「中断する」を選ぶと、結果画面を経由せず**ダンジョン選択（冒険タブ）へ戻る**（履歴保存なし）。

## 9. 永続化（Firestore保存）

### 9.1 冒険履歴

冒険終了時に結果を履歴として保存し、**記録一覧画面（`/roguelike/history`、`RoguelikeHistoryScreen`）**で新しい順に表示する。結果画面の「📖 記録」ボタンから **push 遷移**（戻る＝pop で結果画面へ復帰。結果の二重保存を避けるため go ではなく push）。各カードは**左にボス（ダンジョン）アイコン**（`enemyArt(dungeonId)`）＋結果バッジ／称号／悩み／推定元素／上位特性／日時を表示。

- **保存先**: `users/{userId}/roguelike_runs/{runId}`（`RoguelikeDatasource.saveRun`）
- **保存タイミング**: 結果画面の初回表示時に1度だけ（`initState`）
- **セキュリティ**: `firestore.rules` の `users/{userId}/{subcollection=**}` ルールにより**本人のみ read/write 可**。専用ルール追加は不要
- **保存フィールド**: `characterName` / `element`（本編元素） / `inferredElement` / `result`（GameResult名） / `title`（称号） / `topTrait` / `traits`（10特性マップ） / `growthStage` / `dungeonId` / `worry`（挑戦した悩み） / `finalHp` `finalFood` `finalMoney` `finalItems`（回復薬） `finalBond` / `hadCompanion` / `companionName` / `enemiesDefeated` / `visitedCount` / `createdAt`（サーバ時刻）
- **表示**: 記録一覧画面が `roguelikeHistoryProvider`（StreamProvider.family by userId・最新30件）で一覧表示（結果バッジ／称号／悩み／推定元素／上位特性／日時）。`recentRunsProvider`（最新5件）も定義済み

### 9.2 克服記録（心の図鑑）

克服した悩み（ダンジョン）を記録し、選択画面の「克服済み」表示・最終ダンジョン解禁に使う。

- **保存先**: `users/{userId}/roguelike_clears/{dungeonId}`（`RoguelikeDatasource.recordClear`、`set(merge:true)` で冪等）
- **保存タイミング**: 結果画面で `result == clear` の時
- **保存フィールド**: `worry`（克服した悩み名） / `clearedAt`（サーバ時刻）
- **表示**: `clearedDungeonsProvider`（克服済みID集合）で選択画面・結果画面の図鑑進捗に反映。全悩み克服で最終ダンジョン解禁（`Dungeons.finaleUnlocked`）
- **セキュリティ**: 上記サブコレクションルールで本人のみ read/write。専用ルール追加は不要

### 9.3 図鑑（出会ったイベント・敵・称号の累積）

結果画面「冒険で解放したもの」の表示に使う累積コレクション。

- **保存先**: `users/{userId}/roguelike_meta/codex`（固定ID `codex`。`RoguelikeDatasource.recordCodex`、`arrayUnion` で追記）
- **保存タイミング**: 結果画面の初回表示時
- **保存フィールド**: `events`（出会ったイベントID配列） / `enemies`（出会った敵ID配列） / `titles`（獲得称号配列）
- **表示**: `codexProvider` で取得し、イベント図鑑 N/全イベント・敵図鑑 N/全敵（`Dungeons.allEnemies`）・称号数 を表示
- **セキュリティ**: 上記サブコレクションルールで本人のみ read/write。専用ルール追加は不要

## 10. 広告（AdMob）

冒険機能に AdMob 広告を組み込む。基盤は本体既存のもの（`google_mobile_ads` / `AdConfig`（`data/services/ad_service.dart`）/ `RewardedAdManager` / `ad_provider.dart`）を流用。**プレミアムユーザー（`shouldShowBannerAdProvider` が false）・Web では広告を出さない**。

### 10.1 バナー広告（全5画面の上下）

- 対象: ダンジョン選択（`roguelike_home_screen`）/ 敵図鑑（`roguelike_codex_screen`）/ ダンジョン（`roguelike_game_screen`）/ 結果（`roguelike_result_screen`）/ 記録（`roguelike_history_screen`）。各画面の**最上部と最下部**に配置。ただし**ダンジョン画面（`roguelike_game_screen`）は縦スペース確保のため上部のみ**（下部バナーは非表示）。
- 共通ウィジェット `RoguelikeBanner`（`widgets/roguelike_banner.dart`）。`bottom` で上下を切替え、`AdConfig.roguelikeTopBannerAdUnitId` / `roguelikeBottomBannerAdUnitId` を使用（同一画面で上下は別ユニット）。プレミアム/Web は `SizedBox.shrink()`。
- 結果画面はシェア用オフスクリーンカードを含む `Stack` の**外側**（`Column` の上下）にバナーを置き、共有画像に写り込まないようにする。

### 10.2 リワード動画広告（撃破時のポップアップ）

敵撃破時に**リワード動画**を挟む。ユーザーが「進む」を選んで視聴する opt-in 形式（AdMob ポリシー準拠。自動/強制のインタースティシャルは使わない）。

- **ザコ撃破**: 撃破カードで〔**次に進む**（広告→`closeBattle()` で探索継続）／**進まない**（記録せず冒険タブ＝ダンジョン選択へ）〕。
- **ボス撃破**: 撃破カードで〔**結果を見る**（広告→`confirmBossVictory()`→結果画面＝クリア記録）／**見ない**（記録せず冒険タブへ）〕。
- 広告は `RewardedAdManager.showAndAwaitReward()`（`rewardedAdManagerProvider`）。`_BattleView` の `initState` で `adControllerProvider` を読み事前ロード。**プレミアム/Web、広告の読み込み失敗・スキップ時はそのまま進む**（広告が出ないせいで進めなくならないように）。
- **撃破カードの文言は広告の有無に連動させる**。`noAd = effectiveIsPremiumProvider || kIsWeb`（`_watchAd()` の早期リターン条件と同じ式）で切り替える。

| | 見出し | ボタン |
|---|--------|--------|
| 広告あり（無料・アプリ版） | 広告を見て探索を続けますか？／広告を見て結果を確認しますか？ | 🎬 次に進む／🎬 結果を見る |
| 広告なし（プレミアム・Web） | 探索を続けますか？／結果を確認しますか？ | 次に進む／結果を見る |

### 10.3 広告ユニットID・未対応事項

- デバッグビルドは Google のテスト広告（`AdConfig.isTestMode = kDebugMode`）。
- iOS本番のローグライク用バナーは**予定追加画面のバナーユニットを流用**（`roguelikeTopBannerAdUnitId` = `scheduleAddTopBannerAdUnitId` / `roguelikeBottomBannerAdUnitId` = `scheduleAddBottomBannerAdUnitId`）。上/下で別ユニット・5画面で共有。リワードは既存の共通ユニットを流用。
- **Android は当面対象外**（広告ユニットIDは `YOUR_ANDROID_..._AD_UNIT_ID` プレースホルダのまま）。Android 配信時に要設定。
- 同意管理（UMP/ATT）は本体同様に未実装。

## 11. 冒険の性格（全踏破の総合診断・AI生成）

全踏破（最終ダンジョン「心の迷宮の守護者」クリア）後に、**キャラクター詳細画面のサブタブ「冒険の性格」**で総合診断を表示する。「実績の羅列」ではなく、**冒険中の選択の傾向を横断集計し、AIが“あなたの心の総括”を言語化**する。

### 11.1 UI（詳細画面のサブタブ）

- `CharacterDetailScreen` の AppBar 下に**セグメント切替（基本 / 冒険の性格）**を置く（`_DetailSegmentControl`、手帳タブのメモ/タスク切替と同じトグルスタイル）。`characterDetailSegmentProvider` で選択を保持し、本体は `IndexedStack` で出し分ける。「基本」は従来の内容、「冒険の性格」が `AdventurePersonalityTab`（`features/roguelike/screens/adventure_personality_tab.dart`）。
- **全踏破前はロック表示**（「全踏破すると解禁」＋克服進捗バー）。
- 全踏破後の表示: **総合の行動傾向**（全ラン合算のレーダー＋TOP3）／**総合の推定元素**（合算から算出）／**AI診断**（`summary`＝あなたはこういう選択を多く取る／`advice`＝この傾向をこう活かそう）／**「🔮生成する」「🔄更新」「診断をシェア」ボタン**。
  - **「🔄更新」は前回生成時からダンジョン結果が変わった（ラン数が増えた）ときだけ表示**する（連打での無駄な再生成を防止）。判定は「生成時に保存した `runCount`」と「現在のラン数（`roguelikeRunCountProvider`＝`roguelike_runs` の件数）」の比較で、変化なしなら更新ボタンを隠しシェアボタンのみ全幅表示。旧データ（`runCount` 未保存）は表示。
- シェアは診断カードを画像化（`RepaintBoundary`）してテキストと共有（結果画面のシェアと同方式）。

### 11.2 集計とAI生成

- **集計**: `roguelikeDatasource.aggregateRunTraits(userId)` が `roguelike_runs`（最大500件）の `traits`（10特性マップ）を横断合算 → `ActionLog`（`ActionLog.fromMap`）。既存の `topTraits()` / `inferredElement()` / `elementStrengthLabel()` を流用。
- **AI生成**: Cloud Function `generateAdventureDiagnosis`（`onCall`・`asia-northeast1`・`enforceAppCheck`）。モデル `gpt-4o-mini`、`max_completion_tokens: 600`、`response_format: json_object`。プロンプトは `OPTIMIZED_PROMPTS.adventureDiagnosis`（上位傾向・推定元素・本編元素・冒険者名を入力）。戻りは `{summary, advice}`。
  - **コスト目安**（`gpt-4o-mini`）: 入力 ~350 / 出力 ~250 トークン程度 ≒ 1回約 $0.0002（数千分の1ドル）。**生成は1回のみ**でFirestoreに保存し、以降は保存値を表示（「更新」で再生成）するためコストは最小。
- **保存**: `users/{userId}/roguelike_meta/diagnosis`（`saveDiagnosis`）。フィールド: `summary` / `advice` / `element` / `topTrait` / `runCount`（生成時点のラン数・更新ボタン表示判定用） / `updatedAt`。表示は `roguelikeDiagnosisProvider`（保存値のStream）。

### 11.3 デプロイ

- `generateAdventureDiagnosis` は Cloud Functions に**新規デプロイが必要**（`firebase deploy --only functions:generateAdventureDiagnosis`）。未デプロイ時は「生成する」がエラーになる（UIはロック/生成前状態のまま）。
