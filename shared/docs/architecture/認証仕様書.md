# 認証仕様書

DARIAS のログイン・アカウント作成の仕様。実装は `flutter/lib/presentation/providers/auth_provider.dart` と
`flutter/lib/data/services/social_auth_service.dart`。

## ログイン方法

| 方法 | プロバイダーID | 対応プラットフォーム |
|---|---|---|
| メールアドレス／パスワード | `password` | iOS / Android / Web |
| Google | `google.com` | iOS / Android |
| Apple | `apple.com` | iOS |

- Google は Web では出さない。Web はサインイン用のボタンをGoogleのSDKに描画させる必要があり、
  アプリ側のボタンからは開始できないため（`SocialAuthService.isGoogleAvailable`）
- Apple は Android でも技術的には動くが、Apple Developer 側で Service ID とリダイレクト先の設定が
  別途必要になるため iOS のみ（`SocialAuthService.isAppleAvailable`）
- Google / Apple は「登録」と「ログイン」を分けない。同じボタンが両方を兼ねる

## アカウント作成時のデータ

どの入口でも `AuthController.createInitialUserData()` を必ず通す。ここで作るのは2つ。

1. `users/{uid}` … メールアドレス・名前・キャラクターの性別・`characterId`
2. `users/{uid}/characters/{characterId}/details/current` … 性別・`personalityKey`・Big5の初期値・
   `analysis_level`・`points`

**初回かどうかは `users/{uid}` ドキュメントの有無で判定する**（`_afterSocialSignIn`）。
認証だけ済んでドキュメントが無い状態（初回の途中でアプリを閉じた場合など）でも、
もう一度性別選択からやり直せるようにするため。

### キャラクターの性別

- メール登録: アカウント作成画面で選ぶ
- Google / Apple: 入力欄が無いため、**初回サインインの直後に `/character-gender` を挟んで選んでもらう**
  （`CharacterGenderScreen`）。選ぶまで他の画面へは進めない（ルーターで固定）。
  この画面には「別のアカウントでやり直す」も置き、サインインしたまま進めなくなる状態を作らない

## 同じメールアドレスの扱い

Firebase の「メールアドレスごとに1つのアカウント」設定を維持する。
**複数アカウントを許可すると、同じメールアドレスで uid が2つでき、キャラクターも購読状態も分かれてしまう。**

メール登録済みの人が Google / Apple でサインインすると `account-exists-with-different-credential` が返る。
このとき `SocialSignInStatus.needsLink` を返し、次の流れで1つのアカウントにまとめる。

1. パスワード入力ダイアログを出す（`SocialSignInButtons._linkWithExistingAccount`）
2. パスワードでサインイン
3. `linkWithCredential()` で Google / Apple を紐づける
4. 以後どちらの方法でも同じアカウントに入れる

**パスワードは連携後も変わらない。** 逆に Google / Apple で作ったアカウントにはパスワードが無いため、
メールでもログインしたい場合は、設定画面の「ログイン方法」からパスワードを設定する。

## ログイン方法の管理（設定画面）

設定 → 「ログイン方法」（`/login-methods`・`LoginMethodsScreen`）で、1つのアカウントに
ログイン方法を追加・解除できる。**ログイン中は本人確認が済んでいるので、パスワードを
聞かずに追加できる**のがこの画面の役割。

| 操作 | 実装 |
|---|---|
| Googleを追加 | `linkGoogle()` → `linkWithCredential` |
| Appleを追加 | `linkApple()` → `linkWithProvider` |
| メールログインを追加 | `linkEmailPassword()` → `EmailAuthProvider.credential` を `linkWithCredential` |
| 連携を解除 | `unlinkProvider()` → `unlink` |

- **Google / Apple で作ったアカウントにはパスワードが無い**ため、ログイン画面の連携
  （パスワードでの本人確認）が使えない。この画面がその入口になる
- メールアドレスを持たないアカウント（Appleの「メールを非公開」など）でも追加できるよう、
  メールログインの追加ではアドレスも入力できる
- **最後の1つは解除できない**（解除するとログインできなくなるため、`unlinkProvider` が弾く）
- Appleの「メールを非公開」を選ばれた場合は `@privaterelay.appleid.com` の別アドレスになるため、
  同じ人でも別アカウントとして作られる。これはApple側の仕様で、避けられない

## 前回のログイン方法の表示

- **ログイン画面**: 前回使った方法のボタンに「前回はこちら」を出す（`LastLoginBadge`）。
  未ログインではFirestoreを読めないため、端末（SharedPreferences・キー `last_login_method`）に
  プロバイダーIDを保存している（`LastLoginMethodStore`）。
  **アプリを入れ直した直後や別端末の初回は表示されない**
- **設定画面**: ログイン中は `currentUser.providerData` から「Googleでログイン中」「メールアドレス・Googleでログイン中」
  のように出す（連携済みなら両方並ぶ）

## 退会（アカウント削除）

本人確認はログイン方法ごとに変える（`settings_screen.dart`）。Google / Apple で登録した人は
パスワードを持たないため、パスワード入力は求めない。

| ログイン方法 | 本人確認 |
|---|---|
| メール | パスワード入力 → `reauthenticateWithCredential` |
| Google | Googleサインインをやり直す → `reauthenticateWithCredential` |
| Apple | `reauthenticateWithProvider` |

本人確認のあとに Cloud Functions の `deleteUserAccount` を呼び、最後に `user.delete()` する。

## 計測

`sign_up` / `login` の `method` に `email` / `google` / `apple` を送る（`AnalyticsService`）。
詳細は [Analytics計測仕様書](./Analytics計測仕様書.md)。

## 事前設定（Firebase / 各ストア）

- Firebase Console → Authentication → Sign-in method で Google と Apple を有効にする
- Android: デバッグ鍵と Play App Signing 鍵の SHA-1 / SHA-256 を Firebase に登録し、
  `google-services.json` を更新する（Android用のOAuthクライアントが作られる）
- iOS: `Info.plist` の `CFBundleURLTypes` に `GoogleService-Info.plist` の `REVERSED_CLIENT_ID` を登録済み。
  Sign in with Apple は `Runner.entitlements` の `com.apple.developer.applesignin` で有効化済み
- Apple Developer で App ID の Sign in with Apple を有効にする
